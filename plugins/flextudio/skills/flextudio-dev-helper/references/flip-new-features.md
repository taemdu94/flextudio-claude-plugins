# 신규 기능: 플립프론트(AI 채팅으로 화면 만들기)와 플립백(서버 플로우)
이 파일이 답하는 질문: 플립프론트와 플립백은 무엇이고 Studio 와 어떻게 고르나요 / 어떤 순서로 시작하나요 / 데이터는 어디서 가져오나요 / 미리보기·버전·배포는 어떻게 하나요 / 플립백 노드는 무엇이 있나요 / 플로우는 무엇으로 실행되나요 / 화면과 플로우는 어떻게 잇나요 / 요청문은 어떻게 쓰나요 / 안 되는 것과 막힐 때 조치

목차
1. 두 기능 한눈에 보기
2. 시작하기
3. 플립프론트: 화면 만들기
4. 플립백: 서버 플로우 만들기
5. 화면과 플로우 잇기
6. 좋은 요청문 쓰는 법
7. 알려진 제약과 지원하지 않는 것
8. 자주 막히는 증상과 조치

쓰는 법
- 이 내용은 2026년 11월 초 기준입니다. 신규 기능은 몇 주 단위로 바뀝니다. 화면 글자·메뉴가 바뀌었을 수 있으니 공식 문서(https://docs.flextudio.com)와 실제 화면으로 확인하세요.
- 바뀌기 쉬운 버튼·창 이름에는 [확인 필요]를 붙였습니다. 질문자 화면과 다르면 화면을 우선하고 다른 점을 알려 달라고 하세요.
- Studio 방식(시나리오, 이벤트, 서비스) 질문은 이 파일이 아니라 각 주제 설명을 보세요.

## 1. 두 기능 한눈에 보기

### 1-1. 플립프론트와 플립백은 무엇인가요
결론: 플립프론트는 채팅으로 요청하면 AI 가 화면(웹 앱 소스 코드)을 만들어 주는 도구입니다. 플립백은 서버에서 도는 업무 흐름(플로우)을 노드와 선으로 만드는 도구이고, AI 어시스턴트가 초안을 제안합니다.
- 플립프론트 결과물은 React 소스 코드입니다. 시나리오 메타가 아니므로 Studio 에서 열어 고칠 수 없습니다.
- 플립백 결과물은 플로우입니다. DB 조회·저장, 외부 API 호출, K-System SP 호출, 분기, 반복을 노드로 잇습니다.
- 둘의 관계는 매장과 주방에 비유할 수 있습니다. 화면(플립프론트)이 주문을 넣으면 플로우(플립백)가 처리해 결과를 돌려줍니다.

```text
[사용자] → [플립프론트 화면] → POST 호출 → [플립백 플로우] → DB / 외부 API / K-System SP
```

### 1-2. Studio 방식과 신규 기능 중 무엇을 고르나요
결론: ERP 업무 화면, 시트 입력, 결재·서명 같은 업무 컨트롤이 필요하면 Studio 방식이 맞습니다. 디자인 자유도가 중요한 화면이나 빠른 시제품, 서버 로직을 화면과 분리하고 싶을 때는 신규 기능이 맞습니다.

| 기준 | Studio 방식 | 플립프론트 + 플립백 |
|---|---|---|
| 만드는 법 | 컨트롤 배치, 속성, 이벤트 설정 | 채팅 요청(화면), 노드 연결과 AI 제안(서버) |
| 고치는 법 | 속성 패널에서 값 변경 | 채팅, [요소 수정], 코드 탭 직접 편집 |
| ERP 연동 | 서비스 바인딩으로 SP 호출 | 플립백 SPList·ServiceWF 노드로만 호출 |
| 앱 시작 화면 | 가능 | 불가. 앱 메뉴로만 붙음 |
| AI 사용량 | 없음 | 워크스페이스 AI 크레딧 차감 |

### 1-3. 한 앱 안에서 둘을 함께 쓸 수 있나요
결론: 쓸 수 있습니다. 앱의 시작 화면은 Studio 시나리오로 두고, 플립프론트 화면은 그 앱의 메뉴로 붙입니다.
할 일:
1. 시작 화면용 Studio 시나리오를 하나 만들어 앱에 등록하세요.
2. 플립프론트 화면은 배포할 때 그 앱을 고르고, 콘솔 [레이아웃관리]에서 메뉴로 노출하세요(3-5).
[확인 필요] Studio 이벤트 액션 종류에 FlipBack 이 있어 Studio 화면도 같은 플로우를 부를 수 있는 것으로 보입니다. 설정 화면에서 플로우를 고를 수 있는지는 Studio 에서 직접 확인하세요.

## 2. 시작하기

### 2-1. 어디로 들어가고 무엇이 있어야 하나요
결론: 플렉스튜디오 계정으로 로그인한 뒤 콘솔의 [Flip Front]·[Flip Back] 버튼으로 들어갑니다. 따로 로그인하지 않습니다. 워크스페이스에 AI 크레딧이 설정돼 있어야 쓸 수 있습니다.
할 일:
1. 첫 화면에서 쓸 워크스페이스를 고르세요.
2. 버튼이 안 보이거나 「사용할 수 있는 워크스페이스가 없어요」가 뜨면 워크스페이스 관리자에게 AI 크레딧 설정을 요청하세요.
3. 남은 크레딧과 사용량은 두 도구의 설정 → [크레딧 누적 사용량]에서 보세요.
- AI 크레딧은 플립프론트 채팅, 플립백 AI 어시스턴트를 쓸 때 줄어듭니다. 만든 플로우를 실행할 때는 줄지 않습니다.
- API 키를 등록하거나 AI 모델을 고르는 메뉴는 없습니다.

### 2-2. 어떤 순서로 만드는 것이 덜 막히나요
결론: 데이터를 저장하거나 ERP 를 읽는 앱이면 플로우를 먼저 만들고 화면을 나중에 요청하세요. 순서를 뒤집으면 AI 가 데이터 출처를 묻는 질문 카드를 내거나 샘플 데이터로 만듭니다.
할 일:
1. 플립백: 필요하면 설정에서 DB 연결을 준비하세요(4-7).
2. 플립백: 새 플로우 → AI 어시스턴트에 요청 → 제안 적용 → [디버그 실행]으로 확인하세요.
3. 플립백: 입력·출력 스키마를 채우고 [버전 저장] → 배포 → [API 연결]을 추가하세요.
4. 플립프론트: 플로우를 연결한 뒤 화면을 요청하세요.
5. 플립프론트: [사용자 정보 지정] 후 미리보기로 확인하고, [버전 저장] → 앱 메뉴로 배포하세요.
화면 모양부터 보고 싶으면 1번 전에 "샘플 데이터로" 화면을 먼저 만들어도 됩니다. 나중에 플로우를 연결하고 바꿔 달라고 요청하면 됩니다.

## 3. 플립프론트: 화면 만들기

### 3-1. 첫 요청은 어떻게 하나요
결론: 첫 화면 입력칸에 만들 화면을 쓰고 [만들기]를 누르면 프로젝트가 바로 생기고 1~2분 뒤 미리보기에 화면이 뜹니다.
할 일:
1. 모드는 바로 코드를 만드는 기본값 [Freebuild] 로 두세요.
   무엇을 만들지 정하지 못했으면 [Discuss]로 상의부터 하세요.
2. 화면 캡처·엑셀·PDF 를 [+ 추가] → [파일 첨부]로 붙이면 그 모양을 참고합니다. 한 메시지에 첨부는 10개까지입니다.
3. 빌드 오류가 나면 AI 가 두 번까지 스스로 고칩니다. 그래도 남으면 어느 화면이 어떻게 깨지는지 채팅으로 알려 주세요.
- 입력칸을 누르면 그 프로젝트의 편집 권한을 잡습니다. 다른 사람에게는 "○○님 편집 중"으로 읽기 전용이 됩니다. 다 썼으면 [편집 종료]를 누르세요.

### 3-2. 데이터는 어디서 가져오나요
결론: AI 는 연결된 플립백 플로우를 먼저 씁니다. 연결된 것이 없으면 계산기처럼 저장할 것이 없는 앱은 바로 만들고, 기록이 남는 앱이면 질문 카드로 데이터 출처를 묻습니다.

| 질문 카드 선택지 [확인 필요] | 결과 |
|---|---|
| 플립백 플로우 연결하기 | 연결할 플로우를 고르게 안내합니다(5-1) |
| 샘플 데이터로 시작하기 | 화면 안에 예시 데이터를 넣어 만듭니다 |
| 데이터는 나중에 하기 | 빈 화면으로 만듭니다 |

- 요청에 "샘플 데이터로 만들어 줘"를 적으면 카드 없이 바로 만듭니다. 샘플 데이터는 이렇게 사용자가 말해야만 만듭니다.
- 플립프론트에는 K-System SP 를 직접 부르는 기능이 없습니다. ERP 데이터는 플립백 플로우로 받습니다.

### 3-3. 미리보기에서 실제 데이터를 보려면 어떻게 하나요
결론: 로그인 사용자가 필요한 플로우를 부르려면 워크벤치 맨 위의 열쇠 아이콘 [사용자 정보 지정]에서 앱·테넌트·사용자를 먼저 골라야 합니다.
할 일:
1. 열쇠 아이콘을 누르고 [디버그 실행 환경 선택] 창에서 앱, 테넌트, 테스트 사용자를 고르세요 [확인 필요].
2. [이 사용자로 실행]을 누르세요. 고른 사용자가 플로우에서 로그인 사용자로 쓰입니다.
3. 미리보기 위 도구 줄의 [PC]·[모바일]로 화면 크기를 바꿔 보세요 [확인 필요].
확인: 데이터 탭 [데이터 호출]에 화면이 부른 함수가 시각·걸린 시간과 함께 쌓이고, 줄을 누르면 보낸 값(Request)과 결과(Response)가 보입니다.

### 3-4. 만든 화면은 어떻게 고치나요
결론: 채팅 요청, [요소 수정], 코드 탭 직접 편집 세 가지로 고칩니다.
할 일:
1. 한 번에 한 가지만 요청하세요. 여러 가지를 한 문장에 넣으면 일부를 빠뜨립니다.
2. 특정 부분을 고치려면 미리보기 위 [요소 수정]을 켜고 그 요소를 누른 뒤 채팅으로 말하세요. 고른 요소가 입력칸 위에 붙습니다 [확인 필요].
3. 입력칸에 `@` 를 치면 플로우·코드·파일·페이지를 골라 요청에 붙일 수 있습니다 [확인 필요].
4. 결과가 마음에 안 들면 그 메시지의 [이 지점부터 다시 시작]으로 되돌리세요.

### 3-5. 버전 저장과 배포는 어떻게 하나요
결론: [버전 저장]으로 v1, v2 처럼 버전을 남기고, 같은 창에서 플렉스튜디오 앱을 골라 그 앱의 메뉴로 배포합니다.
할 일:
1. [버전 저장]을 누르고 AI 가 쓴 제목·설명을 확인하세요.
2. 「배포할 앱을 바로 선택합니다.」가 켜진 채로 [저장 후 배포]를 누르세요. 버전만 남기려면 체크를 끄고 [저장]을 누르세요.
3. 배포할 앱을 고르고 [배포]를 누르세요. 배포할 앱은 콘솔에서 미리 만들어 두어야 합니다.
4. 콘솔 [레이아웃관리] → 메뉴 설정에서 플립프론트 화면 항목을 메뉴에 넣고 [라이브에 적용]을 누르세요 [확인 필요].
확인: 앱에 로그인하면 메뉴에 그 화면이 보입니다.
- 한 프로젝트는 한 번에 배포 하나만 진행됩니다. 진행 중에 또 누르면 「이 프로젝트의 다른 배포가 아직 진행 중입니다.」가 뜹니다.

## 4. 플립백: 서버 플로우 만들기

### 4-1. 플로우는 어떻게 만들고 AI 는 어떻게 쓰나요
결론: [플로우] → [새 플로우]로 만들고 에디터 오른쪽 [AI 어시스턴트] 탭에 요청하면, AI 가 변경 제안 카드를 냅니다. 카드를 적용해야 캔버스가 바뀝니다.
할 일:
1. [새 플로우]를 누르면 이름 untitled 로 바로 생깁니다. 상세에서 연필 아이콘으로 이름을 바꾸세요.
2. [에디터 열기] → [AI 어시스턴트] 탭에 요청을 쓰세요.
3. 제안 카드를 보고 [모두 적용]을 누르세요. 일부만 적용하려면 [선택 적용]을 누르세요.
   되돌리려면 [실행 취소]를 누르세요.
4. 엑셀·화면 캡처를 첨부해 "이 표대로 만들어 줘"라고 할 수 있습니다. 첨부는 그 질문에만 쓰이므로 다음 질문에 필요하면 다시 붙이세요.
- AI 는 저장·실행을 스스로 하지 않습니다. 에디터는 자동 저장되고, 실행은 사람이 누릅니다.
- AI 가 되물으면 「확인이 필요해요」 판에서 답하고 [답변 보내기]를 누르세요 [확인 필요].

### 4-2. 노드에는 어떤 것이 있나요
결론: 16종입니다. 시작 노드(트리거)는 없고, 들어오는 선이 없는 노드가 시작점, 나가는 선이 없는 노드가 끝점입니다. 화면의 노드 이름은 바뀔 수 있습니다 [확인 필요].

| 묶음 | 노드 | 하는 일 |
|---|---|---|
| 흐름·제어 | If / Switch | 조건에 맞는 갈래로 보냅니다 / 값에 따라 여러 갈래로 나눕니다 |
| 흐름·제어 | Wait | 정한 시간만큼 기다린 뒤 넘깁니다 |
| 흐름·제어 | Flow Call | 배포된 다른 플로우를 불러 결과를 받습니다 |
| 흐름·제어 | Error | 플로우를 실패로 끝내고 정한 상태 코드와 메시지를 돌려줍니다 |
| 흐름·제어 | Map / Parallel | 목록 항목마다 같은 노드를 반복합니다 / 여러 갈래를 동시에 돌립니다 |
| 변환 | Log / Code | 실행 로그에 메시지를 남깁니다 / JavaScript 로 값을 가공합니다 |
| 통합 | HTTP Request | 외부 API 를 부릅니다 |
| 통합 | Postgres / MySQL / MSSQL | 연결한 DB 에 SQL 을 실행합니다 |
| 통합 | SPList / ServiceWF | K-System SP 를 순서대로 실행합니다 / K-System 서비스 메서드를 실행합니다 |
| 통합 | Send Email (SMTP) | 설정 [연결관리]에 등록한 메일 계정으로 메일을 보냅니다 |

- 노드 값에는 `{{ }}` 표현식을 씁니다. 자주 쓰는 값은 `$input`(받은 값), `$user`(로그인 사용자), `$env`(환경변수), `$var`(실행 중 임시값)입니다.
- SPList 의 SP 이름에는 `{{ }}` 를 쓸 수 없습니다. 입력에 따라 다른 SP 를 부르려면 If·Switch 로 갈라 노드를 나누세요.

### 4-3. 만든 플로우를 어떻게 시험하나요
결론: 머리줄 [디버그 실행 환경]에서 실행할 사용자를 정하고 [디버그 실행] 버튼이나 Ctrl+Enter 로 돌립니다.
디버그 실행은 저장 전 편집본으로 돕니다.
할 일:
1. [디버그 실행 환경]에서 [앱 사용자] / [테넌트만] / [지정안함] 중 하나를 고르세요 [확인 필요]. 로그인 사용자가 필요 없는 연습은 [지정안함]이면 됩니다.
2. [디버그 실행]을 누르고 칸에 넣는 [간편 입력] 또는 [JSON으로 입력]으로 값을 넣은 뒤 [실행]을 누르세요.
3. 아래 [실행 이력]에서 결과와 출력 JSON 을 보세요. 실패하면 실패한 노드와 오류가 보입니다.
4. SPList·ServiceWF 가 있는 플로우는 [앱 사용자]로, K-System 사원과 연동된 사용자를 골라야 돕니다.

### 4-4. 버전 저장과 배포(LIVE/TEST)는 어떻게 하나요
결론: [버전 저장]으로 PUB#1, PUB#2 처럼 고정된 버전을 만들고, 그 버전을 TEST(연습) 또는 LIVE(운영)에 거는 것이 배포입니다.
할 일:
1. 캔버스 빈 곳을 눌러 [플로우 설정]에서 입력 데이터($INPUT)·출력 데이터($OUTPUT) 항목을 적으세요. AI 에게 "마지막 실행 내역 기준으로 스키마 작성해줘"라고 해도 됩니다.
2. [버전 저장] → 변경 설명(AI 작성) 확인 → 「저장한 뒤 배포 대상을 고릅니다」가 켜진 채로 [저장 후 배포]를 누르세요.
3. 다음 단계에서 배포할 곳(TEST 또는 LIVE)을 고르고, [API 연결]과 [일정 추가]도 여기서 할 수 있습니다 [확인 필요].
4. 배포 상태와 되돌리기는 플로우 상세 [배포 관리] 탭에서 하세요.
- 막는 검증 오류가 있으면 저장되지 않습니다. 경고는 저장을 막지 않습니다.

### 4-5. 플로우는 무엇으로 실행되나요
결론: 플로우는 노드가 아니라 바깥에서 시작됩니다. 호출 주소를 만드는 [API 연결]로 화면이나 다른 시스템이 부르거나, [자동 실행 일정]이 정한 시각에 돌립니다.
할 일:
1. 화면에서 부르려면 플로우 상세 [기본 정보] → [API 연결] → 연결 추가에서 경로 이름을 적고 저장하세요. 배포와 별개 단계라 빠뜨리기 쉽습니다.
2. 경로는 `orders` 처럼 한 단어(1단계)로 쓰세요. 다른 플로우가 쓰는 경로는 쓸 수 없습니다.
3. 정기 실행은 [자동 실행 일정] → 일정 추가에서 일정 이름(필수), 대상 플로우, 실행 버전(LIVE/TEST), 주기를 정하세요. 배포된 버전만 실행됩니다.
확인: [API 연결]에 호출 주소와 인증 방식(FlexAppToken)이 보입니다. 호출은 조회도 모두 POST 이고, 보낸 JSON 본문이 `$input` 이 됩니다.
- 외부 시스템이 웹훅처럼 이 주소를 부르게 하려면 로그인 쿠키 없는 인증 방식이 필요합니다. 지금 연결 창에서 인증 방식을 바꾸는 칸은 보이지 않습니다 [확인 필요]. 담당자에게 문의하세요.

### 4-6. 실행 결과는 어디서 보나요
결론: [실행 내역] 메뉴에서 실행마다 상태, 스텝별 입력·출력, 로그를 봅니다.
할 일:
1. 상태·실행 방법·테넌트·앱으로 걸러 보세요.
2. 디버그 실행 기록까지 보려면 [디버그 실행 포함]을 체크하세요(기본 꺼짐).
3. Code 노드에서 `console.log` 로 남긴 값도 로그에 나옵니다.

### 4-7. DB 는 어떻게 연결하나요
결론: 설정 [데이터베이스]에서 PostgreSQL·MySQL·MSSQL 연결을 추가합니다. 워크스페이스 공용 연결은 2개까지이고, 테넌트마다 따로 연결을 지정할 수도 있습니다.
할 일:
1. [공용 연결 추가]에서 종류, 호스트, 포트, 데이터베이스, 사용자, 비밀번호를 넣고 저장하세요.
2. [연결 테스트]로 확인하세요.
3. 고객 DB 방화벽에는 IP `3.37.52.246` 를 허용하세요. 플립백의 DB 연결은 이 주소를 거쳐 나갑니다.
- 비밀번호·API 키 같은 값은 설정 [환경변수]에 암호화 저장하고 노드에서 `{{ $env.<키> }}` 로 쓰세요.

## 5. 화면과 플로우 잇기

### 5-1. 플립프론트에 플로우를 어떻게 연결하나요
결론: 플로우를 배포하고 [API 연결]까지 마친 뒤, 플립프론트 데이터 탭이나 채팅 `@` 로 그 플로우를 연결합니다.
할 일:
1. 데이터 탭 [플립백 연결] → [추가하기] → 플로우를 체크하고 [연결하기]를 누르세요 [확인 필요]. 또는 채팅 입력칸에 `@` → [플로우]에서 고르세요.
2. TEST·LIVE 양쪽에 배포된 플로우는 스테이지를 고를 수 있습니다. 기본은 LIVE 입니다. 바꾸려면 연결 창을 다시 여세요.
3. 채팅에 "연결한 ○○ 플로우로 목록을 불러오게 바꿔 줘"라고 요청하세요.
확인: 미리보기에 실제 데이터가 나오고 [데이터 호출]에 호출 기록이 쌓입니다.

### 5-2. 플로우를 고쳐 다시 배포하면 화면도 바뀌나요
결론: 다시 배포하면 플립프론트 연결에 자동으로 반영됩니다. 입력·출력이 바뀌면 [확인 필요] 배지, 그 스테이지에서 빠지면 [제공 중단] 배지가 붙습니다.
할 일:
1. 배지를 확인하고 화면이 바뀐 입력·출력에 맞는지 채팅으로 고치게 하세요.
2. 경로를 바꿨다면 연결 창을 다시 열어 연결을 고치고, "플로우 경로가 바뀌었어. 화면이 바뀐 경로를 부르도록 고쳐 줘."라고 보내세요.

## 6. 좋은 요청문 쓰는 법

### 6-1. 플립프론트 요청은 어떻게 쓰나요
결론: 화면 구성(무엇이 어디에), 보여 줄 항목, 동작, 데이터 출처를 한 문단에 적으세요.

| 아쉬운 요청 | 좋은 요청 |
|---|---|
| 주문 관리 화면 만들어 줘 | 대리점 주문 목록 화면을 샘플 데이터로 만들어 줘. 열은 주문번호·대리점·품목·수량·상태, 위에 상태 필터와 검색칸 |
| 예쁘게 해 줘 | 상태가 "출고대기"인 행은 주황색 배지로, 수량은 오른쪽 정렬로 |
| 버튼 추가 | 각 행 끝에 "상세" 버튼을 두고, 누르면 오른쪽에 주문 상세 패널을 열어 줘 |

### 6-2. 플립백 요청은 어떻게 쓰나요
결론: 테이블 정보(연결 이름, 테이블, 컬럼과 타입), 입력, 출력, 오류 조건, 쓸 노드를 적으세요. 로그인 사용자 정보는 입력으로 받지 말고 `$user` 로 쓰라고 하세요.

```text
[테이블 정보]
연결 이름: <연결이름> (PostgreSQL)
- <스키마>.post: id bigint, author_id text, author_name text, purpose text, message text, created_at timestamptz

방명록에 글을 저장하는 플로우를 만들어 줘. 입력은 purpose(필수)와 message 야.
작성자는 입력으로 받지 말고 $user.fBaseUserID, $user.fBaseUserName 으로 저장해.
purpose 가 비어 있으면 400 '방문 목적을 입력해 주세요' 오류로 끝내 줘. 저장한 글은 RETURNING 으로 돌려줘.
```

- AI 는 DROP 같은 위험한 SQL 은 제안하지 않고, 프로시저는 이름을 말해 준 경우에만 부릅니다.

## 7. 알려진 제약과 지원하지 않는 것

- 두 도구 모두 삭제는 휴지통(보관) 처리입니다.

## 8. 자주 막히는 증상과 조치

| 증상·메시지 | 원인 | 할 일 |
|---|---|---|
| 미리보기에 「로그인이 필요합니다」 | 미리보기 사용자를 정하지 않음 | 열쇠 아이콘 [사용자 정보 지정]에서 앱·테넌트·사용자 지정(3-3) |

| 「SP명에는 {{ }} 표현식을 쓸 수 없습니다」 | SP 이름에 표현식 사용 | SP 이름을 그대로 적고 갈래는 If·Switch 로 |

문의할 때는 워크스페이스, 프로젝트 또는 플로우 이름, 누른 순서, 오류 문구 전체(텍스트), 실행 내역의 실행 시각을 함께 보내세요.
