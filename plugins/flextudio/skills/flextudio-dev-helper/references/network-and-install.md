# 네트워크와 설치: 방화벽, K-System 연동 서비스(Flex-K), HTTPS, 사용자 동기화

쓰는 법
연동 서비스 설치 준비물과 기본 접속 오류 대조는 앱 만들기와 배포 설명의 "K-System 연동 서비스 설치 사전 점검" 절에 있습니다.
서비스 오류 메시지 한 줄 대조는 문제 해결 표에 있습니다. 이 파일은 그보다 깊은 네트워크 확인과 고객사 IT 와 주고받을 내용을 다룹니다.

## 1. 통신 경로 한눈에 보기

플렉스튜디오 연동에는 방향이 다른 두 갈래가 있습니다. 어느 갈래에서 끊겼는지 먼저 가리면 확인할 장비가 정해집니다.

```text
[갈래 A] 사용자 단말 ──HTTPS 443 아웃바운드──▶ 플렉스튜디오 도메인 (화면, 서비스 요청)
[갈래 B] 플렉스튜디오 중계서버 ──인바운드──▶ 고객사 ERP 앱 서버(IIS, 연동 서비스) ──▶ ERP DB
```

| 갈래 | 출발지 | 목적지 | 고객사에서 볼 장비 |
|---|---|---|---|
| A 화면·서비스 요청 | 사용자 PC, 모바일, 키오스크 | 플렉스튜디오 도메인 443 | 사내 방화벽 아웃바운드, 프록시, 웹 필터 |
| B ERP 연동 | 플렉스튜디오 중계서버 | ERP 앱 서버 연동 서비스 포트 | 경계 방화벽 인바운드, 웹방화벽(WAF), IIS |
| 외부 DB 연동 | 플렉스튜디오 외부 DB 연동 서버 | 고객사 DB 포트 | 경계 방화벽 인바운드 |

- 갈래 B 는 항상 플렉스튜디오 쪽에서 고객사로 들어가는 방향입니다. 고객사 ERP 가 플렉스튜디오로 먼저 접속하지 않습니다.
- 브라우저 F12 콘솔의 `net::ERR_*` 는 갈래 A 의 문제이고, 서비스 응답 본문의 `connect ETIMEDOUT <주소>:<포트>`, `ECONNRESET` 은 갈래 B 의 문제입니다.

## 2. 방화벽 담당자에게 보낼 요청 항목

### 2-1. 갈래 B(ERP 연동) 인바운드 허용 요청서에 무엇을 적나요
결론: "출발지 IP → 고객사 서버의 수신 포트" 로 여는 규칙입니다. 출발 포트는 고정되지 않으므로 조건에 넣지 마세요.

| 항목 | 적을 값 | 비고 |
|---|---|---|
| 출발지 IP | 3.38.20.130, 15.165.13.115 | 두 개를 함께 여는 것을 권장합니다 |
| 목적지 | ERP 앱 서버의 공인 IP 또는 도메인 | 내부 IP 는 플렉스튜디오에서 닿지 않습니다 |
| 목적지 포트 | 연동 서비스 8585(기본). 도메인과 SSL 을 적용했으면 443 | 서버킷은 설치 때 정한 포트 |
| 출발 포트, 프로토콜, 방향 | Any, TCP, 인바운드 | 출발 포트는 요청마다 바뀝니다 |

출발지 IP 는 바뀔 수 있습니다. 설치 전에 플렉스튜디오 담당자에게 최신 값을 꼭 확인하세요.
할 일:
1. 위 표를 그대로 방화벽 담당자에게 보내세요.
2. 웹방화벽(WAF)이나 IPS 가 따로 있으면 같은 출발지 IP 를 예외로 넣어 달라고 함께 요청하세요(4-3).
3. 허용이 끝나면 디버거에서 K-System 서비스 하나를 실행해 보세요.
확인: 연결 오류 대신 SP 결과나 SP 오류 메시지가 오면 네트워크는 열린 것입니다.

### 2-2. 사용자 단말 쪽(갈래 A)에는 무엇을 열어야 하나요
결론: 단말에서 밖으로 나가는 HTTPS 443 을 도메인 기준으로 허용합니다. 플렉스튜디오 앞단 IP 는 여러 개가 돌아가며 바뀌므로 IP 로 막고 열면 안 됩니다.

| 허용할 도메인 | 용도 |
|---|---|
| `*.flextudio.com` | 앱 화면, 서비스 요청, 콘솔 |
| 화면이 불러오는 외부 스크립트 도메인 | F12 Network 탭에서 실패한 요청의 도메인으로 확정합니다(6-1) |

- TCP 443 은 반드시 열려 있어야 합니다. UDP 443 은 6-2 를 보세요.

### 2-3. 외부 DB 연동은 어떤 IP 를 여나요
결론: 외부 DB 연동은 출발지가 따로 있습니다. 3.37.52.246 → 고객사 DB 포트를 인바운드로 여세요.
이 값도 바뀔 수 있으니 공식 문서 "외부 DB 연동" 쪽의 Flextudio IP 항목과 플렉스튜디오 담당자에게 최신 값을 확인하세요.

## 3. 연동 서비스 설치와 HTTPS 전환

### 3-1. 연동 서비스 설치를 요청할 때 무엇을 준비하나요
결론: 아래 다섯 가지를 정리해 플렉스튜디오 담당자에게 보내면 설치 일정을 잡을 수 있습니다.

| 항목 | 내용 |
|---|---|
| 설치 타입 | ERP 모바일 서버 설치 안내 문서의 구성 중 어느 것인지 |
| 앱 서버 | 연동 서비스를 올릴 IIS 서버의 원격 접속 주소 |
| 모바일 포트 | 기본 8585 |
| SSL 여부 | 도메인과 인증서를 쓰는지 |
| 운영 DB 이름 | 법인별 운영 DB 이름 |

- 임시 서버에는 설치하지 않습니다. 운영할 서버를 준비하세요.
- 연동 서비스는 ERP 모바일 IIS 사이트의 구성 요소를 함께 씁니다. 설치하면 모바일 구성 요소가 최신으로 바뀌고, DB 패치와는 따로 움직입니다.
- [확인 필요] 정기 패치 시간대와 그동안 멈추는 범위는 공지로 확인하세요.

### 3-2. 고객사 서버를 HTTP 에서 HTTPS 로 바꾸면 무엇을 고치나요
결론: 고객사 서버 쪽 설정과 테넌트 [시스템 정보] 두 곳을 함께 바꿔야 합니다. 포트만 바꾸면 웹서비스가 동작하지 않습니다.
할 일:
1. 고객사 서버에 도메인 바인딩과 인증서를 적용하세요. 인증서는 루트와 중간 인증서를 묶은 전체 체인이어야 합니다.
2. 연동 서비스의 웹서비스 설정 파일(web.config)을 HTTPS 바인딩에 맞게 고치세요. ERP 설치 매뉴얼 절차대로 고객사나 수행 파트너가 진행합니다.
3. 콘솔 테넌트 [시스템 정보]의 연동 주소와 포트를 새 값으로 바꾸세요.
4. 운영 테넌트를 바로 바꾸기 어렵다면 시험용 테넌트를 하나 만들고 HTTPS 값을 넣어 먼저 시험하세요.
확인: 시험 테넌트에서 K-System 서비스와 파일 첨부가 모두 되면 운영 테넌트 값을 바꾸세요.
- HTTP 바인딩을 그대로 두면 HTTP 와 HTTPS 를 함께 쓸 수 있습니다. 이때는 HTTP 포트도 방화벽에 열려 있어야 합니다.
- 인증서는 도메인에 발급되므로 IP 주소로 접속하면 이름이 맞지 않습니다. 연동 주소는 도메인으로 넣으세요.
- 사내 인증기관(CA)이 발급한 인증서는 플렉스튜디오가 그 루트를 따로 등록해야 연결됩니다. 공인 인증기관 인증서를 권장하고, 사내 CA 를 써야 하면 담당자와 미리 협의하세요.
- 공인 DNS 에 없는 사내 전용 도메인은 그대로는 닿지 않습니다. 시험이 필요하면 담당자와 협의하세요.

### 3-3. 파일을 첨부하면 로딩이 끝나지 않고, 콘솔에 Mixed Content 가 보입니다
결론: 파일 업로드와 다운로드는 브라우저가 고객사 파일 서비스 주소를 직접 부릅니다. 앱 화면은 HTTPS 이므로 파일 서비스 주소가 HTTP 면 브라우저가 막습니다.
원인: 테넌트 [시스템 정보]의 연동 서비스 파일 서비스 주소가 `http://` 이거나 IP 주소입니다.
할 일:
1. F12 콘솔에서 `Mixed Content` 와 `Failed to fetch` 문구를 확인하세요.
2. 파일 서비스 서버에 접속 도메인과 이름이 맞는 인증서를 설치하세요.
3. [시스템 정보]의 파일 서비스 주소를 `https://<인증서 도메인>:<포트>` 로 바꾸세요.
확인: 다시 첨부했을 때 F12 Network 의 업로드 요청이 200 으로 끝나면 해결된 것입니다.
- [확인 필요] HTTPS 로 바꾼 뒤 출력물(OZ 리포트) 화면만 비어 있으면 출력 서버 주소가 아직 HTTP 일 수 있습니다. F12 Network 에서 차단된 주소가 `http://` 인지 보고 ERP 담당 부서에 확인하세요.

## 4. 연결 점검 순서

### 4-1. ERP 연동이 아예 안 될 때 어디부터 보나요
결론: 설정 → 네트워크 → 인증서 → 앞단 장비 → SP 순서로 좁힙니다. 앞 단계가 맞아야 뒤 단계 메시지가 의미가 있습니다.
할 일:
1. 콘솔 테넌트 [시스템 정보]의 연동 주소, 포트, 업무 DSN, 운영 DSN 이 모두 채워졌는지 보세요.
2. 디버거에서 K-System 서비스 하나를 실행하고 오류 원문을 텍스트로 복사하세요.
3. 아래 표에서 오류가 어느 단계인지 고르세요.

| 오류에 보이는 것 | 막힌 단계 | 확인할 사람 |
|---|---|---|
| `ECONNREFUSED`, `ENOTFOUND`, `connect ETIMEDOUT` | 네트워크(방화벽, 주소, 포트) | 고객사 방화벽 담당자 |
| `unable to verify the first certificate`, 인증서 문구 | 인증서 체인 | 고객사 서버 담당자 |
| HTML 페이지 내용, `400 Bad Request`, `Malicious Code Detected` | 웹방화벽이나 IIS 오류 페이지(4-3) | 고객사 보안 담당자 |
| "연결정보 '…' 는 서버에 존재하지 않습니다" | ERP 앱 서버의 연결 설정(4-4) | ERP 서버 담당자 |
| SP 이름, 컬럼 이름이 든 SQL 오류 | 연결은 정상, SP 문제 | SP 개발자 |

확인: 오류가 SQL 오류로 바뀌면 네트워크 단계는 끝난 것입니다. 그다음은 K-System SP 설명을 보세요.

### 4-2. 오래 걸리다가 실패합니다. 제한시간은 얼마인가요
결론: 플렉스튜디오가 고객사 응답을 기다리는 시간은 약 30초이고, 고객사별로 늘리는 설정은 없습니다.
- SP 가 30초 가까이 걸리면 조건을 좁히거나 처리를 나누세요.
- 실제 사례에서 연결 자체가 맺어지지 않을 때는 약 15초 뒤 `connect ETIMEDOUT` 이 났습니다. 이 경우는 SP 가 아니라 네트워크를 보세요.
- 한 번에 오가는 데이터는 약 4MB 를 넘으면 실패할 수 있습니다. 이미지가 든 조회는 파일 서비스로 나누세요.

### 4-3. HTML 이나 400 Bad Request 가 돌아옵니다 (웹방화벽 차단)
결론: 고객사 앞단의 웹방화벽(WAF)이 플렉스튜디오 요청을 공격으로 오인해 막은 것입니다. SP 는 실행되지 않았습니다.

| 응답 모양 | 흔한 원인 | 조치 |
|---|---|---|
| `400 Bad Request`, malformed request 류 HTML | 출발지 IP 가 WAF 예외에 없음 | 2-1 의 출발지 IP 를 WAF 예외로 등록 |
| `Malicious Code Detected` 류 | 보내는 값에 `<img …>` 같은 HTML 태그 | 보내기 전에 태그를 지우거나 바꾸세요 |
| SQL Injection 탐지 문구 | 정상 요청이 탐지 규칙에 걸림 | 그 경로를 출발지 IP 기준 예외로 등록 |

- 예외를 넣은 뒤에도 장비 정책 갱신으로 다시 막힐 수 있습니다. 재발하면 같은 응답 원문을 보안 담당자에게 다시 전달하세요.

### 4-4. "연결정보가 서버에 존재하지 않습니다" 가 나옵니다
결론: 플렉스튜디오는 ERP 앱 서버에 닿았고, ERP 앱 서버가 DSN 에 맞는 DB 연결 정보를 찾지 못한 것입니다.
할 일:
1. 테넌트 [시스템 정보]의 DSN 이름이 ERP 서버의 연결 설정과 같은지 보세요.
2. ERP 연동 주소가 최근에 바뀌었다면 새 주소로 고치세요.
3. 둘 다 맞으면 ERP 서버 담당자에게 서버 연결 설정 파일의 연결 문자열(따옴표 누락 등)을 확인하고 앱 풀을 재생해 달라고 요청하세요.

## 5. 가끔만 나는 통신 오류

### 5-1. 자동 갱신 화면에서 몇 시간에 한 번 "서버와 통신에 실패하였습니다" 가 뜹니다
결론: 서비스 두 개를 붙여서 연달아 부르거나, 여러 단말이 같은 초에 동시에 조회하면 두 번째 연결이 중간 장비에서 간헐적으로 거부될 수 있습니다.
할 일:
1. 연달아 부르는 두 번째 이벤트를 1초 늦춰 실행하세요.

```javascript
// 첫 조회가 끝난 뒤 1초 뒤에 두 번째 조회 이벤트를 실행합니다
setTimeout(function () {
  f.Event('<두번째조회이벤트>').runNext();
}, 1000);
```

2. 여러 키오스크가 시계 정각에 맞춰 조회하면 시작 시각을 단말마다 조금씩 다르게 하세요.
3. 키오스크 한 대에는 앱 탭을 하나만 띄우세요. 탭마다 따로 조회가 나갑니다.
확인: F12 Network 에서 30분 이상 돌려 `(failed)` 요청이 사라졌는지 보세요.

### 5-2. 실패 시각을 어떻게 모으나요
결론: 오류 창의 `RequestID` 앞부분 숫자가 발생 시각(밀리초 단위 epoch)입니다.
할 일:
1. 오류가 날 때마다 `RequestID` 줄을 복사해 모으세요.
2. 숫자를 시각으로 바꿔 고객사 방화벽 로그와 대조하세요.

### 5-3. 방화벽 담당자는 "차단 로그가 없다" 고 합니다
결론: 세션 테이블에서 조용히 버린 패킷은 일반 차단(deny) 로그에 남지 않습니다. 다른 종류의 로그를 요청해야 합니다.
할 일:
1. 실패 시각 앞뒤 15초 범위로 아래 로그를 요청하세요.
   - 세션 로그, out-of-state 드롭 로그(세션 정보 없는 패킷을 버린 기록)
   - SYN Flood, DoS 방어, 위협 로그
   - 출발지 3.38.20.130, 15.165.13.115 와 ERP 포트 양방향
2. ERP 서버가 보낸 RST 가 방화벽에서 버려지면 플렉스튜디오는 응답을 못 받고 `connect ETIMEDOUT` 으로 보게 됩니다. 이 경우 방화벽 설정만 고치면 오류 이름이 바뀔 뿐 사라지지 않을 수 있으니 ERP 서버 쪽 원인도 함께 보세요.
- 이 일은 고객사, 수행 파트너, 망 관리 업체가 함께 보는 일입니다. 요청은 고객사 담당자에게 보내세요.

### 5-4. 키오스크가 아침이나 저녁에만 오류를 냅니다
결론: `ERR_NETWORK_IO_SUSPENDED`, `ERR_NAME_NOT_RESOLVED`, `ERR_NETWORK_CHANGED` 가 절전 진입이나 복귀 때 함께 보이면 서버 문제가 아니라 단말 전원 문제입니다.
할 일: 키오스크 PC 의 절전과 화면 꺼짐을 해제하세요.

## 6. 사내망에서만 화면이 안 열릴 때

### 6-1. 외부에서는 열리는데 사내망 PC 에서만 흰 화면이 나옵니다
결론: 사내 방화벽이나 프록시가 화면이 불러오는 외부 스크립트 도메인을 막은 경우가 많습니다. 앞 스크립트 하나가 막히면 뒤에 `… is not defined` 오류가 줄줄이 따라 나옵니다.
할 일:
1. 문제가 난 바로 그 단말에서 F12 Network 탭을 열고 새로고침하세요.
2. 실패한 요청(빨간 줄)의 도메인을 모두 적으세요. 맨 처음 실패가 진짜 원인입니다.
3. 같은 단말을 휴대폰 핫스팟에 연결해 다시 열어 보세요. 열리면 사내망 차단이 확정됩니다.
4. 적은 도메인을 IP 가 아니라 도메인 기준으로 허용해 달라고 IT 담당자에게 요청하세요.
확인: 실패하던 요청이 200 이나 304 로 바뀌고 `is not defined` 오류가 사라지면 해결된 것입니다.
- 다른 PC 에서 그 주소를 열어 보고 "열린다" 고 판단하면 틀립니다. 반드시 문제 단말과 같은 망에서 확인하세요.

### 6-2. `ERR_QUIC_PROTOCOL_ERROR` 가 보입니다
결론: 브라우저가 UDP 443(QUIC)으로 먼저 붙었는데 사내망이 UDP 를 막은 것입니다.
할 일: UDP 443 을 허용하거나, 그 단말 브라우저에 QUIC 을 끄는 정책(`QuicAllowed` 를 false)을 적용해 TCP 443 만 쓰게 하세요.

## 7. 서버킷(구축형 서버)의 두 통신 경로

### 7-1. 서버킷은 어떤 길로 통신하고, 방화벽은 어떻게 여나요
결론: 서버킷은 고객사 Windows 서버에 설치하는 실행 환경이고, 통신 경로를 둘 중 하나로 정합니다. 경로에 따라 방화벽과 인증서 조건이 다릅니다.

| 경로 | 방화벽 | SSL | 맞는 경우 |
|---|---|---|---|
| 단말 → 서버킷 직접 | 서버킷 포트 Any 오픈 | 필수 | 대용량 파일을 주고받을 때 |
| 단말 → 중계서버 → 서버킷 | 출발지 IP(2-1)만 오픈 | 없어도 됨 | Any 오픈이 보안 정책상 안 될 때 |

- 중계 경로는 요청·응답 크기와 실행 시간에 제한이 있어 대용량 파일 처리에는 맞지 않습니다.
- 보안 정책상 Any 오픈이 어렵고 파일도 다뤄야 하면, 파일 전용 사이트를 따로 두고 허용 IP 를 좁히는 방안을 담당자와 협의하세요.
- 서버킷 IIS 사이트는 플렉스튜디오가 부르는 주소입니다. 사용자가 브라우저로 여는 주소가 아닙니다.
- `Connection to ServerKit timed out.` 이 나오면 서버킷 서비스 상태와 위 경로의 방화벽 조건을 확인하세요.

## 8. 외부 DB 와 외부 API 연결

### 8-1. 외부 DB 에서 로그인 실패(`ELOGIN`)가 나옵니다
결론: 네트워크는 DB 까지 닿았고, [외부 DB 정보]의 계정, 비밀번호, DB 이름 가운데 하나가 틀렸습니다.
할 일: DB 이름 철자와 계정 권한을 DB 담당자와 대조하세요. 호스트는 공인 IP 여야 합니다.

### 8-2. 화면에서 외부 API 를 부르면 CORS 오류가 납니다
결론: 브라우저가 직접 부르는 외부 API 는 그 API 쪽에서 플렉스튜디오 앱 도메인을 허용해야 합니다. 플렉스튜디오 설정으로는 풀 수 없습니다.
할 일:
1. F12 콘솔의 CORS 문구에서 막힌 출처(origin) 값을 복사하세요.
2. 외부 API 관리자에게 그 출처와 사전 요청(preflight)에 필요한 헤더 허용을 요청하세요.
3. 외부 API 설정을 바꿀 수 없으면 API 연동 서비스로 서버에서 부르는 방식을 검토하세요.

## 9. K-System 사용자 동기화 오류

### 9-1. 동기화가 되는 조건과 기본 규칙은 무엇인가요

| 규칙 | 내용 |
|---|---|
| 대상 앱 | 초대기반앱에 연결된 테넌트만 동기화됩니다 |
| 사람 구분 | 사번(EmpId)이 사용자 구분 기준입니다 |
| 필요한 값 | 사번, 이름, 휴대폰, 이메일 |
| ERP 에서 지운 사람 | 플렉스튜디오에서 자동으로 지우지 않습니다 |

- 휴대폰 번호 형식은 고객관리 설명과 같습니다(하이픈 없이 01000000000).
- 재직자와 퇴직자의 사번이 겹치면 어느 쪽이 남을지 알 수 없습니다. 사번 중복을 먼저 정리하세요.
- `_base.EmpSeq` 는 ERP 동기화로 들어온 사용자에게만 있습니다. API 로 만든 사용자에게는 없습니다.
- 표준 동기화용 FlexSQL 은 약속된 형식이라 고치지 마세요. 다른 기준이 필요하면 별도 동기화 방식을 담당자와 협의하세요.
- 동기화 뒤에 도는 후처리 FlexSQL 은 약 500명 단위로 나눠 여러 번 실행됩니다. 안에 테이블 전체 삭제(TRUNCATE)를 넣으면 마지막 묶음만 남습니다.

### 9-2. [사용자 동기화] 버튼이 `Internal server error.` 로 실패합니다
결론: 가장 흔한 원인은 테넌트 [시스템 정보]의 연동 서비스 주소(화면 라벨 'FlexK API URL')가 비었거나 틀린 것입니다. 별도 동기화 SP 를 만들 필요는 없습니다.
할 일:
1. [회사 정보] > [시스템 정보] > K-System 탭에서 연동 서비스 주소(화면 라벨 'FlexK API URL', https 도메인), 연동 주소와 포트, 회사 번호, 업무·운영 DSN 을 확인하세요.
2. 정상 동작하는 다른 테넌트와 항목별로 비교하세요.
3. 값이 모두 맞는데도 같으면 실행 시각을 적어 플렉스튜디오 담당자에게 서버 로그 확인을 요청하세요.
확인: 동기화 후 [사용자관리]에 ERP 사용자가 보이면 해결된 것입니다.

### 9-3. 시험 서버에서 동기화했는데 운영 테넌트에 사용자가 들어갑니다
결론: ERP 의 동기화 대상 테넌트 설정이 운영 값으로 남아 있는 것입니다. 시험 서버를 운영에서 복사해 만들면 자주 생깁니다.
할 일: ERP [K-스마트환경설정]의 동기화 테넌트를 시험 테넌트로 고치도록 ERP 담당 부서에 요청하세요.

### 9-4. ERP 에서 직접 사용자를 보낼 때 누가 이미 등록됐는지 모릅니다
결론: Tenant/User API 의 사용자 조회로 지금 등록된 사람을 먼저 받아 비교하세요. 전체 삭제 후 재등록은 앱 권한이 풀리고 로그인이 해제되므로 권하지 않습니다.
할 일:
1. 사용자 조회를 cursor 방식(`cursorMode=true`, 한 번에 최대 1000명)으로 부르고 `hasNextPage` 가 true 인 동안 `nextCursor` 로 이어 받으세요.
2. ERP 명단과 사번(fBaseUserNo) 기준으로 비교하세요.
3. ERP 에만 있으면 TransactUser C 와 GrantAppUser, 값이 다르면 U, 플렉스튜디오에만 있으면 RevokeAppUser 로 앱 권한만 회수하세요.
- 조회에는 Read Only 이상 권한의 API 키가 필요합니다. API 문서는 플렉스튜디오 담당자에게 받으세요.
- [확인 필요] 이미 있는 사람에게 C 를 보내거나 이미 권한이 있는 사람에게 GrantAppUser 를 다시 보낼 때의 응답은 시험 테넌트에서 먼저 확인하세요.

## 10. 세션과 로그인 문제

### 10-1. 세션은 언제 만료되나요
결론: 그 기기에서 처음 로그인한 때부터 테넌트에 정한 세션 유지일이 지나면 만료됩니다. 기본값은 90일입니다.
- 모바일에서 먼저 로그인하고 나중에 PC 에서 로그인하면 PC 는 PC 로그인 시점부터 따로 셉니다.

### 10-2. 모바일 앱에서 로그인이 갑자기 풀립니다
결론: 서버 응답을 받기 전에 앱을 강제 종료하면 새 인증 정보를 못 받아 다음 요청에서 로그아웃됩니다. 인증 정보 탈취를 막는 설계 동작입니다.
할 일:
1. 스토어 최신 앱을 쓰는지 확인하세요. 예전 설치 파일(APK)을 직접 깐 앱도 같은 증상을 냅니다.
2. PC 브라우저에서 반복되면 브라우저 복원, 계정 동기화, 백신, 사용자 프로필 복원 프로그램이 예전 접속 정보를 되살리는지 확인하세요.

### 10-3. 앱 전환 뒤 가끔 `checking your Token.` 이 뜹니다
결론: 앱 전환 때 토큰 갱신이 간헐적으로 처리되지 않는 문제가 보고됐고 플랫폼에서 개선을 검토했습니다.
할 일:
1. [확인 필요] 현재 개선 상태는 QnA 게시판에서 확인하세요.
2. 재발하면 발생 시각, 앱, 테넌트, 사용자를 적어 문의하세요.

### 10-4. 앱 전환이 느립니다
결론: 로그인 세션을 앱 단위로 관리하므로 앱을 바꿀 때마다 로그인 과정이 다시 돕니다.
할 일: 전환 후 처음 여는 시나리오를 가볍게 만드세요. 첫 화면의 init 처리와 시나리오 크기가 작을수록 빨라집니다.

### 10-5. PC 에서 특정 IP 에서만 접속하게 할 수 있나요
결론: 공식 답변은 시나리오에서 막는 방법입니다. `f.Native.getIP` 로 IP 를 받아 `f.IP.address` 를 검사하고, 허용 목록에 없으면 안내 후 진행을 멈추세요.
[확인 필요] 인자 뜻은 공식 명세 f.Native.getIP 절에서 확인하세요.
