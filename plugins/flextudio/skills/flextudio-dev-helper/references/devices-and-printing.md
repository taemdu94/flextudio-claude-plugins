이 파일이 답하는 질문: 인쇄 창 없이 버튼 한 번에 출력할 수 있나요 / Chrome 실행 옵션과 QZ Tray 중 무엇을 쓰나요 / 라벨 용지와 여백은 어떻게 맞추나요 / OZ 출력물을 뷰어 없이 바로 낼 수 있나요 / 앱에서 인쇄하려면 / PDA 스캐너 값은 어떻게 들어오나요 / 스캔값이 한글로 깨져요 / 안드로이드 앱 빌드와 출시에서 막혀요 / 오래된 단말에서도 되나요

목차
1. 출력 방식 고르기
2. 화면에서 라벨을 그려 인쇄하기
3. Chrome 실행 옵션(--kiosk-printing)
4. 출력 연결 프로그램(QZ Tray)
5. 프린터·용지·여백

쓰는 법
- 출력과 스캔의 짧은 요약은 구축과 배포 설명의 모바일 앱과 PDA 절, 출력과 인쇄 절에 있습니다. 이 파일은 그보다 자세한 설치 단계와 실패 조치를 다룹니다.
- 문서 요소(DOM)를 직접 다루는 스크립트는 비공식 방식입니다. 플렉스튜디오 업데이트로 화면 구조가 바뀌면 깨질 수 있다는 경고를 꼭 함께 전하세요.
- 바로 출력은 제품 기능으로 넣는 개선을 검토하고 있습니다. 아래 2~4절은 그 전까지 쓰는 임시 방법입니다.

## 1. 출력 방식 고르기

### 1-1. 출력 버튼을 누르면 인쇄 창 없이 바로 나가게 할 수 있나요?
결론: 웹 화면은 프린터에 직접 닿지 못해 기본으로는 브라우저 인쇄 창이 뜹니다. 단말 쪽 준비를 하면 버튼 한 번에 낼 수 있습니다.

| 방식 | 인쇄 창 | 단말 준비 | 맞는 곳 |
|---|---|---|---|
| 브라우저 인쇄(`window.print()`) | 뜸 | 없음 | 가끔 출력하는 일반 업무 |
| Chrome 실행 옵션 `--kiosk-printing` | 안 뜸(미리보기가 잠깐 깜빡임) | 바로가기 설정, 프린터 1회 선택 | 출력 전용 PC, 현장 단말 |
| 출력 연결 프로그램(QZ Tray) | 안 뜸(처음엔 허용 창) | 단말마다 설치, 서명 인증서 등록 | 깜빡임 없이 여러 프린터를 골라 쓸 때 |
| OZ 출력물 기본 | OZ 뷰어 + 브라우저 인쇄 창 | 없음 | ERP 출력물을 그대로 쓸 때 |

- 바로 출력 두 방법은 Windows PC 의 Chrome 기준이고 모바일 앱에는 해당하지 않습니다. 단순 양식은 Chrome 실행 옵션부터, OZ 서식은 6절을 보세요.

## 2. 화면에서 라벨을 그려 인쇄하기

### 2-1. 라벨 양식을 화면 HTML 로 만들어 인쇄하려면
결론: 인쇄 전용 마크업을 Embed 컨트롤에 따로 두고, 인쇄 직전에 그 요소를 문서 body 바로 아래로 옮긴 뒤 `window.print()` 를 부릅니다.
할 일:
1. 라벨 마크업을 Embed 컨트롤에 고유 id 로 두세요. 화면 컨트롤을 그대로 인쇄하지 마세요.
2. 바코드 그림이 필요하면 시나리오 [외부파일설정]에 바코드 라이브러리를 넣으세요(예: `https://cdn.jsdelivr.net/npm/jsbarcode/dist/JsBarcode.all.min.js`, 시험한 판은 3.11.6).
3. 바코드 값에 `;` 나 소문자가 있으면 CODE128 이나 QR 로 만드세요. Code39 는 대문자·숫자와 일부 기호만 담습니다.
4. `@media print` 로 라벨만 보이게 하고, 버튼 이벤트 스크립트에서 라벨 요소를 body 로 옮긴 뒤 인쇄하세요.
원인: 크기가 고정된 그룹 안에 있으면 그룹 밖은 잘려서 인쇄됩니다. `position:absolute` 로도 그룹 밖으로 나오지 못합니다.
확인: 브라우저 인쇄 미리보기에 라벨 한 장이 잘리지 않고 보이면 성공입니다.

### 2-2. 라벨이 여러 장 겹쳐 나오거나, 두 번째 카드부터 바코드가 비어요
결론: Embed 를 감싼 그룹이 카테고리의 행 수만큼 복제되어 같은 id 가 여러 개 생긴 것입니다.
할 일: 그룹의 [데이터 용도]를 고른 1건만 그리는 값으로 바꾸고 대상 섹터를 지정하세요. 자세한 내용은 화면과 데이터 설명의 데이터 용도 절에 있습니다.
확인: 행이 여러 건인 상태에서 인쇄해도 라벨이 한 장만 나오면 성공입니다.

## 3. Chrome 실행 옵션(--kiosk-printing)

### 3-1. 출력 전용 Chrome 을 설정하려면
결론: Chrome 을 `--kiosk-printing` 옵션으로 켜면 인쇄 요청이 확인 없이 마지막에 고른 프린터로 나갑니다.
할 일:
1. 출력 전용 프로필 폴더를 하나 만드세요(빈 폴더).
2. 바탕 화면에 바로가기 `출력설정`(아래 첫 줄)과 `바로출력`(둘째 줄)을 만드세요.
3. `출력설정` 으로 앱을 열어 로그인하고, 출력 버튼을 눌러 인쇄 창을 띄우세요.
4. 대상 프린터를 고르고 [설정 더보기]에서 머리글과 바닥글을 끄고 여백을 정하세요. [취소]를 눌러도 고른 값이 기억됩니다.
5. 창을 닫고 앞으로는 `바로출력` 으로 여세요.
```text
"<Chrome 설치 폴더>\chrome.exe" --user-data-dir="<출력 전용 폴더>" --app="<앱 주소>"
"<Chrome 설치 폴더>\chrome.exe" --user-data-dir="<출력 전용 폴더>" --kiosk-printing --app="<앱 주소>"
```
- `--user-data-dir` 는 평소 Chrome 과 나눈 전용 프로필, `--app` 은 주소창 없는 앱 창입니다.
확인: `바로출력` 창에서 출력 버튼을 누르면 인쇄 창 없이 종이가 나옵니다.

### 3-2. Chrome 실행 옵션이 먹지 않아요
| 보이는 것 | 원인 | 조치 |
|---|---|---|
| 인쇄 창이 그대로 뜸 | 같은 프로필의 Chrome 창이 옵션 없이 이미 떠 있었음 | 그 창을 모두 닫고 `바로출력` 으로 다시 여세요 |
| 종이 대신 PDF 가 저장됨 | 대상이 "PDF로 저장"으로 기억됨 | `출력설정` 으로 3-1 의 3~4번을 다시 하세요 |
| 날짜·주소가 같이 찍힘 | 머리글과 바닥글이 켜짐 | 3-1 의 4번을 다시 하세요 |
| 바코드 없이 오류 안내 | 바코드 라이브러리를 받지 못함 | 사내망에서 `cdn.jsdelivr.net` 접속을 열거나 파일을 내부 서버에 두세요 |

- 단말을 켤 때 자동으로 열려면 `바로출력` 을 시작프로그램 폴더(`shell:startup`)에 넣으세요. [확인 필요] Chrome 144 이상에는 같은 동작을 켜는 관리 정책(`SilentPrintingEnabled`)이 있습니다. PC 단위 설정이라 그 PC 의 모든 사이트 인쇄가 바로 나갑니다. 플렉스튜디오에서 실측하지 않았으니 IT 담당자와 시험한 뒤 쓰세요.

## 4. 출력 연결 프로그램(QZ Tray)

### 4-1. QZ Tray 는 어떻게 동작하고 어떻게 설치하나요?
결론: PC 에 설치하는 작은 출력 프로그램입니다. 화면이 출력 내용과 프린터 정보를 같은 PC 안 통로(localhost)로 넘기면 프로그램이 Windows 인쇄로 바로 보냅니다.
할 일:
1. `https://github.com/qzind/tray/releases` 에서 Windows 설치 파일을 받으세요.
2. 파일 [속성] > [디지털 서명]에서 서명자가 QZ Industries LLC 인지 확인하세요.
3. 설치하세요. 알림 영역에 QZ Tray 아이콘이 생기면 준비가 끝났습니다.
4. 시나리오 [외부파일설정]에 `https://cdn.jsdelivr.net/npm/qz-tray/qz-tray.js` 를 넣고(시험한 판은 2.3.0, 설치한 QZ Tray 와 같은 판으로 고정), 출력 버튼 스크립트 예제는 담당자에게 받으세요.
확인: 배포한 앱 주소에서 출력 버튼을 누르고 허용 창에서 [Allow]를 누르면 종이가 나옵니다.
- 오픈소스(LGPL-2.1)라 무료이고, 유료는 기술 지원과 회사 전용 빌드입니다. 회사 PC 는 외부 프로그램 설치에 승인이 필요할 수 있습니다. 설치 전에 전산 담당자에게 확인하세요.

### 4-2. 허용 창(Untrusted website)을 없애려면
결론: 회사 인증서로 요청마다 서명하면 묻지 않고 출력합니다.
할 일:
1. 회사 인증서와 개인키를 한 번 만드세요. 직접 만든 인증서로도 됩니다.
2. 공개 인증서를 각 단말의 QZ Tray 설치 폴더에 `override.crt` 로 넣고 QZ Tray 를 다시 켜세요.
3. 요청 서명은 서버에서 하세요. 개인키는 서버에만 둡니다.
- 개인키를 시나리오 스크립트, 호스팅 폴더, [외부파일설정]에 두지 마세요. 모두 브라우저로 내려가 누구나 받아 갈 수 있습니다. 허용 창의 "Remember this decision" 은 체크하지 마세요. 서명 없는 사이트에서 체크하면 [Allow]가 비활성화된다는 공개 사례가 있습니다.
- [확인 필요] 서명을 붙였을 때 허용 창 없이 나가는지는 사내 PC 한 대에서만 시험했습니다.

### 4-3. QZ Tray 로 출력하지 못했다는 오류가 나요
| 보이는 것 | 원인 | 조치 |
|---|---|---|
| 배포 앱에서 연결 실패 | QZ Tray 가 꺼져 있거나 설치되지 않음 | 알림 영역 아이콘을 확인하고 시작 메뉴에서 켜세요 |
| Studio 디버거에서만 연결 실패 | 디버거는 다른 주소의 iframe 이라 Chrome 이 PC 안 프로그램 연결을 막음 | 배포한 앱 주소에서 시험하세요 |
| 아무것도 안 나감 | 허용 창에서 [Block]을 누름 | 다시 누르고 [Allow]를 누르세요 |
| 보안망에서만 실패 | Chrome 정책이 사이트의 localhost 호출을 막음 | 전산 담당자에게 정책 예외를 요청하세요 |

## 5. 프린터·용지·여백

### 5-1. 용지가 없다며 멈추거나 글자가 잘려요
| 상황 | 할 일 |
|---|---|
| 사무용 A4 프린터에 용지 크기를 지정해 보냄 | 크기 지정을 빼세요. 그 크기 용지가 없으면 프린터가 "용지 없음"으로 멈춥니다 |
| A4 에 여백 0 으로 보냄 | 여백을 5mm 정도 주세요. 가장자리는 찍히지 않아 위·왼쪽이 잘립니다 |
| 라벨 프린터를 씀 | 프린터 드라이버에 라벨 용지(예: 100x60mm)를 등록하고, 라벨 크기와 `@page` 크기를 같게 맞추세요 |
| 인쇄 창에서 사용자가 용지를 고름 | Chrome 은 `@page` 크기 대신 고른 용지를 씁니다 |

- Chrome 은 프로필마다 마지막에 고른 프린터를 기억합니다. 처음 쓰는 프로필은 Windows 기본 프린터로 잡힙니다. [확인 필요] 라벨 프린터에서 한 장에 한 라벨이 정확히 맞는지는 아직 시험하지 않았습니다. 첫 장을 눈으로 확인하세요.

### 5-2. ZPL 같은 라벨 프린터 언어를 직접 보내고 싶어요
결론: 브라우저는 프린터의 9100 포트로 직접 연결하지 못합니다. 드라이버로 인쇄하거나 PC 설치 프로그램을 거치세요.
[확인 필요] QZ Tray 의 프린터 언어 직접 전송(raw)은 플렉스튜디오 화면에서 시험하지 않았습니다.

## 6. OZ 출력물

### 6-1. OZ 출력물을 뷰어 없이 바로 출력할 수 없나요?
결론: 플렉스튜디오 화면은 ERP 가 만든 OZ HTML5 뷰어를 띄웁니다. OZ 파라미터만으로는 브라우저 인쇄 창을 없앨 수 없습니다.
원인: HTML5 뷰어는 인쇄용 PDF 를 만든 뒤 브라우저 인쇄 창을 엽니다. 웹 페이지가 인쇄 창을 건너뛰는 방법은 웹 표준에 없습니다.
- 뷰어의 인쇄 옵션 창(매수, 범위, 용지)은 OZ 인쇄 명령에 조용한 인쇄 값을 주면 건너뜁니다. 그 뒤의 브라우저 인쇄 창은 그대로 뜹니다.
- PC 설치형 OZ 뷰어나 OZ 스케줄러 서버 인쇄는 OZ 공식 기능이지만, K-System 이 제공하는지와 라이선스는 [확인 필요] 입니다. ERP 담당 부서에 물어보세요. 모바일 앱에서는 PDF 로 받아 인쇄하고, 기기와 프린터를 같은 네트워크에 두세요.

### 6-2. 그래도 OZ 서식 그대로 버튼 한 번에 내야 해요
결론: 뷰어를 화면 밖에 숨겨 PDF 를 받은 뒤 인쇄하는 스크립트와 3절의 Chrome 실행 옵션을 함께 쓰면 버튼 한 번에 나갑니다. 사내 시험에서 확인했습니다.
할 일:
1. 출력 버튼 이벤트의 OZ 출력물 서비스 앞뒤에 스크립트 액션을 하나씩 두세요. 스크립트는 담당자에게 받으세요.
2. 출력 PC 의 Chrome 을 3-1 처럼 설정하세요. 이 설정이 없으면 브라우저 인쇄 창이 한 번 뜹니다.
확인: 버튼을 누른 뒤 뷰어가 보이지 않고 2~4초 안에 종이가 나오면 성공입니다.
- 엔진의 뷰어 창 구조를 직접 다루는 비공식 방법입니다. 업데이트로 구조가 바뀌면 스크립트를 고쳐야 합니다. [확인 필요] 모바일 앱과 PDA, 여러 쪽 보고서에서는 시험하지 않았습니다.

### 6-3. 출력물 서비스가 Bad Request 로 실패해요
결론: 같은 오류 이름이라도 플렉스튜디오에서 막힌 경우와 ERP·OZ 서버까지 간 뒤 실패한 경우가 있습니다.
할 일:
1. F12 [Network]에서 출력물 요청의 응답 본문을 여세요.
2. 본문이 서버 오류 HTML 이고 `.odi` 나 repository 같은 OZ 서버 예외가 보이면 ERP·OZ 서버 쪽 문제입니다. ERP 담당 부서에 응답 본문을 전하세요.
3. 같은 출력물이 A 화면에서는 되고 B 화면에서만 실패하면 출력물과 OZ 서버는 정상입니다. 두 화면이 보내는 요청을 비교하세요.
4. 그 밖의 경우는 출력물 서비스 설정의 빈 값을 채우세요. 시스템 정보 오류는 K-System SP 설명의 오류 표를 보세요.

## 7. 설치형 앱에서 인쇄하기

### 7-1. 앱에서 인쇄 버튼을 눌러도 아무 일이 없어요
결론: 설치형 앱은 `window.print()` 를 조용히 무시합니다. 인쇄할 때만 웹 주소를 만들어 기기 브라우저로 넘기세요.
할 일:
1. 출력 버튼 이벤트에서 앱인지 가리고, 앱이면 웹 링크를 만들어 브라우저로 여세요.
2. 받는 화면 Step 의 시작 이벤트에서 링크 파라미터를 읽어 데이터를 채우고 인쇄하세요.
```javascript
// 출력 버튼 이벤트 스크립트
if (f.Native.isOn) {
  var url = f.Link.createAppLink({ print: 'label', LotID: '<LotID 값>' }, true); // true = 웹 주소
  f.Browser.open(url);
} else {
  window.print();
}
```
```javascript
// 받는 Step 의 시작 이벤트 스크립트
var p = f.Link.getLinkParam();
if (p && p.print === 'label' && !_v.linkPrintDone) {
  _v.linkPrintDone = true;               // 같은 링크로 두 번 인쇄하지 않게 막습니다
  setTimeout(function () { window.print(); }, 500);
}
```
- `createAppLink` 둘째 인자를 `false`(앱 링크)로 주면 앱이 다시 열려 같은 동작이 되풀이됩니다. 브라우저는 앱과 세션이 따로라 로그인 화면이 먼저 뜰 수 있습니다. 웹앱으로 운영할 수 있으면 그쪽이 동선이 짧습니다.
- 앱 화면에 바로 인쇄하는 기능은 지원하지 않습니다. 개선 과제로 요청하세요.

## 8. PDA 스캐너 입력

### 8-1. 스캐너 값이 화면에 들어오는 방식은 무엇이 있나요?
| 방식 | 값이 들어오는 곳 | 키보드 언어 영향 | 만들 것 |
|---|---|---|---|
| 키보드 모드(웨지) | 커서가 있는 입력 컨트롤 | 받음 | 입력이 멈춘 뒤 한 번 조회(8-2) |
| `f.Scanner` | 숨은 입력칸 → 지정한 카테고리 | 받음(입력 경로가 같은 웨지) | init 설정, 스캔 이벤트(8-3) |
| 카메라 `f.Native.getBarcode` | 결과 이벤트의 `f.Barcode.value` | 받지 않음 | 9절 |
| 블루투스 스캐너 | 키보드 모드와 같음 [추정] | 받음 [추정] | 연결 때 앱이 첫 화면으로 가면 앱을 최신으로 업데이트 |
| 스캐너 앱의 인텐트 출력 | [확인 필요] 플렉스튜디오에서 받는 방법이 확인되지 않음 | 받지 않음 | 담당자에게 문의 |

### 8-2. 키보드 모드 스캐너로 입력이 끝나면 자동 조회하려면
결론: 입력 컨트롤에는 Enter 전용 이벤트가 없습니다. input 이벤트에서 타이머를 걸어 입력이 멈춘 뒤 한 번만 조회하세요.
```javascript
// 바코드 입력 컨트롤의 input 이벤트 스크립트
var now = Date.now();
var val = (_c.<카테고리> && _c.<카테고리>[0] ? _c.<카테고리>[0].<키> : '') || '';
if (!_v.scanBurst || now - _v.scanBurst.last > 400) _v.scanBurst = { start: now, count: 0 };
_v.scanBurst.last = now; _v.scanBurst.count++;
if (_v.scanTimer) clearTimeout(_v.scanTimer);
_v.scanTimer = setTimeout(function () {
  var b = _v.scanBurst;
  if (!b || val.length < 8) return;                                  // 최소 길이
  if (!(b.count === 1 || (b.last - b.start) / b.count < 30)) return; // 스캐너 속도 입력만
  if (_v.lastScanQueried === val) return;                            // 같은 값 중복 조회 방지
  _v.lastScanQueried = val;
  f.Event('<조회이벤트>').runNext();
}, 300);
```
- 손 입력용으로 change 이벤트에도 조회를 걸어 두어도 중복 조회는 생기지 않습니다.
- 스크립트에서 값을 고쳐 컬렉션에 넣어도 입력 컨트롤 글자는 그대로입니다. 화면 글자까지 바꾸려면 `f.Component('<fid>').element` 안의 input 요소에 직접 값을 넣으세요(비공식).

### 8-3. f.Scanner 를 설정하는 순서
할 일:
1. Step 시작 이벤트에서 `f.Scanner.init(options)` 를 한 번 부르세요. init 없이 `startScan()` 을 부르면 메시지 없이 끝납니다. [확인 필요] `scanSuffix`·`usePDAModels` 밖의 옵션은 [함수 자동 생성] 코드와 대조하세요.
2. 스캐너 앱의 접미 문자열(예: `~#A#~`)을 `scanSuffix` 와 똑같이 맞추세요. Enter·Tab 키 방식 종료는 감지하지 못합니다.
3. 스캔 이벤트에서 카테고리의 마지막 행을 읽고 바로 비우세요. 첫 행을 읽으면 두 번째 스캔부터 옛 값을 읽습니다.
4. 스캔 중 표시는 엔진 상태 대신 직접 켜는 `_v` 값으로 그리세요. PDA 에서는 스캔 시작 직후 엔진 상태가 늦게 바뀝니다.
5. 화면을 떠날 때와 팝업을 닫을 때 `f.Scanner.stopScan()` 을 부르세요. 멈추지 않으면 숨은 입력칸이 포커스를 계속 가져가 다른 입력칸에 글자가 안 들어갑니다.
```javascript
f.Scanner.init({
  categoryName: '<스캔카테고리>', ckey: 'scanValue',
  scanSuffix: '~#A#~', eventName: '<스캔이벤트>',
  usePDAModels: ['<기기 모델명>']   // 기본 허용 목록에 없는 기기일 때
});
```
```javascript
// <스캔이벤트> 스크립트
var sr = _c.<스캔카테고리> || [];
var last = sr.length ? sr[sr.length - 1] : null;
var raw = String((last && last.scanValue) || '').trim();
f.Collection.removeSector('all', '<스캔카테고리>');
```
- 기기 모델명은 아래 스크립트로 확인해 대소문자·하이픈까지 그대로 넣으세요. 제조사 표기와 다를 수 있습니다. 모델이 목록에 없으면 엔진 버전에 따라 "지원하지 않는 기기" 안내가 뜨거나 카메라 스캔으로 바뀝니다. PDA 인데 카메라가 뜨면 모델명부터 확인하세요.
- `navigator.userAgentData` 가 없는 브라우저(예: iOS Safari)에서는 PDA 스캐너 경로를 쓸 수 없습니다.
```javascript
navigator.userAgentData.getHighEntropyValues(['model'])
  .then(function (h) { f.Toast().title(h.model || '모델 정보 없음').show(); });
```

### 8-4. 키보드가 한글 모드면 스캔값이 깨지나요?
결론: 웨지 방식(키보드 모드, `f.Scanner`)은 깨질 수 있습니다. 스캐너가 키 신호를 보내고 기기 키보드 설정이 글자로 바꾸기 때문입니다. 숫자로만 된 값은 사실상 문제가 없습니다.
할 일:
1. 영문이 섞이면 카메라 스캔을 쓰거나, 영문·숫자가 아닌 글자가 섞인 값은 저장하지 말고 다시 스캔하게 하세요.
2. Windows 태블릿에서 베트남어처럼 숫자 줄까지 글자로 바꾸는 키보드 배열을 쓰면 숫자도 깨집니다. 단말 OS 와 키보드 배열을 먼저 확인하세요.
확인: 키보드 언어를 바꿔 가며 같은 라벨을 스캔해 글자 수와 값이 같으면 영향이 없습니다.

## 9. 카메라 스캔

### 9-1. 카메라 스캔이 시작하자마자 꺼지거나 PC 에서 잘 안 읽혀요
결론: 앱에서는 기기 카메라 스캐너가, 브라우저와 디버거에서는 웹캠 스캐너가 열립니다. 웹캠은 정확도가 낮습니다.
할 일: 카메라 권한을 확인하고, 권한이 있는데도 꺼지면 다른 프로그램이 카메라를 쓰는지 본 뒤 PC 를 다시 켜 보세요. 최종 확인은 실제 기기에서 하세요.
- 앱의 카메라 스캔은 한 번에 한 건씩 읽습니다. 다음 건은 결과 이벤트에서 스캔을 다시 부르세요(연속 스캔 지연은 자주 묻는 질문의 바코드 절).
- [확인 필요] 휴대폰에서 `f.Scanner` 로 카메라 연속 스캔을 하는 기능은 통합을 검토 중이라는 답변이 있었습니다. 지금 지원 여부는 담당자에게 확인하세요.

## 10. 모바일 앱 빌드와 출시

### 10-1. APK 파일만 받아 공용 태블릿에 설치할 수 있나요?
결론: 안드로이드 APK 개별 배포는 원칙적으로 제공하지 않습니다. 수정과 개선이 반영되지 않고 지원이 어렵기 때문입니다. iOS 는 App Store 밖 설치 경로가 없습니다.
할 일: 스토어 계정을 쓸 수 없으면 모바일 브라우저로 앱 주소에 접속하고 [홈 화면에 추가]로 아이콘을 만드세요.

### 10-2. 안드로이드 샘플 프로젝트를 빌드하기 전에 점검할 것
1. 프로젝트 폴더를 OneDrive 같은 동기화 폴더 밖에 두세요. 안에서 빌드하면 `Cannot snapshot ... not a regular file` 로 실패합니다. 옮길 때는 잘라내기가 아니라 복사하세요.
2. `applicationId` 를 워크스페이스 [앱] > [SDK 설정]의 패키지 ID 와 철자까지 같게 하고 [라이브에 적용]을 누르세요. 첫 업로드 뒤에는 바꿀 수 없습니다.
3. `google-services.json` 을 내 패키지 이름으로 만든 Firebase 프로젝트 것으로 바꾸세요. 샘플 것이면 "No matching client" 로 실패합니다.
4. `strings.xml` 의 `app_name` 을 채우세요.
5. `flex-lib` 를 최신으로 올리고 Sync 하세요.
확인: 실행하면 첫 화면이 본인인증(휴대폰·이메일 인증) 화면이면 정상입니다. 초대앱은 [고객관리]에 등록된 번호로만 인증번호가 갑니다.

### 10-3. 알림 허용 창에 앱 이름 대신 패키지 이름이 보여요
결론: 매니페스트의 `android:label` 이 비었거나 라이브러리 매니페스트가 덮어쓴 경우입니다.
할 일: Merged Manifest 에서 `application` 의 `android:label` 을 확인하고, 덮어쓰였으면 `tools:replace="android:label"` 을 넣으세요.

### 10-4. 서명 AAB 와 Play Console 테스트에서 막혀요
| 보이는 것 | 조치 |
|---|---|
| "버전 코드는 이미 사용되었습니다" | 한 번 올린 versionCode 는 게시하지 않아도 다시 못 씁니다. 숫자를 올리고 같은 키 파일로 다시 빌드하세요 |
| Create 에서 "Please select the build variants" | release 행을 눌러 App ID 가 보이게 한 뒤 Create 를 누르세요 |

- 키 파일(.jks)과 비밀번호는 업데이트마다 필요합니다. 프로젝트 밖에 따로 보관하세요.
- 개인 개발자 계정은 정식 출시 전 비공개 테스트 요건(테스터 수와 기간)이 있습니다. 시점마다 바뀌니 Play Console 도움말에서 확인하세요.

### 10-5. 최신 기기에서 스토어가 "지원하지 않는 기기"라고 해요
결론: 스토어에 올린 앱의 targetSdk 가 낮거나, Play 스토어 국가 설정이 해외로 되어 있는 경우입니다.
할 일:
1. targetSdk 를 36 으로, `flex-lib` 를 1.0.26 이상으로 올려 다시 빌드하고 올리세요.
2. 기기의 Play 스토어 [설정] > [일반] > [계정 및 기기 환경설정] > [국가 및 프로필]을 확인하고, 같으면 Play 스토어 앱 데이터를 지우세요.

### 10-6. iOS 빌드와 심사
- 개발 기기로 빌드하려면 기기 등록이 필요합니다. Xcode [Window] > [Devices and Simulators]의 Identifier 를 담당자에게 전하세요. 위치·카메라 권한 설명 문구가 모호하면 심사에서 거절됩니다. 어떤 기능에서 왜 쓰는지와 그 기능을 쓸 때만 쓴다는 점을 적으세요(예: "바코드·QR 스캔과 사진 첨부 기능을 쓸 때만 카메라를 사용합니다").

## 11. 오래된 단말과 브라우저

### 11-1. 오래된 안드로이드 단말이나 PDA 에서도 되나요?
결론: [확인 필요] 설치형 앱의 최소 Android 버전(minSdk)은 확인된 값이 없습니다. 샘플 프로젝트의 `build.gradle` 에서 minSdk 를 확인하고, 그보다 낮은 단말은 담당자와 협의하세요.
- PDA 는 Android 13 이상, Chrome 최신 버전을 권장합니다. 오래된 PDA 는 화면 동작이 느릴 수 있습니다. 한 기종에서 스캔부터 화면 반영까지 약 0.7~1.2초였습니다. 현장 기기로 꼭 재 보세요.

### 11-2. 현장 키오스크·PC 에서 흰 화면만 나와요
결론: F12 콘솔 오류가 `SCRIPT1002`, `SCRIPT5009` 처럼 `SCRIPT` 로 시작하면 IE 나 구형 Edge 라서 엔진 스크립트를 읽지 못한 것입니다. 방화벽과는 관계가 없습니다.
할 일:
1. 실행 브라우저를 Chrome 이나 신형 Edge 로 바꾸세요. 전체화면 운영은 `msedge.exe --kiosk <앱 주소> --edge-kiosk-type=fullscreen` 처럼 실행하세요.
2. 바꾼 뒤에도 흰 화면이고 콘솔 첫 줄이 리소스 로드 실패면 사내망이 외부 스크립트 주소를 막는 것입니다. F12 [Network]에서 실패한 주소를 확인해 도메인 허용을 요청하세요.
- 앱에서만 무한 로딩이고 모바일 Chrome 은 정상이면 서버 SSL 인증서의 중간 인증서 체인을 확인하세요. Android 앱은 체인이 빠지면 인증서 검증에 실패합니다.
