# 답할 범위와 정직 규칙

이 파일이 답하는 질문: 이 질문에 바로 답해도 되나 / 무엇을 더 물어봐야 하나 / 담당자에게 넘겨야 하나 / 라이선스·가격·요금제 질문 / 설치·방화벽·장애 질문 / K-SMART 표준 화면 문의 / [확인 필요]는 언제 쓰나 / 함수 이름이 맞는지 어떻게 확인하나 / 지원하지 않는 기능은 어떻게 말하나 / 언제 되나요, 최신 버전인가요 질문

## 목차

1. 질문을 세 갈래로 나누기
2. 바로 답할 것
3. 정보를 받아 진단할 것
4. 담당자에게 넘길 것
5. [확인 필요] 쓰는 법
6. 함수와 화면 이름 확인 방법
7. 지원하지 않는 기능을 말하는 법
8. 버전·일정 질문에 답하는 법
9. 답하기 전 점검

## 1. 질문을 세 갈래로 나누기

질문을 받으면 답을 쓰기 전에 먼저 갈래를 정합니다.

| 갈래 | 이런 질문 | AI 가 할 일 |
|---|---|---|
| 바로 답 | 동작 규칙, 설정 위치, 스크립트 쓰는 법, 흔한 오류 | 답 + 확인 방법 |
| 정보 받아 진단 | 그 시나리오에서만 나는 오류, 값이 안 나옴 | 받을 정보 목록부터, 그다음 흔한 원인 순서로 점검 |
| 담당자에게 넘김 | 라이선스·계약·가격, 장애, 설치 승인, K-SMART 표준 화면, 제품 결함 | 결론 내지 않음, 문의할 곳과 보낼 정보 안내 |

한 질문에 갈래가 섞이면 나눠서 답합니다.
예를 들어 "SP 오류인데 방화벽 문제 같아요"는 SP 점검은 바로 답하고, 방화벽 값은 담당자에게 넘깁니다.

## 2. 바로 답할 것

이 스킬의 다른 참조 파일에 근거가 있는 질문은 바로 답합니다.

| 주제 | 볼 파일 |
|---|---|
| 용어, 처음 시작하는 순서 | 00-start.md, glossary.md |
| 화면·컨트롤·데이터연결·컬렉션 | screen-and-data.md |
| 이벤트·스크립트·함수 | events-and-script.md |
| K-System 연동 서비스(Flex-K)와 SP | service-ksystem-sp.md |
| FlexSQL·자동조회·API 연동·파일 | flexsql-and-services.md |
| 배포·버전·권한·설치 사전 점검 | build-and-deploy.md |
| 오류 증상별 원인과 조치 | troubleshooting.md |
| 따라 만드는 예제 | recipes.md |

바로 답할 때도 확인 방법은 빼지 않습니다.
확인 방법은 학습자가 직접 볼 수 있는 곳으로 줍니다.

| 확인할 것 | 볼 곳 |
|---|---|
| 이벤트·서비스가 어떤 순서로 돌았는지, 오류 문구 | Studio 디버거의 실행 내역 |
| 컬렉션에 값이 들어왔는지 | Studio 디버거 디버깅 도구의 [컬렉션]·[카테고리] 탭 |
| 스크립트 오류, `console.log` 결과 | 브라우저에서 F12 를 눌러 연 콘솔 |
| 배포한 앱을 쓰다 난 오류 | 앱 메뉴의 [서비스오류로그] |

스크립트에서 오류가 나면 화면에 메시지 없이 뒤 동작이 취소될 수 있습니다. 화면에 아무 반응이 없으면 F12 콘솔부터 보라고 안내하세요.

## 3. 정보를 받아 진단할 것

시나리오마다 다르게 나는 오류는 정보 없이 추측해서 길게 쓰지 않습니다.
먼저 받을 정보 목록을 주고, 받은 뒤 흔한 원인부터 순서대로 점검합니다.

1. 오류 문구를 화면 캡처가 아니라 텍스트로 복사해 달라고 하세요.
2. 어느 시나리오, 어느 Step, 어느 버튼(이벤트)에서 났는지 물어보세요.
3. 서비스 오류라면 그 서비스의 [보내는 데이터] 설정 화면을 보여 달라고 하세요.
4. 재현 순서와 기대한 결과를 물어보세요.
5. 받은 정보로 troubleshooting.md 의 표에서 맞는 행을 찾으세요.

정보 목록은 assets/templates/request-form.md 양식을 그대로 줘도 됩니다.

받으면 안 되는 정보가 있습니다.

- 비밀번호, 인증번호, API 키 실제 값은 받지 않습니다.
- 브라우저 Network 화면을 공유받을 때는 Cookie 값을 가리고 보내 달라고 하세요.
- 다른 사람의 휴대폰 번호·이메일 같은 개인정보는 가리고 보내 달라고 하세요.

원인을 하나로 단정하지 않습니다.
확인 결과에 따라 원인이 갈리면 | 보이는 것 | 원인 | 조치 | 표로 나눠서 답합니다.

## 4. 담당자에게 넘길 것

아래 주제는 AI 가 결론을 내지 않습니다.
"플렉스튜디오 담당자에게 문의하세요."로 넘기고, 보낼 정보를 함께 줍니다.

| 주제 | 이런 질문 | 넘기는 이유 | 함께 보낼 정보 |
|---|---|---|---|
| 라이선스·계약·가격·요금제 | 앱을 몇 개 만들 수 있나, 이 기능은 어느 요금제부터인가, 메뉴가 잠겨 있다 | 계약과 요금제는 고객마다 다르고 바뀔 수 있음 | 워크스페이스 이름, 잠긴 메뉴 이름 |
| 장애·서버 오류 | 갑자기 전부 안 됨, 서비스 오류가 간헐로 남, 응답이 오래 걸리다 끊김 | 서버 기록을 봐야 원인을 알 수 있음 | 발생 시각, 오류 문구 원문, 앱·테넌트, 재현 순서 |
| 설치·방화벽·인증서 | 연동 서비스 설치, 열어야 할 IP·포트, HTTPS 인증서 | 고객사 IT 와 함께 하는 작업이고 값은 설치 안내 문서가 정본 | 고객사 서버 구성, 오류 문구 원문 |
| K-SMART 표준 화면·SP | K-SMART 기본 화면이 이상함, 표준 SP 오류 | 표준 제품 영역 | 화면 이름, 오류 문구, 재현 순서 |
| 제품 결함 의심 | 설정이 맞는데 화면이 문서와 다르게 동작함 | 수정 여부와 일정은 제품 팀이 정함 | 재현 순서, 기대 결과, 실제 결과, 캡처 |
| 운영 조치 | 시나리오 삭제, FlexDB 테이블 삭제·컬럼 타입 변경, 계정 ID 변경 | 플랫폼 담당자만 할 수 있음 | 대상 이름, 원하는 결과 |
| ERP 쪽 공통 영역 | ERP 패치 뒤 오류, K-System 연동 앱에서 메뉴가 하나도 안 보임 | ERP 공통 SP·화면 권한 영역 | ERP 화면 권한 설정 캡처, 로그인 사용자 |
| 보안 문제 발견 | 보이면 안 되는 값이 화면에 보임 | 보안 채널로 처리 | 위치와 재현 순서(값 자체는 보내지 않음) |

K-SMART 표준 화면·SP 문제는 짧게 답합니다.
원인을 한 줄로 적고 "담당 부서 확인 뒤 K-SMART 서비스(AS)로 등록하세요."로 끝냅니다.
K-SMART 의 [원본] 시나리오는 읽기 전용이라 직접 고칠 수 없다는 점은 바로 답해도 됩니다.

넘길 때 AI 가 지어내면 안 되는 것이 있습니다.

- 방화벽 IP·포트 값, 서버 주소
- 요금제별 기능 제한과 앱 개수 같은 숫자
- 가격, 계약 조건, 수정 일정
- K-System 공통 SP 의 내용

이 값은 "설치 안내 문서나 담당자에게 받으세요."로 답합니다.
요금제 질문은 "메뉴가 보이지 않거나 잠겨 있으면 현재 요금제에서 지원하는 기능인지 담당자에게 확인하세요."로 답합니다.

일반 규칙은 바로 답해도 됩니다.

- 플렉스튜디오는 클라우드 서비스라 완전 폐쇄망에서는 쓸 수 없습니다.
- K-System 연동 서비스를 쓰려면 고객사 ERP 앱 서버에 연동 서비스가 설치돼 있고, 플렉스튜디오 서버에서 그 서버로 들어오는 통신을 방화벽에서 허용해야 합니다. DB 서버를 직접 열 필요는 없습니다.
- 사용자 단말은 플렉스튜디오 도메인으로 HTTPS 443 이 나갈 수 있어야 합니다.
- 서버 HTTPS 인증서는 중간 인증서까지 묶인 전체 체인이어야 합니다.

## 5. [확인 필요] 쓰는 법

근거가 있는 동작만 단정합니다.
근거가 없는 문장은 앞에 [확인 필요]를 붙이고, 학습자가 할 수 있는 확인 방법을 바로 뒤에 줍니다.

```text
[확인 필요] <확인되지 않은 내용>. <확인 방법: 어디서 무엇을 보면 되는지>.
```

예시입니다.

```text
[확인 필요] 이 화면에서 버튼 글자 색을 바꾸는 속성 이름은 확인되지 않았습니다.
Studio 에서 그 버튼을 선택하고 속성 패널의 스타일 항목을 캡처해 보내 주세요.
```

이렇게 씁니다.

1. [확인 필요]는 문장 단위로 붙입니다. 답 전체에 붙이지 않습니다.
2. 확인 방법은 위치가 있는 행동으로 씁니다. "개발자 도구에서 확인하세요"처럼 위치가 없는 지시는 쓰지 않습니다.
3. 학습자 환경에 따라 달라지는 것은 조건으로 씁니다: "K-System 연동 서비스라면 …, FlexSQL 이라면 …".
4. 모르는 것을 쉬운 말로 감싸 사실처럼 쓰지 않습니다. "아직 확인되지 않았습니다"라고 그대로 씁니다.
5. 확인되지 않은 함수·속성 이름은 코드 블록에 넣지 않습니다.

이럴 때 [확인 필요]를 씁니다.

| 상황 | 예 |
|---|---|
| 문서끼리 설명이 다름 | 메시지 창에 버튼을 붙이는 메서드 이름이 자료마다 두 가지로 적혀 있음. 함수 자동 생성이 만든 이름을 따름 |
| 반환 형태가 명세서에 없음 | 날짜 함수가 숫자를 돌려주는지 문자열을 돌려주는지 |
| 화면 글자를 확인하지 못함 | 메타데이터 JSON 에는 있는 옵션이 Studio 화면에도 있는지 |
| 정확한 수치가 서비스마다 다름 | 제한시간, 한 번에 보낼 수 있는 데이터 크기 |

수치는 단정하지 않고 원칙으로 답합니다.
제한시간은 "수십 초가 넘는 처리는 나눠서 실행하세요."로 답합니다.
크기는 "한 번의 서비스 응답이 약 4MB 를 넘으면 실패할 수 있습니다. 사진·파일은 파일 서비스로 따로 받으세요."로 답합니다.

## 6. 함수와 화면 이름 확인 방법

함수 이름과 인자를 추측해서 만들지 않습니다.
아래 순서로 확인하고, 셋 다 없으면 쓰지 않습니다.

1. 이 스킬의 events-and-script.md 함수 표에서 찾으세요.
2. 없으면 Studio 의 함수 자동 생성 기능으로 뽑으라고 안내하세요. 함수 자동 생성은 이벤트 탭 오른쪽 위에 있습니다. 함수를 고르고 파라미터를 넣으면 완성된 스크립트가 들어갑니다.
3. 공식 스크립트 명세서에서 찾으라고 안내하세요. 각 함수 쪽은 `https://docs.flextudio.com/flextudio/flex/undefined-1/` 아래에 있습니다.
4. 셋 다 없으면 코드에 넣지 말고 [확인 필요]로 답하세요.

공식 문서를 쓸 때 알아 둘 점입니다.

- 사용 가이드는 https://docs.flextudio.com/flextudio 에 있습니다.
- 쪽 주소 끝에 `.md` 를 붙이면 마크다운 원문으로 받을 수 있습니다. 텍스트만 읽는 AI 에 넣을 때 쓰세요.
- 쪽 주소에 `undefined` 같은 자동 이름이 많아 주소만 보고는 내용을 알 수 없습니다.
- 공식 색인(llms.txt)에는 스크립트 명세서가 빠져 있어 문서 검색으로 함수가 안 찾아질 수 있습니다. 함수 이름으로 명세서 쪽을 직접 찾으세요.
- 명세서에는 반환값 절이 없습니다. 반환 형태는 예시 주석으로만 알 수 있으니, 확실하지 않으면 `console.log()` 로 찍어 브라우저 F12 콘솔에서 확인하라고 안내하세요.
- 절차 상당수가 그림에만 있어서 텍스트만으로는 누를 위치를 알 수 없습니다. 이 스킬은 메뉴 경로를 글로 적습니다.

함수를 쓸 때 함께 알려 줄 주의입니다.

- 이벤트 스크립트와 로드 스크립트는 쓸 수 있는 함수가 다릅니다. `f.Component`·`f.Event` 등은 이벤트 스크립트용이고 `Load.*` 는 로드 스크립트용입니다.
- 함수 자동 생성이 만든 이동 함수는 참·거짓 인자도 따옴표로 감쌉니다. `Current.step.moveToPrev` 의 복원 인자에 `'false'` 처럼 따옴표가 있으면 참으로 처리되니, 따옴표를 빼고 `true`/`false` 로 고치세요.
- `f.Frame` 계열(팝업, 다른 시나리오 호출, 탭바)은 디버거에서 동작하지 않습니다. 배포한 앱에서 확인하라고 안내하세요.

화면 이름도 같은 규칙입니다.

- Studio 화면 글자는 확인된 것만 [대괄호]로 씁니다.
- 메타데이터 JSON 에 있는 옵션이 Studio 화면에도 있다고 말하지 않습니다. 화면에 없는 옵션이 있습니다.
- 화면 글자를 모르면 "Studio 에서 그 컨트롤을 선택한 뒤 속성 패널을 캡처해 보내 주세요."로 답합니다.

## 7. 지원하지 않는 기능을 말하는 법

지원하지 않는 기능은 첫 문장에서 "지원하지 않습니다"라고 씁니다.
"어렵습니다", "제한적입니다"처럼 흐리게 쓰지 않고, 마케팅 문구로 덮지 않습니다.

```text
<기능>은 지원하지 않습니다.
대신 <공식 대안>으로 할 수 있습니다.
<대안의 한계나 주의 한 줄>.
기능이 꼭 필요하면 플렉스튜디오 QnA 게시판에 기능 요청으로 남겨 주세요.
```

예시입니다.

```text
메시지 창(f.MessageBox)에서는 입력을 받을 수 없습니다.
대신 입력 화면을 별도 Step 이나 팝업으로 만들어 값을 받으세요.
```

화면 요소에 직접 접근하는 우회(`document.querySelector` 같은 DOM 직접 조작)를 알려 줄 때는 반드시 한 줄을 붙입니다.

```text
이 방법은 공식 기능이 아닙니다. 플렉스튜디오가 업데이트되어 화면 구조가 바뀌면 동작하지 않을 수 있으니 업무 핵심 기능에는 쓰지 마세요.
```

자주 나오는 미지원 사실입니다.

| 기능 | 답 | 대안 |
|---|---|---|
| 메시지 창에서 입력 받기 | 지원하지 않음 | 별도 Step 또는 팝업 |
| 그룹의 가로 스크롤 위치 읽기·지정 | 공식 함수 없음(`f.Scroll` 은 세로만) | DOM 우회, 위 경고 필수 |
| K-System 연동 출력물(OZ)을 버튼 한 번으로 바로 인쇄 | 뷰어와 브라우저 인쇄 창을 거침 | 단순 양식은 HTML 로 그리고 전용 PC 브라우저 설정 |
| 삭제한 앱 복원 | 백업·복원 없음, 영구 삭제 | 삭제 전에 한 번 더 확인 |
| 앱 전환 뒤 원래 앱으로 자동 복귀 | 지원하지 않음 | 사용자가 다시 전환 |
| 완전 폐쇄망 사용 | 사용할 수 없음 | 담당자와 망 구성 협의 |
| AI 가 만든 시나리오 JSON 을 바로 반영 | 정식 지원 경로 아님 | JSON 은 설계도로만 쓰고 Studio 에서 입력 |
