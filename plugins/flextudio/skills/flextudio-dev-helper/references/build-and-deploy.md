## 1. 구조 한 장: 워크스페이스, 앱, 테넌트, 사용자

워크스페이스는 개발 조직 단위이고, 앱은 배포 단위이며, 테넌트는 앱을 쓰는 회사 한 곳입니다.

```text
워크스페이스(개발 조직)
 ├─ [개발]: 시나리오, 권한키          ← 앱과 독립
 ├─ [데이터]: API 연동 모듈, FlexSQL 서비스
 ├─ 앱 A ── [시나리오 관리](배포된 버전 선택) ── 레이아웃(시작페이지, 메뉴, 탭바)
 │         └─ 고객(테넌트) 1..n ── 사용자, 시스템 정보(ERP와 DB 연결)
 └─ 앱팩: 시나리오 묶음 배포
```

| 용어 | 뜻 | 기억할 점 |
|---|---|---|
| 워크스페이스 | 개발 조직 단위 | 홈페이지 [무료로 시작하기]에서 주소를 정해 만듭니다 |
| 앱 | 사용자에게 배포되는 단위 | 앱 ID 는 웹 접속 URL 에 쓰입니다 |
| 테넌트(고객) | 같은 앱을 쓰는 회사 한 곳 | 사용자 명단과 ERP 연결 정보를 테넌트마다 따로 갖습니다 |

- [개발]-[시나리오 개발]에서 만든 시나리오는 어떤 앱에도 속하지 않습니다.
- [앱]-[시나리오 관리]에서 만든 시나리오는 그 앱에 바로 포함됩니다.
- 시나리오를 복제해 앱에 추가하면 안의 서브시나리오도 함께 들어갑니다.
- 테넌트 ID 와 테넌트번호는 고객을 만들 때 자동으로 정해지고 고칠 수 없습니다.
- ERP 와 DB 연결 정보는 앱이 아니라 테넌트의 [회사 정보]-[사용할 System], [시스템 정보]에 넣습니다.
- 그래서 같은 앱이라도 접속한 테넌트에 따라 연결되는 ERP 가 달라집니다.

## 2. 처음 만드는 순서

1. 홈페이지 [무료로 시작하기]에서 워크스페이스를 만드세요.
2. 처음 뜨는 앱 생성 창에서 앱을 만드세요.
3. 기업 업무앱이면 초대기반앱으로 만드세요(5절 표 참고).
4. [고객관리]에서 고객(테넌트)을 만드세요.
5. ERP 나 외부 DB 를 쓰면 [고객관리]에서 그 고객의 설정 페이지를 열고 [시스템 정보]에 연결 정보를 넣으세요.
6. Studio 에서 시나리오를 만들고 저장한 뒤 [배포]를 누르세요.
7. 앱의 [시나리오 관리]-[시나리오 배포]에서 시나리오와 버전을 고르고 [라이브에 적용]을 누르세요.
8. 레이아웃 관리에서 시작페이지와 메뉴를 정하세요.
9. 같은 고객 설정 페이지의 [사용자관리]에서 사용자를 추가하고 앱 사용권한을 주세요.
10. [앱 초대 문자 발송]으로 사용자를 초대하세요.

확인 방법: 사용자가 받은 6자리 인증번호로 로그인해 시작페이지가 보이면 성공입니다.

## 3. 배포와 버전: 저장한 내용이 사용자에게 보이기까지

Studio 에서 저장만 하면 사용자에게 보이지 않습니다.
대상마다 반영 버튼이 따로 있습니다.

| 대상 | 반영하려면 | 주의 |
|---|---|---|
| 시나리오 | Studio 저장 후 [배포]를 누릅니다(시나리오 버전 발행) | 한 번은 배포해야 앱에서 고를 수 있습니다 |
| 앱 | [시나리오 배포]에서 버전을 고르고 [라이브에 적용]을 누릅니다 | 문서에 따라 [앱에서 사용하기]로 적혀 있습니다. 누르는 즉시 실사용자에게 반영됩니다 |
| FlexSQL 서비스 | [새 버전 발행] 또는 [현재버전으로 변경내역 반영]을 누릅니다 | 시나리오 쪽 SQL Script Version 이 0 이면 최신 버전이 실행됩니다 |
| API 연동 모듈 | 모듈 화면 아래 버튼 영역에서 [배포]를 누릅니다 | [확인 필요] 배포 전 Test-API 가 어느 버전을 쓰는지 |
| 권한키 | 권한키를 쓴 시나리오를 배포하고 라이브에 적용합니다 | 앱에 배포되지 않은 권한키는 사용자에게 줄 수 없습니다 |

### "고쳤는데 앱에 안 나와요" 확인 순서

1. Studio 에서 시나리오 [배포]를 했는지 보세요.
2. 앱 [시나리오 배포]에서 새 버전을 고르고 [라이브에 적용]을 했는지 보세요.
3. FlexSQL 서비스를 새 버전으로 발행했는지, API 연동 모듈을 [배포]했는지 보세요.
4. 링크앱팩을 쓰는 앱이면 [앱팩] 메뉴에서 배포했는지 보세요.
5. 앱에서 메뉴로 다시 들어가거나 홈 버튼을 누르세요. 그래도 안 보이면 브라우저를 새로고침하세요.

### 배포 전에 지킬 것

- [라이브에 적용]은 실사용자에게 바로 반영되므로 먼저 디버거로 확인하세요.
- 팝업, 다른 시나리오 호출, 탭바 같은 f.Frame 계열 동작은 디버거에서 동작하지 않습니다. 배포된 앱에서 확인하세요.
- 앱 삭제는 영구 삭제이고, 백업과 복원은 지원하지 않습니다.
- [확인 필요] 릴리즈 노트에 앱 수정 승인, 앱 복사 생성 기능이 있습니다. 화면 위치와 범위는 docs.flextudio.com 릴리즈 노트로 확인하세요.

## 4. 앱팩과 패키지설치

- 앱팩은 여러 시나리오를 묶어 관리하고 배포하는 단위입니다.
- 앱에 링크앱팩을 쓰면 앱의 [시나리오 배포] 메뉴가 꺼지고 [앱팩] 메뉴에서 배포합니다.
- 앱팩 메뉴는 예전 워크스페이스에만 있고, 신규 워크스페이스는 앱 설정에서 통합 관리합니다.
- 엔진 버전은 시나리오가 아니라 팩 단위로 정해집니다. 같은 시나리오가 워크스페이스마다 다르게 동작하면 엔진 버전부터 의심하세요.
- 패키지설치는 플렉스튜디오가 제공하는 묶음(시나리오, DB 테이블과 SP, FlexSQL, 권한키)을 워크스페이스에 내려받는 기능입니다.
- 이미 설치한 패키지는 다시 설치할 수 없습니다.
- 패키지설치는 직접 만든 앱을 옮기는 기능이 아닙니다. [확인 필요] 직접 만든 앱을 다른 워크스페이스로 옮기는 정식 방법은 담당자에게 확인하세요.

## 5. 사용자와 권한

### 공개앱과 초대기반앱

| 기능 | 공개앱 | 초대기반앱 |
|---|---|---|
| 사용자 직접 가입, SNS 가입, 미가입자 접근 | 됩니다 | 안 됩니다 |
| 관리자 등록(엑셀 일괄), 초대 문자 발송 | 안 됩니다 | 됩니다 |
| 문자나 메일 인증 로그인, 외부 솔루션 사용자 연동 | 안 됩니다 | 됩니다 |
| 과금 기준 | 접속 횟수 | 사용자 수 |

기업 내부 업무앱은 초대기반앱이 맞습니다.
외부 DB 연동도 초대기반앱에서만 지원합니다.

### 사용자 등록과 로그인

- 고객 설정 페이지의 메뉴 이름은 초대기반앱이면 [사용자관리], 공개앱이면 [SNS 유저관리]입니다.
- 신규 사용자는 이메일과 휴대폰 번호 중 하나가 꼭 있어야 합니다.
- 휴대폰 번호는 하이픈 없이 01000000000 형식으로 넣으세요.
- 로그인은 휴대폰 번호나 이메일로 받은 6자리 인증번호로 합니다. 휴대폰 우선인 인증 기본값은 바꿀 수 없습니다.
- 워크스페이스 개발자로 등록해도 앱 권한은 생기지 않습니다. 그 앱 테넌트의 사용자로 추가하세요.
- 앱 사용권한을 주면 "사용가능"이 되고, 초대 문자로 사용자가 접속해야 "사용중"이 됩니다.
- 세션 유지일은 테넌트 [회사 정보]에서 일 단위로 정합니다.
- 고객관리의 사용자와 권한 데이터는 플랫폼 서버가 관리하므로 SQL 로 조회할 수 없습니다.
- K-System 사용자 동기화를 쓰는 테넌트에는 사용자 추가, 수정, 삭제 버튼이 없습니다. ERP 에서 고치고 동기화하세요.

### 디버그 권한

디버그 권한은 특정 사용자에게만 나는 오류를 그 사용자 정보로 재현하는 기능입니다.

1. [사용자관리]에서 그 사용자에게 디버그 권한을 주세요.
2. 디버거 [앱 접속 정보]에서 앱, 테넌트, 그 사용자를 고르세요.
3. 같은 순서로 실행해 오류를 재현하세요.

실사용 중 난 오류 기록은 앱의 [서비스오류로그]에서 봅니다.

### 권한키

권한키는 사용자마다 다른 화면을 보이게 하는 키입니다.

| 규칙 | 내용 |
|---|---|
| 이름 | 영문, 숫자, 밑줄만 씁니다. 중복은 안 됩니다 |
| 수정과 삭제 | 라이브, 이전 버전, 편집 중 시나리오 가운데 한 곳이라도 쓰면 안 됩니다 |
| 부여 대상 | 사용자 또는 그룹. 그룹에 주면 그룹 안 전원에게 적용됩니다 |
| 겹칠 때 | 그룹 권한키와 사용자 권한키는 우선순위 없이 둘 다 적용됩니다 |

- 새 권한키는 시나리오에서 쓰고 라이브에 적용해야 권한관리 메뉴에 보입니다.
- 탭 하나에만 거는 권한키 설정은 없습니다. 탭 클릭 이벤트 스크립트에서 `f.Auth.check` 로 확인하세요.

```javascript
// 탭 클릭 이벤트 스크립트: 권한키가 없으면 안내하고 이 스크립트를 끝냅니다
if (!f.Auth.check('<권한키>')) {
  f.MessageBox('Alert').setTitle('<안내 문구>').show();
  return;
}
```

이 코드가 하는 일: 로그인한 사용자에게 `<권한키>`가 있는지 봅니다.
없으면 안내 창을 띄우고 아래 코드를 실행하지 않습니다.
f.Auth.check 는 권한이 있으면 true, 없으면 false 를 돌려줍니다. 이벤트의 다음 액션까지 막는 방법은 events-and-script.md 의 흐름 제어를 보세요.

- 여러 앱 권한을 한 번에 줄 때는 그룹별 권한관리의 [전체] 탭에서 저장하세요.

## 6. 레이아웃, 앱 전환, 링크

- 레이아웃 관리에서 상단헤더, 시작페이지, 알림 페이지, 하단탭바, 우측 메뉴, PC-Web(Beta)를 설정합니다.
- 시작페이지는 시나리오, 메뉴리스트, URL 중 하나이고, 메뉴 UI 는 박스형과 트리형이 있습니다.
- [개발]에서 만든 시나리오는 앱에 추가해야 메뉴와 시작페이지에서 고를 수 있습니다.
- 앱 전환은 한 테넌트가 여러 앱을 다시 로그인하지 않고 오가는 기능이고, 초대기반앱에서만 됩니다.
- 전환해 들어올 앱에서 "다른 앱에서 이 앱으로 전환 허용"을 켜고 레이아웃 관리에서 사용 설정을 하세요.
- 전환 목록에는 사용 권한이 있는 앱만 보이고, 원래 앱으로 자동 복귀하는 기능은 없습니다.
- 링크관리에서 특정 시나리오로 바로 여는 짧은 URL 을 만들고 데이터를 실어 보낼 수 있습니다.
- K-System 연동 앱에서 메뉴가 하나도 안 보이면 ERP 쪽 화면 권한 설정부터 확인하세요.

## 7. 요금제별 제한

요금제 숫자를 단정하지 마세요.
공식 가이드(2025-10 기준) 안에서도 표기가 서로 다릅니다.

| 기능 | 가이드 표기 | 상태 |
|---|---|---|
| 메뉴별 권한, SDK | Start 이상 | 가이드 표기 |
| FlexSQL | Start 이상과 Business 이상이 함께 적혀 있음 | [확인 필요] |
| FlexDB, 고객관리, 외부 DB, K-System 연동, Test-API | Business 이상 | [확인 필요] 최신 기준 |
| 앱팩, 링크앱팩 | Enterprise 이상 | 가이드 표기 |

메뉴가 없거나 잠겨 있으면 현재 요금제에서 지원하는 기능인지, 앱 개수와 사용자 수 한도는 얼마인지 플렉스튜디오 담당자에게 확인하세요.

## 8. K-System 연동 서비스 설치 사전 점검과 접속 문제

플렉스튜디오는 클라우드(SaaS) 서비스라 완전 폐쇄망에서는 쓸 수 없습니다.
화면은 접속할 때마다 클라우드에서 받아 실행하고, 별도 개발 서버 없이 운영 환경 한 벌로 씁니다.

- 데이터 연동: 플렉스튜디오 서버 → 인바운드 → 고객사 ERP 앱 서버(IIS, 연동 서비스). DB 서버는 직접 열지 않습니다.
- 화면 구동: 사용자 단말 → 아웃바운드 HTTPS 443 → 플렉스튜디오 도메인

### 고객사가 준비할 것

| 준비물 | 내용 | 담당 |
|---|---|---|
| ERP 앱 서버 | 연동 서비스를 설치할 IIS 서버 | 고객사 서버 담당자 |
| 방화벽 인바운드 허용 | 플렉스튜디오 서버에서 ERP 앱 서버 포트로 들어오는 통신 | 고객사 방화벽 담당자 |
| 단말 아웃바운드 | 플렉스튜디오 도메인으로 HTTPS 443(IP 가 아니라 도메인 기준) | 고객사 네트워크 담당자 |
| HTTPS 인증서 | 루트와 중간 인증서까지 묶인 전체 체인 | 고객사 서버 담당자 |
| DB 설정 | [확인 필요] DB 호환성 수준 요구값은 설치 안내 문서로 확인 | 고객사 DB 담당자 |
| 서버 시계 | 표준시와 맞춰 둡니다 | 고객사 서버 담당자 |

- 허용할 출발지 IP 와 포트는 바뀔 수 있습니다. 플렉스튜디오 담당자에게 최신 값을 받으세요.
- 설치가 끝나면 테넌트 [시스템 정보]에 연동 주소와 DSN 같은 연결 정보를 넣으세요. 넣을 값은 설치 안내에 따르세요.
- 고객사 서버를 HTTPS 로 바꾸면 테넌트 [시스템 정보]의 연동 주소와 포트도 새 값으로 바꾸세요.
- [확인 필요] 연동 서비스 정기 패치는 매주 목요일 저녁 약 1시간이고 그동안 모바일 앱이 멈춥니다. 정확한 시각은 공지로 확인하세요.
- 한 번의 서비스 응답이 약 4MB 를 넘으면 실패할 수 있습니다. 사진과 파일은 파일 서비스로 따로 주고받으세요.

### 접속 문제 대조표

| 보이는 것 | 원인 | 조치 |
|---|---|---|
| `Invalid System Information` | 테넌트에 K-System 시스템 정보가 없거나 주소, 업무 DSN, 운영 DSN 가운데 하나가 비어 있음 | 콘솔 테넌트 [시스템 정보]를 채우세요 |
| `ETIMEDOUT` 같은 시간 초과 | 고객사 서버가 제한시간 안에 응답하지 않음 | SP 실행 시간과 서버 상태를 보세요 |
| `ECONNREFUSED`, `ENOTFOUND`, `ECONNRESET`, 인증서 오류 | 고객사 서버에 닿지 못함 | 방화벽, 주소, 포트, 인증서를 고객사 IT 와 확인하세요 |
| `unable to verify the first certificate` 류 | 인증서에 중간 인증서가 빠짐 | 전체 체인 인증서로 다시 설치하세요 |
| "서버가 정상 응답 대신 다른 내용을 반환했습니다 (text/html…)" | 방화벽 차단 페이지나 IIS 오류 페이지가 돌아옴 | 메시지 뒤 페이지 글자를 고객사 IT 에 전달하세요 |
| K-SMART 로그인이 갑자기 안 됨 | ERP 앱 서버 시계가 표준시와 10초 넘게 어긋남 | 서버 시계를 맞추세요 |
| 흰 화면, 콘솔에 `SCRIPT1002` | 구형 브라우저(IE, 구형 Edge) | 최신 Edge 나 Chrome 을 쓰세요. IE 모드는 해결책이 아닙니다 |
| 브라우저를 바꿔도 흰 화면, `ERR_` 오류 연쇄 | 사내망이 외부 스크립트 도메인을 막음 | F12 Network 탭에서 실패한 도메인을 찾아 도메인 허용을 요청하세요 |

위 메시지가 보이면 SP 를 고치기 전에 연결부터 확인하세요.

## 9. 모바일 앱과 PDA

- 웹앱은 [라이브에 적용]하면 바로 쓸 수 있습니다.
- 스토어 앱으로 내려면 SDK 설정(iOS, Android)과 앱 출시 절차를 따르세요.
- 스토어 심사와 푸시 알림 준비는 플렉스튜디오 담당자와 함께 준비하세요.

| 상황 | 쓰는 방법 |
|---|---|
| 산업용 PDA 스캐너(키보드 모드) | 스캐너가 포커스된 입력 컨트롤에 값을 직접 넣습니다. 화면 코드가 없어도 값이 들어옵니다 |
| PDA 에서 플랫폼 스캔 기능 | `f.Scanner.init`, `f.Scanner.startScan`, `f.Scanner.stopScan` |
| 모바일 앱 카메라 스캔 | `f.Native.getBarcode`. 결과는 `f.Barcode.value` 에서 읽습니다 |

- 키보드 모드 스캐너는 "입력 완료 감지 → 자동 조회"만 만들면 됩니다.
- 입력 이벤트에 조회를 바로 걸면 글자마다 서비스가 나갑니다. 입력이 멈춘 뒤 한 번만 조회하도록 지연을 두세요.
- 키보드 모드는 키보드 언어 설정의 영향을 받을 수 있습니다. 바코드에 문자가 섞이면 실기로 먼저 시험하세요.
- `f.Scanner` 를 쓰려면 스캐너 앱의 접미 문자열을 init 옵션 `scanSuffix` 와 같게 맞추세요. Enter 나 Tab 키 방식 종료는 감지하지 못합니다.
- 기본 허용 기기가 아니면 init 옵션 `usePDAModels` 에 기기 모델명을 대소문자와 하이픈까지 정확히 넣으세요.
- 스캔 시작을 눌러도 화면에 변화가 없는 것은 정상입니다. 스캔 중 표시를 따로 만드세요.
- 화면을 떠날 때와 팝업을 닫을 때 `f.Scanner.stopScan()` 을 부르세요.
- PDA 는 Android 13 이상, Chrome 최신 버전을 권장합니다.
- 아이폰도 쓸 수 있지만 바코드 인식 방식이 달라 기기별로 나눠 처리해야 합니다.

연속 스캔 화면의 전체 순서는 recipes.md 의 바코드 스캔 예제를 보세요.

## 10. 출력과 인쇄

엔진에는 인쇄 전용 기능이 없고 브라우저 인쇄 `window.print()` 를 씁니다.

| 출력 방식 | 되는 것 | 한계 |
|---|---|---|
| K-System OZ 출력물 | ERP 가 만든 OZ HTML5 뷰어를 띄웁니다 | 뷰어 없이 버튼 한 번에 바로 출력은 OZ 설정으로 할 수 없습니다. 뷰어 [인쇄] 뒤 브라우저 인쇄 창을 거칩니다 |
| 화면 HTML + `window.print()` (웹앱) | 라벨처럼 단순한 양식을 그려 인쇄합니다 | 브라우저 인쇄 창이 뜹니다 |
| 전용 PC 의 Chrome 무대화상자 인쇄 | 버튼 한 번에 기본 프린터로 바로 나갑니다 | 그 PC 의 Chrome 을 `--kiosk-printing` 옵션으로 실행해야 합니다. 전용 PC 나 키오스크에 맞습니다 |
| 설치형 모바일 앱 | `window.print()` 를 조용히 무시합니다 | 이벤트 스크립트에서 `f.Browser.open(url)` 로 브라우저에 넘겨 인쇄하세요. 별도 세션이라 로그인이 다시 뜰 수 있습니다 |

- 모바일 브라우저 인쇄는 iOS AirPrint 나 Android Mopria 가 필요하고, 단말과 프린터가 다른 망이면 프린터가 보이지 않습니다.
- 인쇄 영역이 잘리면 크기 고정 그룹 안에 있기 때문입니다. 인쇄할 내용을 Embed 컨트롤에 따로 두세요.
- OZ 출력물 오류는 F12 Network 의 응답 본문을 캡처해 담당 부서에 전달하세요.

## 11. 한 테넌트에서 여러 앱 쓰기

한 테넌트에서 여러 앱을 쓸 수 있고, 아래 항목은 테넌트 단위로 묶입니다.

| 항목 | 한 테넌트에서 |
|---|---|
| K-System 연결 | 테넌트당 1개입니다. 모든 앱이 같은 ERP DB 를 봅니다 |
| 사용자 | 한 명이 앱 전환으로 여러 앱을 오갈 수 있습니다(초대기반앱) |
| 앱 사용권한 | 앱마다 따로 줍니다 |
| 여러 앱 권한 저장 | 그룹별 권한관리 [전체] 탭에서 한 번에 저장합니다 |

- 앱마다 다른 ERP 를 봐야 하면 테넌트를 나누세요.
- [확인 필요] 앱 단위로 연결을 고정하는 설정이 지금 화면에 있는지는 플렉스튜디오 담당자에게 확인하세요.
- 같은 DB 에 여러 앱의 테이블과 SP 를 두면 이름이 겹칠 수 있습니다. 시작 전에 앱별 접두어 규칙을 정하세요.

## 12. 담당자에게 넘길 것과 문의 양식

라이선스와 요금제, 장애, 연동 서비스 설치 승인과 방화벽 값, ERP 패치와 K-SMART 표준 화면, 데이터 삭제 같은 운영 조치는 이 도우미가 결론을 내지 않습니다.
플렉스튜디오 담당자에게 아래 양식을 채워 문의하세요.
비밀번호와 개인정보는 넣지 마세요.

```text
워크스페이스명:
시나리오명(또는 ID):
Step:
디버거 접속 정보(앱 / 테넌트 / 사용자):
재현 순서:
오류 메시지 원문 또는 RequestID:
브라우저 / 기기 / OS:
```

F12 화면을 공유할 때 Request Headers 의 Cookie 영역은 가리세요.
살아 있는 세션 정보가 들어 있습니다.
