이 파일이 답하는 질문: 섹터 상태를 어떻게 읽나요 / 하위 시나리오에서 데이터가 비거나 부모 데이터가 사라져요 / 저장 뒤 재조회가 가끔 끊겨요 / 자동 조회가 멈춰요 / f.Setting.User.set 을 여러 번 불러요 / Scroll.offset 이 계속 0 이에요 / 카드를 누르면 이미지 확대와 이동이 같이 돼요 / 코드도움 기본값과 Param string / Etc 탭 키가 안 지워져요 / K-System SP 를 넘기기 전에 더 볼 것

목차
1. 데이터·섹터·서브시나리오
2. 이벤트·서비스 호출·진단

쓰는 법
- 실제 개발에서 확인된 함정 가운데 다른 설명에 없는 것만 모았습니다. set 으로 값 바꾸기, Q조회 _SUID, [덮어쓰기] 같은 기본 규칙은 화면과 데이터 설명, K-System SP 설명, 문제 해결 표를 먼저 보세요.
- 화면 구조(DOM)를 직접 건드리는 방법은 비공식이라 업데이트 때 깨질 수 있습니다. 답할 때 이 경고를 함께 전하세요.

## 1. 데이터·섹터·서브시나리오

### 1-1. 섹터가 지금 신규인지 수정인지 읽고 싶습니다
결론: `섹터.status` 를 읽으면 A, U, D 중 한 글자나 빈 글자가 옵니다. `getStatus()` 라는 함수는 없습니다.
할 일:
1. 상태를 넣을 때는 단어로 쓰세요: `섹터.setStatus('added')`.
2. 상태를 읽을 때는 글자로 비교하세요: `섹터.status === 'A'`.
3. 참·거짓이 필요하면 `섹터.isAdded`, `섹터.isUpdated`, `섹터.isDeleted` 를 쓰세요.
4. 반드시 섹터에서 읽으세요. 카테고리나 컬렉션의 status 는 이름만 같고 다른 값을 돌려줍니다.
원인: 삭제 표시가 있으면 D, 다음으로 추가면 A, 수정이면 U 를 돌려줍니다. added 인 행을 set 으로 고쳐도 A 로 남습니다.
확인: 디버거 콘솔 탭에 `_c.activeSector.status` 를 입력해 한 글자가 나오는지 보세요.

### 1-2. 사용자 이름이 글자가 아니라 객체로 들어옵니다
결론: `_base.User.fBaseUserName` 은 환경에 따라 글자일 때도 있고 언어별 이름을 담은 객체일 때도 있습니다. 두 경우를 모두 처리하세요.
```javascript
var n = _base.User.fBaseUserName;
var userName = (n && n.default) ? n.default : (n || '');
```
확인: 저장한 값이나 라벨에 사람 이름이 글자로 보이는지 보세요.

### 1-3. 같은 키 이름을 여러 카테고리에 두어도 되나요
결론: 됩니다. 값은 카테고리마다 따로 있습니다. 다만 `f.Collection.filter` 는 카테고리를 가리지 않아서, 스캔값이나 번호로 한 행을 찾을 때 다른 카테고리의 행이 잡힐 수 있습니다.
할 일:
1. 찾기용 키는 그 카테고리에만 있는 이름으로 따로 두세요. 예: 마스터에만 `<마스터전용키>`.
2. 또는 `(_c.<카테고리> || []).filter(function (s) { return s.<키> === <값>; })` 처럼 카테고리 배열에서 찾으세요.
확인: 찾은 섹터의 다른 키 값이 기대한 카테고리의 값인지 보세요.

### 1-4. 화면에 안 보이는 Seq 값을 다음 Step 으로 넘기고 싶습니다
결론: Seq 같은 숨김 값은 시트 컬럼에 연결하지 말고 카테고리 키에만 두세요. 행을 고르면 그 섹터에 값이 함께 있어 다음 Step 에서 읽을 수 있습니다.
할 일:
1. 조회 SP 가 `<숨김키>` 컬럼을 같은 이름으로 돌려주게 하세요.
2. 카테고리 키 목록에 `<숨김키>` 를 두고, 시트에는 보일 컬럼만 연결하세요.
확인: 행을 고른 뒤 디버거 콘솔 탭에서 `_c.<카테고리>.activeSector.<숨김키>` 값을 보세요.

### 1-5. 하위 시나리오에 목록을 넘겼는데 대상 카테고리가 비어서 도착합니다
결론: 넘기기 전에 `f.Collection.addSector` 로 다른 카테고리에 옮겨 담으면 섹터가 복제됩니다. 선택 행은 원래 카테고리를 가리키고 대상 카테고리에는 복제본만 남아, 상태 필터 active 로는 원래 행만 넘어갑니다.
할 일:
1. 카테고리를 바꿀 때는 `f.Collection.moveCategory('<원본>', 'all', '<대상>')` 로 옮기세요. 같은 섹터가 그대로 이동합니다.
2. 조회로 불러온 목록을 넘길 때는 상태 필터를 전체로 두세요.
확인: 하위 Step 이 열린 직후 디버거 컬렉션 탭에서 대상 카테고리의 행 수를 보세요.

### 1-6. 하위 시나리오 결과를 받으면서 부모의 다른 데이터도 지키고 싶습니다
결론: [서브시나리오의 콜렉션으로 대체하기]는 병합이 아니라 부모 컬렉션을 통째로 바꿉니다. 부모 데이터를 지키려면 내려갈 때 모두 싣고 올라올 때 모두 되돌리세요.
할 일:
1. 부모의 하위 시나리오 설정에서 [컬렉션 복사]를 켜고 상태 필터를 전체로 두세요.
2. 하위에서 작업하세요.
3. 돌아가기 직전에 하위에서만 쓴 조회용 카테고리 행을 `f.Collection.removeSector('all', '<하위조회카테고리>')` 로 지우세요.
4. [서브시나리오의 콜렉션으로 대체하기]를 켜고 상태 필터를 전체로 두세요.
확인: 부모로 돌아온 뒤 디버거 컬렉션 탭에서 부모 카테고리와 하위 결과가 함께 있는지 보세요.
대안: 부모 데이터를 하위에 싣기 싫으면 하위에서 DB 에 저장하고 부모의 [뒤로가기로 돌아올 때] 이벤트에서 다시 조회하세요.

## 2. 이벤트·서비스 호출·진단

### 2-1. 저장과 재조회를 한 서비스로 묶을 수 없는데 가끔 read ECONNRESET 이 납니다
결론: 서비스가 끝나자마자 다음 서비스가 나가면 연결이 끊길 수 있습니다. 묶을 수 없으면 재조회를 1초 늦게 부르세요. 증상을 피하는 방법이고 근본 해결은 아닙니다.
할 일:
1. 지연 전용 이벤트를 하나 만들고 스크립트 액션에 아래 코드를 넣으세요.
```javascript
setTimeout(function () {
  f.Event('<조회이벤트명>').runNext();
}, 1000);
```
2. 저장 뒤 조회 이벤트를 바로 부르던 액션의 대상을 이 지연 이벤트로 바꾸세요.
3. 조회 이벤트 본체에는 지연을 넣지 마세요. 첫 조회까지 느려집니다.
4. 실패를 잡아 다시 부르는 방식은 쓰지 마세요. 다시 부르는 호출도 같은 조건을 만들어 또 실패합니다.
원인: 실측에서 0.5초 지연은 줄어들기만 했고 1초 지연에서는 나지 않았습니다. `f.Content('<fid>').reload()` 로 조회가 걸린 직후에 이어지는 조회도 같은 조건입니다.
확인: 디버거 실행 내역에서 저장의 [Service result] 시각과 조회의 [Call Service] 시각이 1초쯤 벌어졌는지 보세요.

### 2-2. 연결 오류를 볼 때 걸린 시간과 호출 간격을 어디서 읽나요
결론: 걸린 시간은 F12 Network 의 Timing 탭 Waiting 값으로 보세요. 두 호출이 붙어 나갔는지는 디버거의 [Call Service]와 [Service result] 시각으로 보세요. 응답 헤더의 Date 는 초 단위라 걸린 시간 계산에 쓰면 틀립니다.
할 일:
1. 실패한 호출과 성공한 호출의 Waiting 값을 나란히 놓으세요.
2. 아래 표로 판단하세요.

| 실패 호출의 Waiting | 뜻 |
|---|---|
| 성공보다 훨씬 짧고 일정함 | 연결 단계에서 바로 끊겼습니다 |
| 들쭉날쭉함 | 처리 도중 끊겼습니다 |
| 제한 시간 근처 | 시간 초과입니다 |

3. 앞 서비스의 [Service result] 시각과 뒤 서비스의 [Call Service] 시각이 붙어 있으면 연속 호출입니다. 2-1 을 보세요.
확인: 판단 근거로 Waiting 값 두 개와 디버거 시각 두 개를 함께 적어 두세요.

### 2-3. Chart.js 같은 라이브러리를 [외부파일설정]에 넣었는데 전역 이름이 없습니다
결론: 전역 이름을 만드는 UMD 빌드 파일을 넣어야 스크립트에서 `Chart` 같은 이름을 쓸 수 있습니다.
할 일:
1. 라이브러리 배포본 가운데 UMD 빌드 주소를 넣으세요. 예: Chart.js 는 `chart.umd.min.js`.
2. 그리는 코드는 Loaded 이후 이벤트의 스크립트 액션에 두세요.
3. 다시 그릴 때 쓸 차트 객체는 `_v` 에 보관하세요. 스크립트 액션은 실행할 때마다 새로 시작합니다.
4. 파일을 못 불러와도 화면에는 알림이 없습니다. F12 Network 탭에서 확인하세요.
확인: F12 콘솔에 `typeof Chart` 를 입력해 `'function'` 이 나오는지 보세요.

### 2-4. 자동 조회가 한 번 실패한 뒤 멈춥니다
결론: 동기 서비스가 실패하면 같은 이벤트의 남은 액션이 모두 취소됩니다. 서비스 뒤 스크립트 액션에서 `setTimeout` 으로 다음 조회를 예약했다면 그 예약도 실행되지 않아 자동 조회가 거기서 멈춥니다.
할 일:
1. [서비스 고급설정]의 [비동기 호출 사용하기]로 바꾸면 다음 주기 예약 코드는 Async Finally Script 로 옮기세요. 성공과 실패 모두에서 실행됩니다.
2. 비동기에서는 실패가 화면에 보이지 않습니다. 알려야 하면 Async Catch Script 에서 직접 띄우세요.
3. 저장, 조회 버튼처럼 사용자가 직접 누르는 동작은 실패가 보이도록 동기로 두세요.
확인: 디버거에서 조회 서비스를 일부러 실패시킨 뒤 다음 주기가 다시 호출되는지 보세요. 비동기 호출은 디버그 로그가 남지 않으므로 F12 Network 탭에서 확인하세요.

### 2-5. f.Setting.User.set 을 한 스크립트에서 여러 번 부르면 흐름이 이상합니다
결론: 공식 명세의 예시는 두 값을 저장할 때 두 호출 사이에 `return;` 을 두어 한 스크립트에서 연달아 부르지 않습니다. 값마다 스크립트 액션을 나누세요.
할 일:
1. 약관 동의처럼 값이 여러 개면 스크립트 액션 하나에 `f.Setting.User.set(...)` 하나씩 두세요.
2. 값은 1 Kbyte 이내만 저장됩니다. 사용자 프로필 JSON 처럼 큰 값은 FlexDB 나 업무 DB 테이블에 저장하고, 여기에는 키나 표시 여부 같은 작은 값만 두세요.
3. 첫 인자 isAsync 의 true, false 에 따라 다음 액션이 언제 실행되는지는 [확인 필요]입니다. 디버거에서 두 값을 모두 시험하세요.
확인: 앱을 다시 열어 `f.Setting.User.get('<키>')` 가 저장한 값을 돌려주는지 보세요.

## 3. 화면 배치와 스크롤

### 3-1. f.Content('<그룹fid>').Scroll.offset 이 계속 0 입니다
결론: 그룹이 스스로 세로 스크롤하는 상자일 때만 값이 나옵니다. 높이가 내용에 맞춰 늘어나는 그룹은 Step 이 대신 스크롤하므로 0 입니다.
할 일:
1. 그룹 디자인 모드의 [스크롤 타입]에서 세로를 고르세요.
2. 그룹 높이를 내용맞춤이 아니라 고정값(px 또는 %)으로 두세요. 내용이 그 높이를 넘어야 스크롤이 생깁니다.
3. fid 는 그룹이나 레이아웃 것을 넣으세요. 버튼, 입력 컨트롤 fid 는 언제나 0 입니다.
원인: 한 그룹의 스크롤은 가로와 세로 중 하나만 고를 수 있고, offset 은 세로 스크롤 그룹만 읽습니다. 가로 스크롤 그룹은 언제나 0 입니다.
확인: 그룹을 조금 내린 뒤 디버거 콘솔 탭에 위 식을 입력해 0 이 아닌 값이 나오는지 보세요.

### 3-2. 시트의 스크롤 위치를 읽거나 가로로 옮기고 싶습니다
결론: 시트 스크롤 위치를 읽는 함수는 없고 옮기기만 됩니다. 가로로 옮길 때는 `Scroll.toCellAtVisual` 을 쓰세요.
할 일:
1. `f.SheetControl('<시트fid>').Scroll.toCellAtVisual(<행번호>, <열번호>)` 를 부르세요. 번호는 화면에 보이는 순서입니다.
2. 세로로만 옮길 때는 `Scroll.toTop()` 이나 `Scroll.toRowAtVisual(<행번호>)` 를 쓰세요.
확인: PC 웹에서 지정한 열이 화면에 들어오는지 보세요.

### 3-3. 나란히 놓은 그룹들의 높이를 가장 높은 것에 맞추고 싶습니다
결론: 높이가 자동인 그룹은 내용 높이에 묶여, 부모 배치나 로드 스크립트의 stretch 로도 늘어나지 않습니다. 같은 줄 그룹에 같은 고정 높이(px)를 주세요.
할 일:
1. 같은 줄의 그룹마다 높이를 같은 px 값으로 지정하세요.
2. 값은 내용이 가장 많은 그룹을 실제 화면에서 재서 정하세요.
확인: PC 웹과 디버그 실행 화면에서 그룹들의 아래 끝이 나란한지 보세요.

### 3-4. 반복 목록에서 로드 스크립트로 일부 행만 색을 바꿨더니 다른 행에도 남습니다
결론: 조건이 참일 때만 스타일을 주면 다른 행에 스타일이 남는 경우가 확인되었습니다. 참과 거짓 양쪽 값을 모두 적으세요.
```javascript
Load.layout.style(Load.sector.<키> === '<값>'
  ? 'border-left:4px solid #DC2626;'
  : 'border-left:4px solid transparent;');
```
확인: 조건이 서로 다른 행을 섞어 조회해 행마다 색이 맞는지 보세요.

## 4. 컨트롤별 함정

### 4-1. 카드를 누르면 화면 이동과 이미지 확대가 함께 실행됩니다
결론: 그룹의 클릭 이동은 안쪽 이미지를 눌러도 실행됩니다. 이미지만 빼는 설정은 없으니 이동을 이미지 옆 그룹으로 내리세요.
할 일:
1. 카드 바깥 그룹의 [클릭 시 스텝 이동]과 Click 이벤트를 지우세요.
2. 이미지와 나란히 있는 글자 묶음 그룹에 [클릭 시 스텝 이동]이나 Click 이벤트를 거세요.
3. 글자 묶음 그룹이 이미지 옆 영역을 꽉 채우게 하세요. 사용자는 카드 전체를 누르는 것처럼 느낍니다.
4. 반복 목록이면 바꾼 뒤 누른 행의 상세로 가는지 꼭 확인하세요.
원인: 그룹 클릭에서 자동으로 빠지는 것은 그룹의 체크박스와 삭제, 더보기, 편집 버튼뿐입니다.
확인: 이미지를 누르면 확대만, 글자 영역을 누르면 이동만 되는지 보세요.

### 4-2. 이미지 확대 화면이 아래에서 올라옵니다. 가운데 팝업으로 바꿀 수 있나요
결론: 지원하지 않습니다. 이미지 확대 화면은 아래에서 위로 올라오는 방식으로 고정되어 있고 바꾸는 속성이 없습니다.
대안: 확대 이미지를 넣은 팝업형 Step 을 직접 만들고, 이미지 Click 이벤트에서 그 Step 으로 이동하세요.
[확인 필요] 팝업형 Step 의 화면 글자는 Studio Step 속성의 다이얼로그 설정에서 확인하세요.

### 4-3. 콤보 목록이 디버그 실행에서는 아래에서 올라오고, 배포 앱에서는 드롭다운으로 나옵니다
결론: 정상입니다. 목록 모양은 실행 환경이 정합니다. PC 웹으로 연 앱은 컨트롤 바로 아래 드롭다운, Studio 디버그 실행 화면은 모바일처럼 아래에서 올라오는 목록입니다. 시나리오 설정으로는 바꿀 수 없습니다.
할 일: 목록 모양은 실제 사용자가 쓸 환경(PC 웹 또는 모바일)으로 배포해서 확인하세요.

### 4-4. 코드도움으로 받은 목록에서 특정 값을 기본 선택으로 두고 싶습니다
결론: 코드도움 컨트롤은 연결된 키에 값이 먼저 들어 있으면 그 값을 선택된 상태로 보여 줍니다. 목록에서 고르게 하지 말고 키에 기본값을 먼저 넣으세요.
할 일:
1. 화면을 열 때 부르는 조회 SP 가 기본값 컬럼을 함께 돌려주게 하세요.
2. 고정값이면 화면을 여는 이벤트 스크립트에서 `섹터.set('<키>', <기본값>)` 으로 넣으세요.
3. 항목이 몇 개뿐이면 코드도움 대신 처음 이벤트에서 서비스로 목록을 카테고리에 받고, 기본값을 넣은 뒤, 컨트롤의 데이터소스를 그 카테고리로 지정하세요.
[확인 필요] 카테고리를 데이터소스로 고르는 화면 글자는 컨트롤 속성의 데이터소스 항목에서 확인하세요.
확인: 화면을 열자마자 컨트롤에 기본값 이름이 보이는지 보세요.

### 4-5. 코드도움의 [CodeHelp Param string]과 [CodeHelp Keyword]에는 무엇을 넣나요
결론: Param string 에는 K-Studio 코드도움 조건 1~4 값을 `|` 로 이어 넣고, Keyword 에는 검색어를 담을 컬렉션 키 이름을 넣습니다.
할 일:
1. Param string 은 `<조건1>|<조건2>|<조건3>` 처럼 쓰세요. K-Studio 에서 코드도움 파라미터 4개를 넘기던 방식과 같습니다.
2. 컨트롤의 Keyword 에 검색어 키 `<검색어키>` 를 지정하세요.
3. 코드도움 서비스 쪽 파라미터에서 `{=<검색어키>}` 로 받으세요.
[확인 필요] 화면 글자가 위와 다르면 Studio 컨트롤 속성의 코드도움 항목에서 확인하세요.
확인: 검색어를 넣고 코드도움을 연 뒤 디버거에서 보낸 값에 검색어가 들어갔는지 보세요.

### 4-6. 엑셀로 내려받을 때 사진도 넣고 싶습니다
결론: 지원하지 않습니다. `f.Sheet.download` 와 시트 우클릭 엑셀 다운로드 모두 셀 값만 씁니다.
대안: 사진은 `f.File.download` 로 파일을 따로 내려받게 하세요.

## 5. Studio 설정 화면

### 5-1. Etc 탭에 같은 키가 두 줄 보이거나, 줄 삭제 버튼이 눌리지 않습니다
결론: 두 줄은 한쪽 키 이름 끝에 공백이 있는 경우입니다. 삭제가 안 되는 줄은 그 키가 아직 어느 카테고리나 컨트롤 키 목록에 남아 있는 경우입니다.
할 일:
1. 카테고리 키를 추가할 때 앞뒤 공백을 넣지 마세요. 카테고리 키 추가는 공백을 자르지 않습니다.
2. 디버거 콘솔 탭에서 `JSON.stringify(Object.keys(_c.activeSector))` 로 키 이름을 따옴표째 보고, 공백 키만 지우세요. 겉보기가 같아 정상 키를 지우는 실수가 많습니다.
3. 줄을 지우려면 먼저 그 키를 쓰는 카테고리와 컨트롤에서 빼세요.
4. 시트가 있는 시나리오에서는 [All CollectionKey]에서 지워도 Etc 탭에 그대로 남는 결함이 확인되었습니다. 저장하고 Studio 를 다시 열어 확인하고, 남아 있으면 플렉스튜디오 담당자에게 문의하세요.
원인: 공백 키는 SP 호출 때 `Column names ... specified more than once` 오류도 만듭니다.
확인: 저장 후 Studio 를 다시 열어 Etc 탭에 한 줄만 남았는지 보세요.

## 6. K-System SP 넘기기 전 추가 점검

### 6-1. K-System SP 설명의 점검 목록 말고 더 볼 것이 있나요
결론: 아래 세 가지를 더 보세요.

| 점검 | 놓치면 |
|---|---|
| 회사, 언어, 사용자 3값은 [사용자 데이터]에만 넣고 Etc 탭이나 카테고리 키에 다시 등록하지 않았다 | 같은 컬럼이 두 번 생겨 `Column names ... specified more than once` |
| 카테고리 키와 Etc 키에 앞뒤 공백이 없다 | 같은 오류, Etc 탭에 같은 키 두 줄 |
| SP 가 회사, 사용자 값을 임시 테이블 컬럼이 아니라 @CompanySeq, @UserSeq 파라미터로 읽는다 | 6-2 처럼 NULL 이나 다른 타입을 읽음 |

### 6-2. #BIZ_IN 의 UserSeq 컬럼과 @UserSeq 파라미터 값이 다릅니다
결론: 정상입니다. 사용자 정보는 두 길로 따로 옵니다. 파라미터는 숫자로 오고, 컬럼은 화면이 보낸 값의 모양으로 타입이 정해지며 값이 없으면 NULL 입니다.
예: 실측에서 UserSeq 컬럼은 NVARCHAR(MAX) 에 NULL, @UserSeq 파라미터는 INT 0 이었습니다. CompanySeq 는 컬럼이 NVARCHAR(2) '1', 파라미터가 INT 1 이었습니다.
할 일: 회사, 언어, 사용자는 파라미터로 읽으세요. 컬럼 값과 비교해야 하면 CONVERT 로 타입을 맞추세요.

### 6-3. ERP 표준 SP 를 꼭 다시 쓰고 싶습니다
결론: [SP List]에는 바로 넣을 수 없습니다. 새 SP 안에서 #BIZ_IN 을 XML 로 접어 표준 SP 를 부르는 방법은 실측으로 동작했지만, 표준 SP 가 쓰는 @ServiceSeq 값을 SP 에 고정해야 하고 얻는 것이 적습니다.
할 일: 임시 테이블을 직접 읽는 SP 를 새로 만드세요. 표준 SP 의 업무 로직이 필요하면 ERP 개발 담당자와 함께 옮기세요.

## 7. FlexSQL 설계

### 7-1. 날짜 표시 형식을 화면마다 맞추기 어렵습니다
결론: 표시 형식은 SQL 에서 만들어 돌려주고, 화면은 `{=키}` 로 그대로 보여 주세요. 형식을 바꿀 때 SQL 한 줄만 고치면 모든 화면이 같이 바뀝니다.
```sql
SELECT DATE_FORMAT(CreateDate, '%Y-%m-%d %H:%i') AS CreateDate
  FROM <테이블>;
```
확인: 같은 키를 쓰는 화면들에서 날짜 모양이 같은지 보세요.

### 7-2. 상태 값을 바꾸는 규칙을 SQL 에 넣어야 하나요
결론: 넣지 마세요. 어떤 상태로 바꿀지는 시나리오에서 정하고 SQL 은 받은 값을 저장만 하게 하세요. 규칙이 바뀌어도 SQL 을 고치지 않고, 같은 SQL 을 다른 상태 변경에도 다시 씁니다.
```sql
<% let r = paramBlocks[0][0]; %>
UPDATE <테이블>
   SET Status = <%= r.<상태키> %>
 WHERE <PK컬럼> = <%= r.<PK키> %>;
```
확인: 스크립트에서 `섹터.set('<상태키>', '<새 상태>')` 로 바꾼 값이 DB 에 그대로 저장되는지 보세요.

## 8. 증상으로 찾기

| 보이는 것 | 원인 | 볼 곳 |
|---|---|---|
| 브라우저 콘솔에 `Unexpected token ':'` | 시나리오 JSON 을 콘솔에 붙여 실행함 | JSON 은 콘솔에 붙이지 말고 Studio 탭을 다시 여세요 |
| `50000\|Procedure or function '<SP>' expects parameter '@xmlDocument', which was not supplied.\|...\|16` | 영문 DB 에서 ERP 표준형 SP 를 바로 부름 | 6-3 |
| 저장 SP 가 "수정할 행이 없다" 같은 사용자 오류를 냄 | 스크립트로 만든 행이 상태가 비어 U 로 감 | 호출 전 `setStatus('added')`, 1-1 |
| Etc 탭에 같은 키 두 줄, 줄 삭제가 안 됨 | 키 끝 공백, 키가 아직 쓰이는 중 | 5-1 |
| 하위 시나리오에서 대상 카테고리가 빔 | addSector 복제로 선택 행과 카테고리가 갈라짐 | 1-5 |
| 하위에서 돌아오니 부모 데이터가 사라짐 | 대체하기는 통째 교체 | 1-6 |
| 그룹 Scroll.offset 이 항상 0 | 세로 스크롤 상자가 아님 | 3-1 |
| 카드 속 이미지를 눌렀는데 화면이 이동함 | 그룹 클릭이 이미지에도 반응 | 4-1 |
| 디버그 실행과 배포 앱의 콤보 모양이 다름 | 실행 환경 차이 | 4-3 |
| 외부 라이브러리 이름이 undefined | UMD 빌드가 아님, 파일 로드 실패 | 2-3 |
| 몇 초마다 돌던 자동 조회가 어느 순간 멈춤 | 동기 서비스 실패로 뒤의 예약 스크립트가 취소됨 | 2-4 |
| 비동기 서비스가 실패했는데 아무 메시지가 없음 | 비동기는 오류 창과 디버그 로그가 없음 | 2-4, Async Catch Script |
| `f.Setting.User.set` 두 번 뒤 흐름이 꼬임 | 한 스크립트에서 연달아 호출함 | 2-5 |
