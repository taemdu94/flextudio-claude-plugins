# 문제 해결: 증상 → 원인 → 확인 → 조치
이 파일이 답하는 질문: 어디부터 봐야 하나요 / 디버거는 어떻게 쓰나요 / 특정 사용자만 오류가 나요 / 값이 안 나와요 / 저장이 안 돼요 / 행이 쌓여요 / 화면이 안 바뀌어요 / 무한 로딩·흰 화면 / 버튼이 안 먹어요 / 서비스 오류 메시지 뜻 / 코드도움 오류 / DB 권한 오류 / SP 만 따로 시험하려면 / FlexSQL 오류 / 배포했는데 반영이 안 돼요 / 모바일에서만 안 돼요 / 문의할 때 무엇을 보내나요

목차
1. 진단 순서
2. 디버거와 디버그 권한 쓰는 법
3. 증상별 표 (값이 안 나와요, 저장이 안 돼요, 행이 쌓여요, 화면이 안 바뀌어요, 무한 로딩·흰 화면, 버튼이 안 먹어요)
4. 서비스 오류 메시지별 표 (K-System 연동 서비스)
5. FlexSQL·다른 서비스 오류 메시지
6. 배포했는데 반영이 안 돼요
7. 모바일·PDA 에서만 안 돼요
8. 질문할 때 보낼 정보

증상이 아니라 "이 기능이 되나요" 같은 짧은 질문은 자주 묻는 질문 모음을 먼저 보세요.

## 1. 진단 순서

문제가 생기면 데이터가 지나가는 길을 따라 어느 단계에서 끊겼는지부터 찾습니다.
화면 동작 → 이벤트 → 서비스 → SP 또는 SQL → [받는 데이터] → 화면 그리기

1. 디버거로 재현하세요.
   문제가 난 앱, 테넌트, 사용자를 고르고 같은 순서로 눌러 보세요(2절).
2. 디버거 [실행 내역]에서 어느 이벤트까지 실행됐는지 보세요.
3. 메시지 창이 떴다면 문구 전체를 텍스트로 복사하고 4절, 5절 표에서 찾으세요.
4. 메시지 없이 멈췄다면 브라우저 F12 콘솔에서 스크립트 오류를 보세요(3-6).
5. 서비스는 성공했는데 결과가 이상하면 DB 쪽을 따로 확인하세요.
   SP 는 DB 도구에서 단독 실행하세요(아래 예시).
   FlexSQL 은 실행문 미리보기와 [Test-SQL]로 실제 SQL 을 보세요.

| 확인 결과 | 문제 위치 | 볼 곳 |
|---|---|---|
| DB 값은 맞는데 화면만 다름 | 화면 메모리(컬렉션) 갱신 | 3-4 |
| DB 값도 그대로 | SQL·서비스·[보내는 데이터] 설정 | 3-2, 4절 |
| 이벤트가 중간에 끊기고 메시지 없음 | 스크립트 오류 | 3-6 |
| 메시지 창이 뜸 | 서비스 오류 | 4절, 5절 |

설정 하나를 바꿨더니 됐다면 같은 조건에서 그 값만 되돌려 다시 확인하세요.
확인 전에는 그것을 원인으로 단정하지 마세요.

### SP 단독 실행 예시 (MS SQL, K-System 연동 서비스(Flex-K))

플렉스튜디오는 [보내는 데이터]를 임시 표 `#BIZ_IN_DataBlock1` 의 행으로 만들고, 같은 내용을 `#BIZ_OUT_DataBlock1` 에 복사한 뒤 SP 를 4개 파라미터로 실행합니다.
DB 도구에서 같은 모양을 만들면 화면 없이 SP 만 시험할 수 있습니다.

```sql
IF OBJECT_ID('tempdb..#BIZ_IN_DataBlock1') IS NOT NULL DROP TABLE #BIZ_IN_DataBlock1;
IF OBJECT_ID('tempdb..#BIZ_OUT_DataBlock1') IS NOT NULL DROP TABLE #BIZ_OUT_DataBlock1;
CREATE TABLE #BIZ_IN_DataBlock1 (
    WorkingTag NVARCHAR(1), IDX_NO INT, DataSeq INT, Selected INT, MessageType INT, Status INT,
    Result NVARCHAR(255), ROW_IDX INT, IsChangedMst NCHAR(1), TABLE_NAME NVARCHAR(255),
    _SUID NVARCHAR(MAX), _mSUID NVARCHAR(MAX),
    <조건키> NVARCHAR(100), <결과키> NVARCHAR(100),
    CompanySeq INT, LanguageSeq INT, UserSeq INT
);
INSERT INTO #BIZ_IN_DataBlock1 (WorkingTag, IDX_NO, DataSeq, Selected, MessageType, Status, TABLE_NAME, _SUID,
                                <조건키>, CompanySeq, LanguageSeq, UserSeq)
VALUES (N'U', 1, 1, 0, 0, 0, N'DataBlock1', CONVERT(NVARCHAR(50), NEWID()),
        N'<디버거에서 본 값>', <회사번호>, <언어번호>, <사용자번호>);
SELECT * INTO #BIZ_OUT_DataBlock1 FROM #BIZ_IN_DataBlock1;

EXEC <SP이름> @WorkingTag = N'', @CompanySeq = <회사번호>, @LanguageSeq = <언어번호>, @UserSeq = <사용자번호>;
SELECT * FROM #BIZ_OUT_DataBlock1;
```

이 코드가 하는 일: 화면이 보낼 행 1개를 임시 표에 넣고 SP 를 실행합니다.
맨 앞 두 줄은 남은 임시 표를 지워, 같은 창에서 다시 실행해도 실패하지 않게 합니다.
관리 컬럼 12개의 이름과 타입은 K-System 서비스 설명의 임시 테이블 규격과 같습니다.
SP 가 INSERT 하거나 읽는 컬럼이 표에 하나라도 없으면 `Invalid column name` 오류로 실패합니다.
[사용자 데이터]로 보내는 키(CompanySeq 등)와 SP 가 읽거나 쓰는 업무 키도 모두 표에 넣으세요.
업무 키의 타입은 [Etc] 탭 Collections 에 등록한 타입에 맞추세요(string 은 NVARCHAR, int 는 INT, double 은 DECIMAL(19,5)).
마지막 SELECT 에서 Status 가 0 이 아닌 행의 Result 가 오류 원인입니다.

## 2. 디버거와 디버그 권한 쓰는 법

디버거는 실제 테넌트 데이터로 시나리오를 실행하는 시험 화면입니다.
Studio 의 ▶(디버그 실행) 버튼을 누르면 열립니다.
[확인 필요] Studio 화면이 개편되어 메뉴와 탭 이름이 아래와 다르면 같은 역할의 탭을 찾으세요.

1. [앱 접속 정보]에서 앱, 앱팩, 테넌트, 사용자를 고르세요.
2. 화면 모양을 바꾸려면 톱니 설정에서 PC 스타일 보기나 모바일 헤더 숨김을 고르세요.
3. 문제가 난 순서대로 눌러 재현하세요.

| 도구 | 보이는 것 | 이럴 때 보세요 |
|---|---|---|
| [실행 내역] | Step 별로 실행된 이벤트·서비스, 이벤트 안 스크립트(들여쓰기), 오류·알림 문구 | 어디서 멈췄는지 |
| 컬렉션·카테고리 탭 | 지금 메모리에 있는 행과 값 | 받은 키 이름, 값이 들어왔는지 |
| 디버거 콘솔 탭 | 직접 입력한 식의 값(`_c.activeSector` 등) | 섹터 값을 바로 볼 때 |
| [Test-SQL], [Test-API] | FlexSQL 서비스, API 연동 모듈 단독 시험 | 화면 없이 서비스만 볼 때 |

- Test-SQL 결과는 시나리오 데이터에 영향을 주지 않습니다.
  입력값이 이전 값으로 남아 있을 수 있으니 실행 전에 확인하세요.
- 스크립트의 `console.log` 출력은 디버거 콘솔 탭이 아니라 브라우저 F12 콘솔에 나옵니다.
  스크립트 오류는 디버그 실행 중에는 디버거에도 보이지만, 배포한 앱에서는 F12 콘솔에만 남습니다.
- 서버 응답 원문이 필요하면 F12 Network 탭에서 그 요청의 Response 를 보세요.
- 느림·시간 초과는 F12 Network 의 Timing 에서 Waiting 값을 성공한 호출과 비교하세요.
- 디버거 오류는 어느 이벤트인지까지만 알려 줍니다.
  이벤트 안 액션의 건너뛰기를 하나씩 켜 보거나 `console.log` 를 넣어 범위를 좁히세요.

디버거에서 주의할 점은 아래와 같습니다.
- `f.Frame` 계열(팝업, 다른 시나리오 호출, 탭바, 타이틀)은 디버거에서 동작하지 않습니다.
  배포된 앱에서 확인하세요.
- 다음 함수는 디버거에서도 실제로 발송되거나 실행됩니다: `f.Message`(푸시), `f.Mail`, `f.TeamsBot`, `f.Outlook`, `f.Workflow.run`.
- [비동기 호출 사용하기]를 켠 서비스는 실패해도 오류 창이 없고 디버그 로그도 남지 않습니다. SP 가 돌려준 실패 메시지도 보이지 않고 Async Catch Script 만 실행됩니다.

특정 사용자에게만 오류가 나면 이렇게 하세요.
1. 고객 설정 페이지 [사용자관리]에서 그 사용자에게 디버그 권한을 주세요.
2. 디버거 [앱 접속 정보]에서 그 사용자를 고르세요.
3. 같은 순서로 재현하세요.

운영 중에 난 오류는 앱 메뉴의 [서비스오류로그]에서 확인하세요.

## 3. 증상별 표

### 3-1. 값이 안 나와요

| 보이는 것 | 원인 | 확인 | 조치 |
|---|---|---|---|
| 서비스는 성공, 화면 칸이 비어 있음 | SP·SQL 결과 컬럼 이름과 컬렉션 키가 다름 | 컬렉션 탭의 키와 화면 연결 키를 대소문자까지 비교 | SQL 에서 `AS <컬렉션키>` 로 이름을 맞추세요 |
| 받는 데이터는 있는데 목록이 안 그려짐 | [받는 데이터] 카테고리 이름 ≠ 화면에 연결한 카테고리 이름 | 두 이름 비교 | 같은 이름으로 맞추세요 |
| 컬렉션에는 행이 있는데 화면 0행(Q조회 SP) | `#BIZ_OUT` 의 `_SUID` 가 NULL | SP 의 INSERT 컬럼 목록 | `_SUID = CONVERT(NVARCHAR(50), NEWID())` 를 넣으세요. SP 가 직접 SELECT 하는 방식이면 `_SUID` 를 빼세요 |
| 결과가 자동으로 화면에 안 붙음 | 자동 반영은 카테고리가 최상위 그룹에 연결된 경우만 | 연결 그룹 위치 | 최상위 그룹에 연결하거나 서비스 뒤 `f.Content('<그룹fid>').reload()` |
| Loaded 에서 넣은 값이 안 보임 | Loaded 는 화면을 그린 뒤 실행 | 이벤트 위치 | 첫 조회는 Init 에, Loaded 에서 바꾸면 그 영역을 reload 하세요 |
| 서비스 바로 다음 스크립트에서 결과가 비어 있음 | [비동기 호출 사용하기]가 켜져 있음 | 서비스 액션의 [서비스 고급설정] | 결과를 바로 쓰면 비동기를 끄세요 |
| 반복 목록의 `{% %}` 가 모든 행에 같은 값 | `_c.activeSector` 는 그리는 행이 아님 | 스크립트 내용 | 행 값은 `Load.sector.<키>` 로 읽으세요 |
| 버튼 글자에 `{=키}` 가 그대로 보임 | 버튼은 데이터 연결 없이 그려짐 | 버튼을 감싼 그룹의 데이터 연결 | 감싼 그룹에 카테고리를 연결하세요 |
| 조회 결과에 조건 행이 섞임 | `#BIZ_OUT` 에 입력 행이 처음부터 복사되어 있음 | SP 앞부분 | 결과 INSERT 전에 `DELETE FROM #BIZ_OUT_DataBlock1` |
| 아무 행도 안 골랐는데 첫 행 값이 나옴 | 선택 행이 없으면 `_c.activeSector` 가 첫 행을 돌려줌 | 클릭 여부 | 처리 전에 키 값으로 그 행이 맞는지 확인하세요 |
| 부서명 등 사용자 정보가 SP 로 안 감 | 부서명(`fBaseDeptName`)은 [사용자 데이터] 고정 키 8종에 들어 있지 않음 | 보낸 키 목록 | 스크립트에서 보낼 섹터에 `set('Department', _base.User.fBaseDeptName \|\| '')` |

### 3-2. 저장이 안 돼요

| 보이는 것 | 원인 | 확인 | 조치 |
|---|---|---|---|
| 값을 바꿨는데 저장 대상에서 빠짐 | `sector.키 = 값` 직접 대입은 변경 표시가 안 됨 | 스크립트에 `=` 대입이 있는지 | `sector.set('<키>', <값>)` 로 바꾸세요 |
| 새 행이 SP 에 U 로 들어옴 | `f.Collection.addSector` 로 만든 행은 상태가 비어 있음 | 저장 전 `isAdded` | 만든 직후 `setStatus('added')` |
| `setStatus` 를 했는데도 U | 인자 오타(`'Updated'`, `'A'`)면 상태가 지워지기만 함 | 인자 글자 | 소문자 `'added'`, `'updated'`, `'deleted'` 만 쓰세요 |
| 삭제했는데 DB 에 남음 | `f.Collection.removeSector` 는 화면 메모리에서만 지움 | 쓴 함수 | 서버에서도 지울 행은 `sector.delete()` |
| 화면 `status` 값이 SP 에 안 옴 | Status·Result·Message·Selected·DataSeq·IDX_NO·ROW_IDX·WorkingTag·TABLE_NAME 은 대소문자 무관 예약 이름 | 카테고리 키 이름 | `ApprStatus` 처럼 이름을 바꾸세요 |
| 숫자 칸을 비웠는데 0 으로 저장 | 숫자 타입 빈 값은 0 으로 들어감 | 키 타입 | 미입력을 가려야 하면 문자열 타입으로 보내세요 |
| 두 번째 SP 가 실패했는데 첫 SP 저장은 남음 | 공통 트랜잭션이 꺼져 있음 | 서비스 설정 | 공통 트랜잭션을 켜고, SP 안에서 `BEGIN TRAN` 을 쓰지 마세요 |
| 엉뚱한 행이 저장·삭제됨 | 시트는 한 번 클릭으로 Active 행이 안 바뀌고, 선택 행이 없으면 첫 행이 쓰여 다른 행이 처리될 수 있음 | 클릭한 행의 키 값 | 처리 전에 키 값을 확인하세요 |
| FlexSQL 저장 0건, 값이 깨짐 | `<%= %>` 를 따옴표로 또 감쌈 | SQL 본문 | 표현식 앞뒤 따옴표를 지우세요 |
| FlexSQL 로 저장한 값에 `\_` | `<%= %>` 는 `_` 앞에 `\` 를 붙임 | 저장된 값 | 저장 값은 `<%- %>`, LIKE 검색어는 `<%= %>` |
| FlexSQL 을 고쳤는데 옛 동작 | 서비스 버전을 발행하지 않음 | FlexSQL 버전 화면 | [새 버전 발행] 또는 [현재버전으로 변경내역 반영] |

### 3-3. 행이 쌓여요

| 보이는 것 | 원인 | 확인 | 조치 |
|---|---|---|---|
| 조회할 때마다 목록이 늘어남 | [받는 데이터] 반영 방식이 기본값 추가 | 반영 방식 | 조회는 [덮어쓰기] |
| 병합인데 같은 행이 두 줄 | 병합 기준 키가 빈 목록으로 남음 | 기준 키 설정 | 기준 키를 지우거나 `_SUID` 를 지정하세요 |
| 서비스가 두 번 나감 | 버튼 Click 과 이동한 Step 의 Loaded 에 같은 조회 | 실행 내역 | 호출을 한 곳에만 두세요 |
| 1건만 보여야 할 카드가 N번 복제 | 그룹 데이터 사용 방식이 기본값(default) | 그룹 데이터 연결 | 단건은 상세(detail) + 상태 필터 active |
| 행을 옮겼더니 두 줄 | `f.Collection.addSector` 는 복제 | 쓴 함수 | `f.Collection.moveCategory('<원본>', '<상태>', '<대상>')` |
| reload 뒤 복제가 꼬임 | 데이터 연결 그룹 자체를 reload | reload 대상 fid | 연결 없는 그룹으로 한 겹 감싸고 그 그룹을 reload |

## 6. 배포했는데 반영이 안 돼요

저장과 "사용자에게 보임" 사이에는 단계가 여럿 있습니다.
아래 순서로 하나씩 확인하세요.

1. Studio 에서 시나리오를 [배포]했는지(시나리오 버전 발행) 보세요.
2. 앱 [시나리오 관리] > [시나리오 배포]에서 그 버전을 고르고 [라이브에 적용]을 눌렀는지 보세요.

3. FlexSQL 을 고쳤다면 [새 버전 발행] 또는 [현재버전으로 변경내역 반영]을 하세요.
4. API 연동 모듈을 고쳤다면 모듈 화면에서 [배포]하세요.
5. 앱팩을 쓰는 앱이면 [앱팩] 메뉴에서 배포하세요.
6. 새 권한키는 시나리오를 배포하고 라이브에 적용해야 권한 관리에 보입니다.
7. 앱에서는 메뉴로 다시 들어가거나 홈 버튼을 누르면 배포본이 적용됩니다.

|---|---|---|
| 메뉴·시작페이지에서 시나리오를 못 고름 | [개발]에서 만든 시나리오는 어느 앱에도 속하지 않음 | 앱 [시나리오 관리]에 추가하세요 |
| 저장했는데 남이 고친 내용이 사라짐 | 오래 열어 둔 Studio 탭으로 저장하면 그 탭 내용으로 덮어씀 | 다른 곳에서 고친 뒤에는 Studio 탭을 새로 여세요 |
| 같은 시나리오가 워크스페이스마다 다르게 동작 | 엔진 버전이 팩 단위로 다름 | 엔진 버전을 먼저 비교하세요 |
| 권한을 줬는데 다른 앱 권한이 사라진 듯 보임 | 개별 앱 탭 저장 뒤 표시 문제 | 새로고침으로 확인하고, 여러 앱은 [전체] 탭에서 한 번에 저장 |

## 7. 모바일·PDA 에서만 안 돼요

| 보이는 것 | 원인 | 조치 |
|---|---|---|
| 앱에서 시트가 안 보임 | 시트는 모바일 앱에서 쓸 수 없음 | 모바일 화면은 반복 그룹으로 만드세요 |
| 앱에서 엑셀 내려받기가 안 됨 | `f.Sheet.download` 는 PC 웹 전용 | 파일은 `f.File.download` 를 쓰세요(앱에서도 동작) |
| 앱에서 인쇄 버튼이 무반응 | 설치형 앱은 `window.print()` 를 무시 | `f.Link` 와 `f.Browser.open` 으로 브라우저에 넘겨 인쇄 |
| `f.Browser.open` 으로 파일이 안 열림 | https 만 열고 `data:`·`blob:` 주소는 못 엶 | https 주소로 여세요 |
| PDA 스캔 무반응 | 스캐너 앱 접미 문자열 ≠ `scanSuffix`, 또는 기기 모델이 `usePDAModels` 에 없음 | 두 값을 대소문자·하이픈까지 맞추세요 |
| 스캔 시작을 눌러도 화면 변화 없음 | 정상(숨은 입력칸에 포커스만 잡음) | 스캔 중 표시를 따로 만드세요 |
| 다른 화면으로 가도 스캔이 계속됨 | 스캔을 멈추지 않음 | 화면을 떠날 때(OnLeave) `f.Scanner.stopScan()` |
| PC·디버거에서 바코드 인식이 부정확 | 카메라 스캔은 PC 정확도가 낮음 | 실제 기기에서 시험하세요 |
| 숫자 입력 마스크가 이상함(삼성 브라우저) | 브라우저 문제 | Chrome 을 쓰세요 |
| Android 16 에서 뒤로가기 시 앱이 닫힘 | 앱 빌드 라이브러리 버전 | flex-lib 1.0.26 으로 다시 빌드하세요 |
| 로그인 시 "존재하지 않는 번호" | 휴대폰 번호에 하이픈 | `01000000000` 형식으로 등록하세요 |
| 개발자로 등록했는데 앱 로그인 불가 | 개발자 등록은 앱 사용권한이 아님 | 고객 설정 [사용자관리]에서 앱 사용권한을 주고 초대 문자를 보내세요 |
