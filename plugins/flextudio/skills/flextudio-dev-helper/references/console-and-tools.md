# 콘솔 화면과 개발 도구 (배포, 고객관리, 요금제, 디버거, 자동 조회, 구글 시트, API 연동, 링크, 레이아웃)

이 파일이 답하는 질문: 콘솔 어느 메뉴에서 무엇을 하나요? | 시나리오 배포는 어디서 하고 이전 버전은 어떻게 보나요? | 기본앱과 초대 기반 앱은 무엇이 다른가요? | 고객(테넌트)에 앱은 어떻게 할당하나요? | 요금제마다 열리는 기능은? | 디버거 탭은 각각 무엇에 쓰나요? | Test-SQL 에 파라미터는 어떻게 넣나요? | 외부 DB 를 Test-SQL 로 조회하려면? | 자동 조회(FlexAutoQuery)는 어떤 테이블에 쓰나요? | 구글 시트 서비스 모듈은 각각 무엇을 하나요? | API 연동 화면은 어떻게 생겼나요? | 링크로 특정 화면을 바로 열려면? | 메뉴와 하단탭은 어디서 정하나요?

화면 이름과 버튼 글자는 공식 문서(docs.flextudio.com)에 적힌 그대로 [대괄호]로 씁니다.
문서 그림은 2026-03 시나리오 페이지 리뉴얼, 2026-05 콘솔 고객관리 페이지 개편 전 것일 수 있습니다. 화면이 다르면 위치보다 메뉴 이름으로 찾으세요.

목차: 1 콘솔 메뉴 지도 / 2 시나리오 배포와 배포내역 / 3 앱 종류와 고객관리, 앱 할당 / 4 요금제별 기능 / 5 디버거 / 6 자동 조회(FlexAutoQuery) / 7 구글 시트(GoogleSheet) / 8 API 연동 화면 / 9 링크관리, 레이아웃관리, 서비스오류로그, 앱정보설정

## 1. 콘솔 메뉴 지도

| 콘솔 메뉴 | 하는 일 |
|---|---|
| [앱] | 앱별 시나리오, DB 연결, 사용자와 고객 현황을 보고 버전, 레이아웃, SDK 를 설정합니다 |
| [앱팩] | 여러 시나리오를 묶은 앱팩을 만들고 배포합니다 |
| [개발] | 시나리오와 권한키를 관리합니다. [패키지설치]도 여기 있습니다 |
| [데이터] | [API 연동]과 [FlexSQL]을 관리합니다 |
| [고객관리] | 워크스페이스의 모든 고객 목록을 보고 고객 설정 페이지로 들어갑니다 |
| [에뮬레이터] | PC 에서 모바일 화면을 체험합니다. iOS, Android 기기 환경까지 흉내 내지는 않습니다 |

[앱]을 고르면 [대시보드], [시나리오 관리], [레이아웃 관리], [고객관리], [링크앱팩설정], [링크관리], [서비스오류로그], [SDK설정], [앱정보설정] 메뉴가 나옵니다.
초대 기반 앱이 아니면 [고객관리] 자리에 [데이터연결]이 나옵니다.
[대시보드]에는 앱 URL 복사와 [에뮬레이터 바로가기]가 있고, [SDK설정]에서는 iOS, Android 앱 연결과 초대 문자 타입을 정합니다.
나머지 메뉴는 아래 절에서 설명합니다.

## 2. 시나리오 배포와 배포내역

시나리오가 사용자에게 보이려면 두 곳에서 따로 눌러야 합니다.

```text
Studio 저장 → Studio [시나리오 배포] 패널에서 배포(버전 추가)
          → 콘솔 [앱]-[시나리오 관리]-[시나리오 배포]에서 버전 선택 → [라이브에 적용]
```

### Studio 쪽 패널 (맨 위 오른쪽 아이콘)

| 패널 | 영역 | 하는 일 |
|---|---|---|
| [시나리오 배포] | 배포사유입력 | 사유를 적고 시나리오 버전을 추가합니다 |
| [시나리오 배포] | 배포내역 | 버전별 사유와 배포일을 봅니다 |
| [시나리오 배포] | 시나리오 버전별로 확인하기 | 그 버전의 마지막 상태를 새 탭에서 엽니다. 보기만 됩니다 |
| [시나리오 관리] | 편집 내용 입력 | 편집을 마칠 때 바꾼 내용을 적습니다. 마쳐야 다른 작업자가 편집합니다 |
| [시나리오 관리] | 편집내역 되돌리기 | 이번 편집을 저장하지 않고 끝냅니다 |
| [시나리오 관리] | 다른시나리오 덮어쓰기 | 다른 시나리오를 검색해 그 내용으로 덮어씁니다 |
| [시나리오 관리] | 편집내역 | 편집자, 편집 시간, 편집 내용 기록 |

- 시나리오 삭제 창에는 워크스페이스 이름을 뺀 시나리오 아이디를 넣습니다. 예: `wsname||sample_2404090937185` 이면 `sample_2404090937185` 입니다.
- [확인 필요] 이전 버전으로 시나리오 내용을 되살리는 버튼은 문서에 없습니다. 앱에 이전 버전을 다시 적용하는 방법은 아래 버전 목록을 보세요.

### 콘솔 쪽: [앱]-[시나리오 관리]-[시나리오 배포]

| 영역 | 하는 일 |
|---|---|
| 시나리오 검색 | 배포된 시나리오만 찾습니다. 이미 앱에 추가한 시나리오는 나오지 않습니다 |
| 시나리오 목록 | 이름, ID, 라이브 사용 버전, 마지막 개발 버전, 삭제 |
| 버전 목록 | 고른 시나리오의 버전들. 한 번에 하나만 적용합니다 |
| [변경사항 취소] | 마지막 적용 시점으로 되돌립니다 |
| 히스토리 | 라이브에 배포한 내역 |
| [라이브에 적용] | 현재 설정을 앱에 반영합니다 |

1. 검색에서 시나리오를 골라 앱에 추가하세요. 서브시나리오도 함께 들어갑니다.
2. 버전 목록에서 쓸 버전을 고르세요.
3. [라이브에 적용]을 누르세요.

- 같은 문서에서 이 버튼을 [앱에서 사용하기]라고도 적습니다. 같은 버튼으로 보세요.
- [라이브에 적용]은 실사용자에게 바로 반영됩니다. 먼저 디버거로 확인하세요.
- 링크앱팩을 쓰는 앱은 이 메뉴가 꺼집니다. [앱팩] 메뉴에서 버전을 고르고 [라이브에 적용]을 누르세요. 앱팩 기록은 [패킹 히스토리]에 있습니다.
- [개발]에서 만든 시나리오는 이 화면에서 추가해야 앱에서 씁니다. [앱]-[시나리오 관리]의 [새 시나리오]로 만들면 그 앱에 바로 들어갑니다.

## 3. 앱 종류와 고객관리, 앱 할당

| 구분 | 문서 설명 | 콘솔에서 달라지는 점 |
|---|---|---|
| 공개앱(오픈앱) | 별도 인증 없이 접속하는 앱 | 앱 메뉴에 [데이터연결]. 사용자 메뉴 이름은 [SNS 유저관리] |
| 초대 기반 앱(초대앱) | 전화번호, 이메일로 초대한 사용자만 쓰는 앱 | 앱 메뉴에 [고객관리]. 사용자 메뉴 이름은 [사용자관리] |

- 고객관리 문서는 초대 기반 앱이 아닌 앱을 "기본앱"이라고 부릅니다. [확인 필요] 기본앱과 공개앱이 같은 뜻인지는 문서에 정의가 없습니다.
- 기본앱은 레이아웃의 로그아웃 버튼이 켜지지 않습니다.
- 외부 DB 연동, [회사 정보], 앱 전환은 초대 기반 앱에서만 됩니다.
- 기본앱의 [데이터연결]에서 [바로가기]를 누르면 고객 설정 페이지가 일부 메뉴만 열린 채로 뜹니다. 사용자 관리, 앱별 사용자 상태 설정, 그룹관리, 사용자별 권한관리, 그룹별 권한관리, 시스템 정보입니다.

### 콘솔 [고객관리]와 앱 할당

화면은 앱 모음, 고객 검색, 고객 추가, 고객 목록으로 나뉩니다.

- [신규고객추가]는 회사명만 필수입니다.
- [기존고객추가]는 다른 워크스페이스가 관리하는 고객을 연결합니다. 그 고객의 고객번호와 접속키가 필요하고, 둘 다 고객 설정 페이지 [회사 정보]에 있습니다.

1. 고객 목록에서 [상세보기]를 누르세요.
2. [앱 설정]에서 이 고객이 쓸 앱을 고르세요.
3. 링크앱팩을 쓰면 [앱팩 설정]에서 앱팩을 추가하세요.
4. 고객 설정 페이지 [앱별 사용자 상태 설정]에서 사용자에게 앱 사용권한을 주세요. 상태는 [권한없음], [사용가능], [사용중] 세 가지입니다.

- 고를 수 있는 앱은 지금 워크스페이스에 있는 앱뿐입니다. 기존고객추가로 연결한 고객도 같습니다.
- 앱 쪽 [고객관리] 상세보기에는 "기본앱은 할당/해제 설정이 불가능합니다"라는 문구가 있습니다. [확인 필요] 이 기본앱이 앱 종류인지, 그 고객의 기본 앱인지 문서로는 알 수 없습니다.
- 접속키 초기값은 워크스페이스 이름입니다. 바꾼 값은 다시 볼 수 없으니 따로 보관하세요.
- [앱 기본설정]의 [사용자 직접 가입]을 켜면 관리자가 [앱 초대 문자 발송]을 하지 않아도 됩니다. 가입 페이지 링크를 받은 사용자가 정보를 넣고 초대 문자를 직접 받습니다.
- [외부 DB 정보]에는 MySQL, MSSQL, Azure MSSQL, Oracle 을 넣을 수 있고 고객마다 하나입니다. 방화벽에서 허용할 IP 는 공식 문서 "외부 DB 연동" 쪽에 있습니다.

공식 문서 쪽마다 적힌 문장을 그대로 모았습니다. 쪽마다 다르게 적힌 곳이 있으니 요금제를 단정하지 마세요.

| 기능 | 문서 표기 | 판단 |

| 하단 별 권한, 메뉴별 권한, SDK | Start 이상 | 표기 일치 |

| Test-SQL, Test-API, K-System 연동 | Business 이상 | 표기 일치 |
| 외부 DB 연동 | Business 이상, 초대앱만 | 표기 일치 |
| FlexSQL | 콘솔 메뉴 설명은 Start 이상, FlexSQL 쪽은 Business 이상 | [확인 필요] |
| 고객관리 | 콘솔 메뉴 설명은 Enterprise 이상, 고객관리 쪽은 Business 이상 초대앱 | [확인 필요] |
| 앱팩 | 앱팩 쪽은 Business 이상, 고객관리 쪽은 Enterprise 이상 | [확인 필요] |
| 링크앱팩, PC-Web 설정(Beta), 열린화면 탭 | Enterprise 이상 | 표기 일치 |
| 앱 가져오기(beta) | Enterprise 이상 초대앱 | 표기 일치 |
| 패키지설치 | Business 이상. 개발 메뉴 설명은 "Enterprise 이상은 패키지 기본 제공" | 둘 다 문서 표기 |
| 구글 시트, Firestore | 서비스 쪽에 표기 없음 | [확인 필요] |

메뉴가 안 보이거나 잠겨 있으면 워크스페이스 요금제를 플렉스튜디오 담당자에게 확인하세요.

## 5. 디버거

Studio 오른쪽 위 초록색 재생 버튼으로 엽니다. 화면은 디버거 환경 설정, 시나리오 정보, 디버깅화면, 실행 내역 확인창, 디버깅 도구 탭으로 나뉩니다.

- [앱 접속 정보]에서 앱, 앱팩, 테넌트, 사용자를 고르면 그 조건으로 실행합니다.
- 특정 사용자만 오류가 나면 그 사용자에게 디버그 권한을 주고 여기서 그 사용자를 고르세요.
- 최근 접속정보 3건을 다시 고르는 히스토리가 있습니다(2026-03 릴리즈).
- 톱니바퀴에는 [PC 스타일로 보기(BETA)], [모바일 헤더숨김], [로그인 여부]가 있습니다. [로그인 여부]는 공개앱용이고 기본값은 켜짐입니다.
- 실행 내역에는 Step 단위로 이벤트와 서비스가 찍히고, 이벤트 안 스크립트는 들여쓰기로 보입니다.
- 서비스로 보낸 데이터는 [Call Service]에 ParamBlock 으로, 받은 데이터는 [Service result]에 ResultBlock 으로 보입니다.

| 탭 | 언제 쓰나 | 쓰는 법 |
|---|---|---|
| 콘솔 | 변수, 섹터 값을 직접 볼 때 | 이 탭에서 바로 봅니다. F12 개발자 도구로 볼 때는 대상을 runtime 으로 바꿉니다 |
| 컬렉션 | 컬렉션 전체를 섹터 단위로 볼 때 | [Status of]로 상태별로 거릅니다. 컬렉션 키 복사 가능(2026-04 릴리즈) |
| 카테고리 | 카테고리별 섹터를 볼 때 | 카테고리가 없는 섹터는 나오지 않습니다 |
| Test-SQL | 쿼리 스크립트만 실행할 때 | 아래 설명 |
| Test-API | [API 연동] 모듈을 시험할 때 | 아래 설명 |

### Test-SQL

결과는 결과 영역에 보이지만 시나리오 데이터에는 영향을 주지 않습니다.
툴바에는 검색(저장된 FlexSQL 불러오기), 초기화, 실행, 외부 DB 사용 여부 체크박스가 있습니다.

1. 외부 DB 를 조회하면 [외부 DB 사용 여부]를 먼저 체크하세요. [확인 필요] 체크하지 않았을 때 어느 DB 에서 실행되는지는 문서에 없습니다.
2. 스크립트 영역에 쿼리를 쓰세요.
3. 파라미터 영역에 ParamBlock 을 JSON 이중 배열로 넣으세요.
4. [실행]을 누르고 결과 영역에서 실제 실행문과 결과를 보세요.

```sql
<% let sector = paramBlocks[0][0]; %>
SELECT * FROM CafeMenu WHERE Name LIKE <%=sector.name%>;
```

파라미터 영역 예: `[[{"name":"라떼"}]]`

- 바깥 배열은 블록 목록이고 안쪽 배열은 그 블록의 섹터 목록입니다.
- [확인 필요] 실행 내역의 ParamBlock 을 복사해 붙이는 방법은 Test-API 문서에만 있습니다. Test-SQL 에서는 직접 붙여 실행해 확인하세요.

### Test-API

- API/Module 선택: API 와 모듈을 고르고 Event Config Key 값을 넣습니다.
- ParamBlocks 입력: JSON 이중 배열로 넣습니다. 실행 내역에서 복사한 ParamBlock 을 붙여도 됩니다.
- Script 입력: 호출 전 가공은 Param Script, 응답 가공은 After Script 에 씁니다. [API 연동]에 저장한 스크립트를 불러옵니다.
- 오른쪽 버튼으로 호출하고 결과는 로그창에서 봅니다. 왼쪽 버튼은 Event Config Key 입력값을 지웁니다.

### 중단점으로 멈춰 보기

1. 멈추고 싶은 자리에 `console.log("--- Stop")` 을 넣으세요. 그다음 디버거를 실행하세요.
2. F12 콘솔에서 대상을 runtime 으로 바꾸세요. 찍힌 로그의 오른쪽 위치를 눌러 스크립트로 가세요.
3. 멈출 줄 번호를 눌러 중단점을 거세요. 그 이벤트를 다시 실행하세요. 로드 스크립트나 시작 이벤트면 브라우저를 새로고침하세요.
4. 멈춘 상태에서 콘솔에 변수나 컬렉션 이름을 입력해 값을 보세요.

- 디버거에서 난 서비스 오류는 [서비스오류로그]에 남지 않습니다. 팝업, 다른 시나리오 호출, 탭바 같은 f.Frame 계열은 디버거에서 동작하지 않으니 배포된 앱에서 확인하세요.

## 6. 자동 조회(FlexAutoQuery)

FlexSQL 을 직접 쓰지 않고 FlexDB 테이블을 조회, 저장, 수정, 삭제하는 서비스입니다.

- 대상 테이블은 카테고리를 연결하거나 수정할 때 [AI로 DB연결하기]로 만든 테이블뿐입니다.
- 그 밖의 테이블은 FlexSQL 서비스를 쓰세요.
- 자동 생성 테이블에는 DataSeq, CreateDate, CreateUserID, UpdateDate, UpdateUserID, TenantID 가 기본 컬럼으로 붙습니다.
- [FlexSQL 자동생성]으로 FlexSQL 을 만들 수 있습니다. 나중에 추가한 컬럼은 그 FlexSQL 과 연결이 끊기므로 FlexSQL 을 직접 고치세요.

| 설정 | 내용 |
|---|---|
| 시스템명, 카테고리(선택), 테이블명 | 대상 지정 |
| 서비스 유형 | 조회, 저장, 업데이트, 삭제 |
| 정렬 순서 설정 | 대상 컬럼명, 오름차순 또는 내림차순 |
| 검색(키워드) | 대상 컬럼명, Operator, 검색 키워드 컬렉션키. Operator 는 `=` `!=` `<` `<=` `>` `>=` `LIKE` `NOT LIKE` `IS NULL` `IS NOT NULL` |
| 검색(기간) | 시작일 컬렉션 키, 종료일 컬렉션 키 |
| 검색(작성자) | 호출한 사용자 ID 와 CreateUserID 를 비교 |

| 모듈 | 보내는 데이터 | 받는 데이터 |
|---|---|---|
| Query | 1번 블록의 첫 섹터를 조건으로 씁니다 | 조회 결과 |
| Save | 1번 블록의 모든 섹터를 저장. 컬럼명과 같은 키만 들어갑니다 | _SUID 포함 저장 결과 |
| Update | 1번 블록의 모든 섹터를 수정. 컬럼명과 같은 키만 바뀝니다 | _SUID 포함 수정 결과 |
| Delete | 1번 블록의 모든 섹터에 해당하는 데이터를 삭제 | 삭제한 데이터의 _SUID |

## 7. 구글 시트(GoogleSheet)

연결 준비 순서입니다.

1. Google Cloud 프로젝트를 만들고 Google Sheets API 를 사용 설정하세요.
2. 서비스 계정을 만들고 JSON 키를 받으세요.
3. 쓸 구글 시트를 그 서비스 계정 주소에 편집자 권한으로 공유하세요.
4. 고객 설정 페이지(문서 표기는 [DB/회원관리]의 [Data 연결 바로가기])를 열고 [시스템 정보]의 사용할 시스템에 GoogleService 를 추가하세요.
5. Service Account Key 에 JSON 키 파일을 올리고 저장하세요.

| 서비스 항목 | 넣을 값 |
|---|---|
| spreadsheet 아이디 | 시트 URL 의 `/spreadsheets/d/` 다음 값 |
| Sheet 명 | 시트 아래 탭 이름 |
| 기준 컬럼명 | 행을 찾는 키 컬럼. 수정과 삭제에도 값이 바뀌지 않습니다 |

- 첫 행 헤더부터 빈 행이 나오기 전까지를 한 테이블로 봅니다. 빈 행이나 빈 열 뒤 영역은 다른 테이블로 보고 쓰지 않습니다.
- 따로 관리하는 키가 없으면 `_SUID` 컬럼을 만들고 기준 컬럼으로 지정하세요. 값이 자동으로 채워집니다.

| 모듈 | 보내는 데이터 | 받는 데이터 |
|---|---|---|
| Query | 쓰지 않습니다 | 조회 데이터에 _rowIndex 를 붙여 돌려줍니다 |
| Append | 1번 블록에서 기준 컬럼 값이 있는 섹터를 행으로 추가 | _SUID, _rowIndex |
| Update | 1번 블록 섹터의 _rowIndex 와 기준 컬럼이 맞는 행을 수정 | _SUID, _rowIndex |
| Clear | 맞는 행에서 기준 컬럼 밖의 값만 지움 | _SUID, _rowIndex, 삭제 결과 |

- Clear 는 행을 없애지 않습니다. 행 전체 삭제는 구글 시트에서 직접 Delete Row 를 하세요. 이때 무결성은 보장되지 않습니다.
- Update, Clear 에는 Query 로 받은 _rowIndex 를 섹터에 그대로 두고 보내세요.
- 문서는 단순한 작업에 이 서비스를 쓰고, 더 복잡한 데이터 조작은 Firestore 서비스를 쓰라고 권합니다.

## 8. API 연동 화면

콘솔 [데이터]-[API 연동]에서 외부 API 를 모듈로 등록합니다.
왼쪽 API 및 모듈 리스트에서 +로 API 를 추가하고, 항목의 … 에서 모듈추가, 모듈 복사, 삭제를 합니다.
가운데 위 전환 패널로 [모듈 정의]와 [모듈 테스트]를 오가고, 아래 버튼영역에서 [배포]와 변경사항 취소를 합니다.

| 정의 탭 | 내용 |
|---|---|
| Method 및 URL | 요청 방식과 URL. 자동 URL 인코딩을 켜면 이미 인코딩된 값이 두 번 인코딩될 수 있습니다 |
| Params, Header | Key-Value. `{= }` 로 값을 끼워 넣습니다 |
| Advanced Key Setting | Event Config Key 는 `{=Event.키}`, Secret Key 는 `{=키}` |
| Body | `{=ParamBlocks}` 는 이중 배열. 문자열 자리는 `"{=ParamBlocks[0][0]}"` 처럼 따옴표로 감쌉니다 |
| Response | Response Body 는 `{=Result}` 또는 `[[{ "data": "{=Result.data}" }]]`. Custom Error Msg 에 `{=Result.errMsg}` 를 넣으면 그 값이 올 때 오류 팝업 |
| Script | ParamBlocks Convert Script(호출 전, ParamBlocks 를 return), Result Convert Script(호출 후, 반환 없이 결과를 고침) |

- [확인 필요] Result Convert Script 의 결과 변수 이름이 문서 설명은 `Result`, 예시는 `resultBlocks` 입니다. [모듈 테스트]의 afterScript ResultBlocks 로 확인하세요.
- [모듈 테스트]에서 Test Value 에 Event Config Key 값을, Test Param Blocks 에 이중 배열 JSON 을 넣고 호출하세요. Test Result 에서 API URL, Request Headers, Request Body, ResultBlocks, afterScript ResultBlocks 를 봅니다.

1. 모듈을 [배포]하세요.
2. Studio 이벤트에 API 서비스를 추가하고 시스템명과 모듈명을 고르세요.
3. Event Config Key 에 값을 넣으세요. 화면 값은 `{% %}` 대체 스크립트로 넘깁니다.
4. 그 서비스를 이벤트에 연결하세요.

치환 규칙과 시간 제한은 FlexSQL과 데이터 서비스 설명의 API 연동 절을 보세요.

## 9. 링크관리, 레이아웃관리, 서비스오류로그, 앱정보설정

### 링크관리(FlexLink)

1. [FlexLink 생성]에서 앱 시나리오를 검색해 고르세요.
2. 만들어진 짧은 URL 로 접속하면 그 시나리오가 열립니다.
3. 데이터를 넘기려면 URL 뒤에 `?linkParam=값` 을 붙이세요. 이미 `?` 뒤 파라미터가 있으면 `&linkParam=값` 을 붙이세요.
4. 영문 밖의 글자는 `encodeURIComponent(값)` 으로 인코딩하세요.

- 시나리오에서는 보통 첫 Step 의 Init 이벤트에서 `f.Link.getLinkParam()` 으로 값을 읽습니다. `_base.linkParam` 은 지원 종료 예정입니다.
- 다 쓴 뒤에는 `f.Link.init()` 으로 지우세요. 지우지 않으면 메뉴나 탭바로 화면을 옮겨도 계속 그 값을 씁니다.

### 레이아웃관리

바꾼 뒤 오른쪽 아래 [라이브에 적용]을 눌러야 사용자에게 보입니다.
[변경사항 취소]는 마지막 라이브 적용 시점으로 되돌립니다.

| 설정 | 내용 |
|---|---|
| 상단헤더 설정 | 사용 여부. 상단 제목은 시나리오(화면) 명, 직접입력, 로고 이미지 중 하나 |
| 상단 좌우 버튼 | 메뉴, 시작페이지, 로그아웃, 알림, 시나리오. 앞의 넷은 중복 불가. 로그아웃은 초대 기반 앱 전용 |
| 시작페이지 설정 | 처음 보일 화면. 시나리오, 메뉴리스트, URL 중 하나. 초대 기반 앱은 로그인 뒤 보입니다 |
| 알림 페이지 설정 | 알림 버튼이 열 시나리오 |
| 하단탭바 설정 | 사용 여부와 탭 버튼. 왼쪽부터 놓입니다 |
| 우측 메뉴 설정 | 사용 여부. 타입은 박스형 또는 트리형(그룹 사용 가능) |
| 다국어 설정-레이아웃 | 하단탭바와 우측 메뉴의 언어별 글자. 같은 이름도 영역마다 따로 등록합니다 |
| PC-Web 설정(Beta) | min-width, max-width(px), 로그인 배경 이미지 |

- [확인 필요] 메뉴와 시작페이지에서 고를 수 있는 시나리오가 앱에 추가한 것뿐인지는 문서에 없습니다. [레이아웃 관리]의 선택 목록에서 확인하세요.
- [앱 전환 기능 사용하기]를 켜면 같은 테넌트의 모든 앱이 하단에 보입니다. 초대 기반 앱 전용입니다.
- 전환해 들어올 앱의 [앱정보설정]에서 [다른 앱에서 이 앱으로 전환 허용 설정]도 켜세요.
- 에뮬레이터에서 초대 기반 앱끼리 전환하려면 먼저 로그인한 앱에서 로그아웃하세요.

### 서비스오류로그

- 라이브 앱의 서비스 오류를 2주 동안 최신순으로 보관합니다.
- 응답에 error 노드가 있어야 남습니다. 60초 안에 응답이 없던 호출은 남지 않습니다.
- 서비스 타입은 FlexSQL, Custom API, K-System 이 지원되고 API 연동, Firebase 는 추가 예정으로 적혀 있습니다.
- [에러내용]은 사용자가 본 메시지와 같습니다. [복사하기]와 [상세보기]로 전체 로그를 봅니다.

### 앱정보설정

- App 이름, 앱 아이콘(모바일 웹 파비콘), 로고, 테마색을 정합니다.
- 테마색은 시나리오에서 정해도 앱에서 [테마색 변경]으로 고르고 [라이브에 적용]해야 앱에 보입니다.
- [앱 삭제]는 영구 삭제이고 백업과 복원은 없습니다.
- [확인 필요] 2026-04 릴리즈의 앱 복사 생성과 2026-07 릴리즈의 앱 수정 승인(일부 워크스페이스 우선 적용)은 릴리즈 노트에만 있습니다. 화면 위치는 docs.flextudio.com 릴리즈 노트나 담당자에게 확인하세요.
