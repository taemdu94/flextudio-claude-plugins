# 공식 문서 세부: Firestore, 스텝 이동 타입, 권한키 관리 외
이 파일이 답하는 질문: Firestore 서비스는 어떻게 연결하고 무엇을 할 수 있나 / 스텝 버튼의 스텝 이동 타입은 각각 어떻게 움직이나 / 권한키를 만들고 컨트롤과 사용자에 거는 순서는 / 권한키를 스크립트로 확인하거나 더하는 방법은 / 공식 문서에 적힌 화면 글자와 함수 인자

목차
1. Firestore 서비스
2. 스텝 버튼의 스텝 이동 타입
3. 권한키 관리
4. 공식 문서로 확인된 화면 글자와 함수 인자

쓰는 법
- 공식 문서(docs.flextudio.com/flextudio)에만 있는 세부를 모았습니다.
  다른 참조 파일에 있는 기본 설명은 반복하지 않습니다.
- 화면 글자는 공식 문서 표기를 그대로 [대괄호]로 적었습니다.
  실제 화면이 개편돼 글자가 다르면 화면을 따르고, 다르다는 사실을 알려 주세요.
- 함수 인자와 반환값은 공식 함수 명세 기준입니다.
  예외 동작은 디버거에서 한 번 실행해 확인하게 하세요.

## 1. Firestore 서비스

### 1-1. Firestore 를 연결하려면 무엇이 필요한가요
결론: Firebase 프로젝트의 서비스 계정 비공개 키 파일 하나가 필요합니다.
이 키를 고객 설정 페이지의 시스템 정보에 올리면 시나리오에서 Firestore 서비스를 쓸 수 있습니다.
할 일:
1. Firebase 콘솔에서 프로젝트를 만드세요.
2. 프로젝트 설정의 서비스 계정 화면에서 새 비공개 키를 만들어 JSON 파일을 받으세요.
3. 고객 설정 페이지(문서 표기는 [DB/회원관리]의 [Data 연결 바로가기])를 여세요.
4. [시스템정보]의 사용할 시스템에 FireBaseService 를 추가하세요.
5. [Admin Private Key]에 받은 키 파일을 올리고 저장하세요.
확인: Studio 서비스 등록 화면의 [시스템명] 목록에 Firestore 시스템이 보이면 연결된 것입니다.
- 비공개 키 파일은 DB 전체 권한을 가집니다.
  메일이나 메신저로 돌리지 말고 올린 뒤에는 안전한 곳에 보관하세요.
- 공식 문서 "Firestore 연동" 페이지에 연결해 둔 샘플 시나리오 링크가 있습니다.
  처음이면 그 샘플을 먼저 열어 보세요.

### 1-2. Firestore 서비스 화면에는 어떤 항목이 있나요
결론: 공통 항목은 [시스템명], [모듈명], [Firestore 컬렉션] 세 가지이고, 모듈은 Query, Save, Update, Delete 네 가지입니다.

| 항목 | 넣을 값 |
|---|---|
| [시스템명] | 고객 설정에서 추가한 Firestore 시스템 |
| [모듈명] | Query(조회), Save(저장), Update(수정), Delete(삭제) 중 하나 |
| [Firestore 컬렉션] | 작업할 Firestore 컬렉션 이름 |

- 여기서 컬렉션은 Firestore 쪽 문서 묶음 이름입니다.
  플렉스튜디오 화면의 컬렉션(카테고리, 섹터)과 다른 개념입니다.
- Firestore 에 컬렉션을 미리 만들지 않아도 됩니다.
  서비스가 요청한 컬렉션은 처음 저장할 때 자동으로 생깁니다.

### 1-3. Query 에서 정렬과 조건 검색은 어떻게 거나요
결론: [정렬 순서 설정]에서 기준 필드와 방향을, [검색]에서 필드, 연산자, 비교 값을 가진 컬렉션 키를 지정합니다.

| 설정 | 항목 | 설명 |
|---|---|---|
| [정렬 순서 설정] | [대상필드명], [정렬순서] | 기준 필드 하나와 오름차순 또는 내림차순 |
| [검색] | [필드 명] | 조건을 걸 Firestore 필드 |
| [검색] | [Operator] | `==` `!=` `<` `<=` `>` `>=` |
| [검색] | [필드값 컬렉션 키] | 비교할 값이 든 컬렉션 키 |

- 비교 값은 [보내는 데이터] 1번 블록의 첫 섹터에서 [필드값 컬렉션 키]로 꺼냅니다.
- LIKE 같은 부분 일치 연산자는 목록에 없습니다.
  부분 검색이 필요하면 조회 뒤 스크립트에서 걸러 내세요.
- 정렬과 검색을 함께 쓰면 Firestore 쪽에 복합 색인이 필요합니다.
할 일: 정렬과 검색을 같이 쓴 조회가 실패하면 Firebase 콘솔의 Firestore 색인 화면에서 해당 필드 조합의 색인을 등록하세요.
확인: 색인 상태가 사용 가능으로 바뀐 뒤 디버거에서 같은 조회를 다시 실행해 결과가 오는지 보세요.

### 1-4. Update 에서 일부 필드만 바꾸거나 숫자를 1 올리고 싶습니다
결론: [Update 타입]을 [부분 수정]으로 두고, 필드마다 [Update Value 타입]을 고르세요.
숫자 증감과 필드 삭제는 FieldValue 함수로 처리합니다.

| 설정 | 선택지 | 동작 |
|---|---|---|
| [Update 타입] | [전체 수정] | 보낸 데이터로 문서 전체를 덮어씁니다 |
| [Update 타입] | [부분 수정] | 지정한 필드만 바꿉니다 |
| [Update Value 타입] | [컬렉션키] | [필드 값 컬렉션 키]에 지정한 키의 값으로 바꿉니다 |
| [Update Value 타입] | [FieldValue 함수] | [필드 값 함수]의 increment(1), increment(-1), delete() 중 하나를 씁니다 |

- increment(1) 은 1 증가, increment(-1) 은 1 감소, delete() 는 그 필드를 문서에서 지웁니다.
- 조회수, 좋아요 수처럼 여러 사람이 동시에 올리는 숫자는 increment 를 쓰세요.
  화면에서 더한 값으로 덮어쓰면 다른 사람이 같은 때 올린 횟수가 빠질 수 있습니다.
- [전체 수정]은 보낸 데이터로 문서를 덮어씁니다.
  화면에 없는 필드가 문서에 있으면 [부분 수정]을 쓰세요.
[확인 필요] 덮어쓸 때 보내지 않은 필드가 지워지는지는 공식 문서에 적혀 있지 않습니다.
시험 문서 하나로 Firebase 콘솔에서 확인하세요.

### 1-5. 모듈마다 무엇을 보내고 무엇을 돌려받나요
결론: 네 모듈 모두 [보내는 데이터]의 1번 블록(ParamBlock1)을 씁니다.
Query 만 첫 섹터 하나를 쓰고 나머지는 모든 섹터를 처리합니다.

| 모듈 | 보내는 데이터 | 받는 데이터 |
|---|---|---|
| Query | 1번 블록 첫 섹터를 검색 조건으로 씁니다 | 조회된 문서 목록 |
| Save | 1번 블록 모든 섹터를 새 문서로 저장합니다 | _SUID 를 포함한 저장 결과 |
| Update | 1번 블록 모든 섹터를 조건에 맞게 수정합니다 | _SUID 를 포함한 수정 결과 |
| Delete | 1번 블록 모든 섹터에 해당하는 문서를 지웁니다 | 지운 문서의 _SUID |

- Save 는 매번 새 문서를 만듭니다.
  같은 행을 다시 Save 하면 문서가 하나 더 생깁니다.
  기존 문서를 바꿀 때는 Update 를 쓰세요.
[확인 필요] Update 와 Delete 가 섹터의 어떤 값으로 대상 문서를 찾는지는 공식 문서에 적혀 있지 않습니다.
디버거에서 조회한 섹터를 그대로 보내 바뀐 문서를 Firebase 콘솔에서 확인하세요.
- 두 컬렉션을 잇는 관계(예: 약속과 약속 옵션)는 자식 문서에 부모 문서의 ID 를 필드로 저장해 연결합니다.
  조인은 없으므로 부모를 조회한 뒤 자식을 한 번 더 조회하세요.

### 1-6. Firestore 서비스로 할 수 없는 것
결론: 아래는 공식 문서의 Firestore 서비스 설정 항목에 없는 기능입니다.

| 하고 싶은 것 | 지원 | 대안 |
|---|---|---|
| 부분 일치(LIKE) 검색 | 지원하지 않습니다 | 조회 뒤 스크립트에서 거르세요 |
| 컬렉션끼리 조인 | 지원하지 않습니다 | 부모 조회 뒤 자식 조회를 이어서 부르세요 |
| 하위 컬렉션 경로 지정 | [확인 필요] 문서에 설명이 없습니다 | 최상위 컬렉션과 ID 필드로 설계하세요 |
| 요금제별 사용 가능 여부 | [확인 필요] 문서에 표기가 없습니다 | 플렉스튜디오 담당자에게 확인하세요 |

Firestore 자체의 무료 한도와 요금은 Google Firebase 기준입니다.
운영 전에 Firebase 요금 안내를 확인하세요.

## 2. 스텝 버튼의 스텝 이동 타입

### 2-1. 스텝 버튼의 [스텝 이동 타입]에는 무엇이 있나요
결론: 공식 문서 기준으로 다섯 가지입니다.
스텝 버튼은 스크롤과 관계없이 스텝 아래에 고정되는 버튼입니다.

| [스텝 이동 타입] | 누르면 | 추가로 고를 항목 |
|---|---|---|
| [안함] | 이동하지 않습니다 | [클릭 이벤트명] |
| [시작스텝] | 시작 스텝으로 갑니다 | [스텝 이동 직전 실행할 이벤트명] |
| [다음스텝] | 다음 스텝 또는 지정한 스텝으로 갑니다 | 이동 직전 이벤트, [필수값 체크 무시], [이동 스텝 추가] |
| [직전스텝 - 마지막 상태] | 직전 스텝으로 돌아가며 Init 을 다시 실행하지 않습니다 | 위 세 가지와 [컬렉션 이전 상태로 복원하기] |
| [직전스텝 - 새로 시작] | 직전 스텝으로 돌아가 Init 부터 다시 실행합니다 | [직전스텝 - 마지막 상태]와 같습니다 |

- 저장 버튼처럼 이동 없이 이벤트만 실행하려면 [안함]을 고르고 [클릭 이벤트명]에 이벤트를 연결하세요.
- 디자인 모드에서는 [버튼명]과 [사이즈고정]을 정합니다.
- 그룹과 버튼 컨트롤의 [클릭 시 스텝 이동]도 같은 이동 타입 설명을 따릅니다.

### 2-2. 목록으로 돌아갔을 때 다시 조회되게 하려면 어떤 타입을 고르나요
결론: 돌아간 화면을 처음부터 다시 그리려면 [직전스텝 - 새로 시작], 입력하던 상태 그대로 두려면 [직전스텝 - 마지막 상태]를 고르세요.
할 일:
1. 목록 스텝의 Init 에 조회가 있고 돌아갈 때마다 새로 조회해야 하면 [직전스텝 - 새로 시작]을 고르세요.
2. 목록의 스크롤과 입력값을 지키면서 일부만 다시 읽으려면 [직전스텝 - 마지막 상태]를 고르고, 목록 스텝의 [뒤로가기로 돌아올 때] 이벤트에 조회를 두세요.
확인: 상세에서 값을 바꾸고 돌아왔을 때 목록에 바뀐 값이 보이면 됩니다.

### 2-3. [이동 스텝 추가]로 직전 스텝이 아닌 곳으로 돌아가려는데 안 됩니다
결론: 직전스텝 타입에서 지정하는 스텝은 이번 실행 중에 지나온 스텝이어야 합니다.
한 번도 열지 않은 스텝은 직전스텝 타입으로 갈 수 없습니다.
할 일:
1. 지나오지 않은 스텝으로 가려면 [다음스텝] 타입에 [이동 스텝 추가]로 그 스텝을 지정하세요.
2. 맨 처음 화면으로 가려면 [시작스텝]을 고르세요.

### 2-4. 같은 이동을 스크립트로 하려면
결론: 버튼 타입과 같은 동작을 아래 함수로 부를 수 있습니다.
참, 거짓 인자는 따옴표 없이 씁니다.

| 버튼 타입 | 스크립트 |
|---|---|
| [다음스텝] | `Current.step.moveToNext('<스텝ID>', <필수값무시>, '<애니메이션>')` |
| 직전 스텝으로 | `Current.step.moveToPrev('<스텝ID>', <컬렉션복원>, <필수값검사>)` |
| [시작스텝] | `Current.step.moveToFirst()` |
| Init 부터 다시 | `Current.step.restart()` |

```javascript
// 필수값 검사를 건너뛰고 Step2 로 가면서 오른쪽에서 들어오는 효과를 씁니다
Current.step.moveToNext('Step2', true, 'toRight');
```
- 애니메이션 값은 `toRight`(우측에서 등장), `toLeft`(좌측에서 등장), `withDissolve`(밝기 변화) 세 가지입니다.
- moveToPrev 의 두 번째 인자는 [컬렉션 이전 상태로 복원하기]와 같고, 세 번째 인자는 필수값 검사 사용 여부입니다.

### 2-5. 서브시나리오 안에서 [시작스텝]을 누르면 어디로 가나요
결론: 서브시나리오를 부르는 스텝의 [Init(처음)으로 돌아갈 시나리오] 설정이 정합니다.

| 선택 | [시작스텝]을 누르면 |
|---|---|
| [최상위 시나리오] | 맨 처음 실행한 시나리오의 시작 스텝 |
| [현재 시나리오] | 서브시나리오를 부른 시나리오의 시작 스텝 |
| [서브 시나리오] | 불려 온 서브시나리오의 시작 스텝 |

메뉴 첫 화면까지 한 번에 돌아가야 하면 [최상위 시나리오]를 고르세요.

## 3. 권한키 관리

### 3-1. 권한키를 만들고 화면에 거는 전체 순서는
결론: 콘솔에서 만들고, 시나리오의 컨트롤에 걸고, 배포해 라이브에 적용한 뒤, 고객 설정에서 사용자나 그룹에 줍니다.
할 일:
1. 콘솔 [개발]-[권한키관리]의 [새 권한키]에 권한키와 권한명을 넣어 만드세요.
   권한명은 한글도 쓸 수 있습니다.
2. 시나리오를 열고 편집하기를 누르세요.
3. 개발 모드에서 대상 컨트롤을 고르고 [권한키] 칸에서 권한키를 검색해 고르세요.
4. 저장과 배포를 누르세요.
5. 콘솔 시나리오 관리에서 그 시나리오를 최신 버전으로 올리고 [라이브에 적용]을 누르세요.
6. 고객 설정 페이지의 [사용자별 권한관리] 또는 [그룹별 권한관리]에서 권한키를 주세요.
확인: 권한키가 없는 사용자로 앱에 들어가 그 컨트롤이 보이지 않으면 됩니다.
- 앱에 배포되지 않은 권한키는 [사용자별 권한관리]의 [권한키 적용] 목록에 나오지 않습니다.
- 권한명은 등록한 권한키 목록에서 고친 뒤 Enter 를 눌러 저장합니다.

### 3-2. 권한키를 지우거나 고칠 수 없습니다
결론: 한 곳이라도 쓰고 있는 권한키는 수정과 삭제가 막힙니다.
목록의 열쇠 그림과 숫자가 쓰고 있는 곳의 수입니다.

| 상세보기 표시 | 쓰고 있는 곳 |
|---|---|
| 레이아웃/탭바 | 앱 설정의 레이아웃이나 탭바 |
| 라이브 | 라이브에 적용된 시나리오 |
| 사용중 | 라이브가 아닌 이전 버전 시나리오 |
| 편집중 | 아직 라이브에 적용하지 않은 작업 중 시나리오 |

할 일: 상세보기에서 쓰는 곳을 확인하고 그 시나리오와 레이아웃에서 권한키를 모두 뺀 뒤 다시 삭제하세요.
- 사용중 상태는 어느 버전인지 보여 주지 않습니다.
  이전 버전에 남아 있으면 시나리오 버전 목록을 하나씩 확인하세요.

### 3-3. 시나리오에 건 권한키를 한눈에 보고 싶습니다
결론: Studio 하단 패널의 Authkey 탭이 이 시나리오에 건 권한키 목록을 보여 줍니다.
- 이 탭에서 [권한키관리]에 등록된 권한키를 바로 추가하거나 지울 수 있습니다.
- 목록이 늦게 바뀌면 리로드 버튼을 누르세요.
  권한키관리 페이지로 가는 버튼도 있습니다.

### 3-4. 앱 메뉴나 탭바를 사람마다 다르게 보이게 하고 싶습니다
결론: 앱 레이아웃 관리에서 권한 사용을 체크하고 권한키를 추가한 뒤 [라이브에 적용]을 누르세요.
확인: 권한키가 없는 사용자 화면에서 그 메뉴나 탭이 사라지면 됩니다.

### 3-5. 스크립트로 권한키를 확인하거나 잠깐 더하고 싶습니다
결론: 사용자 권한키는 `f.Auth` 함수로, 컨트롤 권한키는 로드 스크립트의 `Load.control.authkey` 로 다룹니다.

| 함수 | 동작 |
|---|---|
| `f.Auth.check('<권한키>')` | 있으면 true, 없으면 false 를 돌려줍니다 |
| `f.Auth.list()` | 사용자가 가진 권한키 배열을 돌려줍니다 |
| `f.Auth.add('<권한키>')` | 사용자에게 권한키를 더합니다. 지금 시나리오 안에서만 유효합니다 |
| `f.Auth.remove('<권한키>')` | 사용자에게서 권한키를 회수합니다 |
| `Load.control.authkey.add('<권한키>')` | 로드 스크립트 전용. 이 컨트롤에 권한키를 겁니다 |
| `Load.control.authkey.remove('<권한키>')` | 로드 스크립트 전용. 이 컨트롤의 권한키를 뺍니다 |

```javascript
// 반복 목록 안 라벨의 로드 스크립트: 비공개 행이면 이 라벨에 관리자 권한키를 겁니다
// 권한키가 걸린 컨트롤은 그 권한키를 가진 사용자에게만 보입니다
if (Load.sector.<비공개여부키> === 'Y') {
  Load.control.authkey.add('<관리자권한키>');
}
```
- `f.Auth.add` 로 더한 권한키는 지금 시나리오 안에서만 유효하고 콘솔의 권한 부여는 바뀌지 않습니다.
  계속 쓸 권한은 고객 설정에서 주세요.
- `Load.control.authkey` 를 쓸 수 있는 컨트롤은 InputText, InputNumber, InputMask, TextArea, InputDate, Label 입니다.

## 4. 공식 문서로 확인된 화면 글자와 함수 인자

### 4-1. f.MessageBox 버튼 함수의 이름과 세 번째 인자
결론: 공식 함수 명세의 이름은 `addBtn(title, eventName)` 이고, 세 번째 인자 color 는 버튼을 회색으로 칠할지 정하는 참, 거짓 값입니다.
```javascript
let msgBox = f.MessageBox('Alert').setTitle('<제목>');
msgBox.addBtn('확인', '<저장이벤트>');
msgBox.addBtn('취소', null, true); // 회색 버튼, 이벤트 없음
msgBox.show();
```
- 버튼은 여러 개 더할 수 있고, 메시지 박스 유형은 Completed, Error, Alert 세 가지입니다.

### 4-2. 그룹 [데이터 용도]의 화면 글자
결론: 공식 문서 표기는 [기본], [신규 입력], [조회], [상세 보기], [수정] 다섯 가지입니다.
한 건만 보여 주는 상세 카드는 [상세 보기]를 고르세요.
- 데이터 연결을 한 그룹은 reload 할 수 없습니다.
  같은 아이디의 그룹이 여러 개 생기기 때문입니다.
  부모 그룹이나 스텝을 다시 그리세요.
- 카테고리 이름은 숫자만으로 지을 수 없습니다.

### 4-3. 크기가 줄어들지 않게 하는 설정의 화면 글자
결론: 그룹의 [사이즈 고정]입니다.
부모 그룹이 배치 속성을 쓸 때만 켤 수 있습니다.

### 4-4. 스텝 이벤트의 화면 글자
결론: 공식 문서의 스텝 이벤트는 [최초 시작 전(Init)], [로드 시 (Loaded)], [뒤로가기로 돌아올 때], [다음으로 이동 전], [앱에 다시 돌아올 때], ScrollEnd 여섯 가지입니다.
- ScrollEnd 는 한글 이름 없이 그대로 표시되며, 스크롤이 끝까지 내려갔을 때 실행됩니다.
- [앱에 다시 돌아올 때]는 모바일 앱에서만 실행됩니다.

### 4-5. 서브시나리오 호출 설정의 화면 글자
결론: 공식 문서 표기는 아래와 같습니다.
화면이 다르게 보이면 화면을 따르세요.

| 공식 문서 표기 | 하는 일 |
|---|---|
| [서브 시나리오로 현재 컬렉션 전달] | 현재 컬렉션을 서브시나리오로 복사합니다 |
| [서브 시나리오의 컬렉션으로 대체하기] | 돌아올 때 서브시나리오의 컬렉션으로 바꿉니다. 끄면 호출 직전 상태로 돌아옵니다 |
| [호출한 시나리오로 돌아가기 허용] | 서브시나리오에서 뒤로가기 버튼을 켭니다 |
| [서브 시나리오 로드 스크립트] | 서브시나리오가 로드된 뒤 실행할 스크립트입니다 |
