## 1. 어떤 서비스를 쓸까
| 하고 싶은 일 | 쓰는 서비스 | 데이터가 있는 곳 |
|---|---|---|
| ERP 데이터를 SP 로 읽고 쓰기 | K-System 연동 | 고객사 ERP DB, service-ksystem-sp.md 참고 |
| SQL 을 직접 써서 읽고 쓰기 | FlexSQL | FlexDB 또는 외부 DB(MySQL, MSSQL) |
| SQL 없이 테이블 하나를 저장, 조회, 삭제 | 자동 조회(FlexAutoQuery) | FlexDB |
| 외부 REST API 호출 | API 연동 | 외부 서버 |
| 파일 올리기, 내려받기 | 파일 서비스(FlexFile) | 플렉스튜디오 파일 저장소 |

## 2. FlexSQL 기본
FlexSQL 은 SQL 안에 자바스크립트 표현식(EJS)을 섞어 쓰는 서비스입니다.
이벤트의 [보내는 데이터]는 스크립트 안에서 `paramBlocks` 변수로 꺼냅니다.
`paramBlocks` 는 이중 배열입니다(블록 배열 안에 행 배열).
첫 블록의 첫 행 값은 `paramBlocks[0][0].<키>` 로 읽습니다.

| 표현식 | 하는 일 |
|---|---|
| `<% 자바스크립트 %>` | 변수 선언, 조건, 반복으로 SQL 조각을 고릅니다. 결과에 글자를 남기지 않습니다 |
| `<%= 값 %>` | 값을 작은따옴표로 감싸서 넣습니다. 값 안의 `'` `"` `\` `%` `_` 앞에 `\` 를 붙입니다 |
| `<%- 값 %>` | 값을 작은따옴표로 감싸서 넣습니다. `'` `"` 앞에만 `\` 를 붙이고 `\` `%` `_` 는 그대로 둡니다 |

조회 예제입니다(MySQL, FlexDB 용).

```sql
<% let block = paramBlocks[0]; %>
<% if (block[0] && block[0].<검색키>) { %>
SELECT DataSeq, <컬럼명> AS <카테고리키>
  FROM <테이블명>
 WHERE <컬럼명> LIKE CONCAT('%', <%= block[0].<검색키> %>, '%');
<% } %>
```

이 코드가 하는 일:
첫 블록 첫 행에 검색어가 있을 때만 SELECT 를 만듭니다.
검색어는 `<%= %>` 로 넣어 `%` `_` 가 글자 그대로 검색됩니다.

| 바꿀 값 | 넣을 것 |
|---|---|
| `<검색키>` | 보내는 데이터의 카테고리 키 |
| `<테이블명>`, `<컬럼명>` | FlexDB 의 실제 이름 |
| `<카테고리키>` | 결과를 받을 카테고리의 키. SELECT 별칭과 글자가 같아야 합니다 |

## 3. FlexSQL 에 값 넣는 규칙
`<%= %>` 와 `<%- %>` 는 둘 다 값에 작은따옴표를 자동으로 붙입니다.
SQL 에 따옴표를 또 쓰지 마세요.
`'<%= 값 %>'` 처럼 쓰면 따옴표가 겹쳐 값이 깨지거나 UPDATE 가 0건이 됩니다.
SQL 문자열 상수(`'신청'`)와 SQL 함수 안의 글자는 직접 따옴표를 씁니다.

| 넣는 값 | 결과 SQL |
|---|---|
| 숫자 `5` | `'5'` (숫자도 따옴표로 감쌉니다) |
| null 또는 undefined | `null` (따옴표 없음) |
| 객체, 배열 | JSON 문자열 |

`<% %>` 안에서 직접 이어 붙여 만든 문자열은 예상과 다르게 들어갈 수 있습니다.
실행문 미리보기로 만들어진 SQL 을 꼭 확인하세요.

밑줄(`_`) 처리 규칙입니다.

| 용도 | 쓰는 표현식 | 이유 |
|---|---|---|
| INSERT, UPDATE 할 값 | `<%- %>` | `<%= %>` 로 넣으면 `Erp_03` 이 `Erp\_03` 으로 저장됩니다 |
| `=` 비교 조건 값 | `<%- %>` | `<%= %>` 로 넣으면 `\_` 때문에 0건이 됩니다 |
| LIKE 검색어 | `<%= %>` | `%` `_` 가 와일드카드가 아니라 글자로 검색됩니다 |

`<%- %>` 도 작은따옴표와 큰따옴표는 막지만 `\` 는 막지 않습니다.
사용자가 직접 입력한 값은 길이와 형식을 이벤트 스크립트에서 먼저 검사하세요.
테이블 이름이나 정렬 방향(ASC, DESC) 같은 SQL 조각은 어느 표현식으로도 넣을 수 없습니다.
조각이 바뀌어야 하면 `<% if %>` 로 SQL 을 갈라 쓰세요.
[확인 필요] 외부 MSSQL 에서 작은따옴표가 든 값(`O'Brien`)은 오류가 날 수 있으니 실행문 미리보기로 만들어진 SQL 을 확인하세요.

## 4. FlexSQL 금지 사항과 실행 제한
| 규칙 | 지키지 않으면 |
|---|---|
| 스크립트 어디에도 소문자 `return` 글자를 쓰지 마세요. 컬럼 이름, 주석, 문자열 상수도 포함입니다 | `checking your SQL Script. (It cannot contain a return.)` |
| 연결한 DB 종류의 탭(MySQL, MSSQL)에 스크립트를 쓰세요. 스크립트는 탭마다 따로 저장됩니다 | `checking your SQL Script.` |
| `<% %>` 안 자바스크립트는 짧게 끝나게 쓰세요. 큰 반복은 시간 초과로 멈춥니다 | 시간 초과 오류 |

`returnDate` 처럼 이름에 return 이 든 컬럼은 이름을 바꾸는 것이 가장 확실합니다.
대문자 `RETURN` 은 검사에 걸리지 않습니다.
[확인 필요] MySQL 은 컬럼 이름의 대소문자를 가리지 않으므로 `RETURNDATE` 로 써도 될 수 있습니다.
실행문 미리보기와 Test-SQL 로 결과를 확인하세요.

여러 문장을 하나로 묶어 실패 시 모두 되돌리는 트랜잭션은 외부 DB 가 MySQL 이고 공통 트랜잭션을 쓸 때만 서버가 걸어 줍니다.
FlexDB 와 외부 MSSQL 에서는 서버가 트랜잭션을 걸지 않습니다.
앞 문장이 성공하고 뒤 문장이 실패하면 앞 문장의 변경은 남습니다.
[확인 필요] FlexDB 스크립트에 `START TRANSACTION`, `COMMIT` 을 직접 쓰는 방식은 아직 확인되지 않았습니다.
쓰려면 Test-SQL 로 실패 상황을 먼저 시험하세요.

## 5. FlexSQL 결과 모양
받는 데이터의 블록 순서는 스크립트 안 SELECT 순서와 같습니다.
SELECT 가 두 개면 [받는 데이터] 1번, 2번 블록에 차례로 들어갑니다.
SELECT 컬럼 별칭은 받을 카테고리의 키와 글자가 같아야 합니다.
INSERT 나 UPDATE 만 하고 SELECT 가 없으면 화면에 반영할 결과가 없습니다.
저장 후 화면을 갱신하려면 스크립트 끝에 SELECT 를 하나 두세요.

설계할 때 지키면 오류가 줄어드는 규칙입니다.

1. 한 SQL 서비스에는 한 가지 일만 넣으세요. INSERT 와 UPDATE 분기를 섞지 않습니다.
2. 확인용 SELECT 를 INSERT, UPDATE 와 한 호출에 섞지 마세요.
3. PK 는 INT 자동 증가 컬럼으로 만드세요.
4. 화면이 쓰는 `_SUID` 는 화면 메모리용 임시 키입니다. DB 에 저장하지 마세요.
5. 부모 행을 넣고 자식 행에 부모 키를 쓸 때는 MySQL 의 `LAST_INSERT_ID()` 를 쓰세요.

## 6. FlexSQL 반영과 확인 방법
새로 만들거나 고친 SQL 서비스는 발행해야 시나리오에서 실행됩니다.

1. 워크스페이스 콘솔의 [데이터] 메뉴에서 FlexSQL 화면을 열고 스크립트를 저장하세요.
2. 처음이면 [새 버전 발행]을 누르세요.
3. 이미 발행한 서비스를 고쳤으면 [현재버전으로 변경내역 반영] 또는 [새 버전 발행]을 누르세요.
4. 시나리오의 FlexSQL 서비스에서 SQL Script Version 값을 확인하세요. 0 이면 가장 최신 버전이 실행됩니다.
5. 시나리오도 고쳤다면 시나리오 배포와 [라이브에 적용]까지 하세요(build-and-deploy.md 참고).

확인 방법입니다.

| 도구 | 보이는 것 |
|---|---|
| 실행문 미리보기 | 표현식을 평가한 뒤 실제로 실행될 SQL |
| 디버거의 Test-SQL | 입력값으로 실행한 결과. 입력값이 이전 값으로 남아 있으니 실행 전에 확인하세요 |
| 디버거(디버그 실행) | 서비스 결과와 함께 실제 실행된 SQL 이 보입니다 |

값이 이상하면 이 순서로 보세요: DB 를 직접 SELECT → 실행문 미리보기 → Test-SQL 입력값 → 시나리오의 [보내는 데이터] 설정 → 화면 카테고리 값

## 7. FlexSQL 오류표
| 보이는 것 | 원인 | 조치 |
|---|---|---|
| `checking your request param.` | 서비스 이름, 버전이 없거나 그 버전의 스크립트가 없음 | 발행 여부와 SQL Script Version 을 확인하세요 |
| `checking your Token.` | 세션이나 디버그 토큰이 만료됨 | 다시 로그인하거나 디버거를 다시 여세요 |
| `checking your DBMS Info.` 또는 `dbInfo not found` | 테넌트에 DB 연결 정보가 없음 | 외부 DB 라면 테넌트 시스템 정보 등록을 확인하세요 |
| `checking your SQL Script.` | 연결 DB 종류 탭의 스크립트가 비어 있음 | 맞는 탭에 스크립트를 쓰고 발행하세요 |
| `checking your SQL Script. (It cannot contain a return.)` | 스크립트에 소문자 return 글자가 있음 | 컬럼 이름, 주석까지 찾아 지우세요 |
| `The corresponding script does not exist.` | 조건 때문에 만들어진 SQL 이 빈 문자열임 | 실행문 미리보기로 `<% if %>` 조건을 확인하세요 |
| `DBMS Query Error :…` | DB 가 돌려준 SQL 오류 원문 | 뒤의 원문을 읽고 미리보기 SQL 을 DB 에서 직접 실행해 보세요 |
| `DBMS Query Transaction Error :…` | 외부 MySQL 의 커밋이나 롤백 실패 | 원문 메시지로 DB 쪽 원인을 확인하세요 |
| 실행은 되는데 화면에 값이 없음 | SELECT 별칭과 카테고리 키가 다르거나, 받는 카테고리 이름이 컨트롤에 연결한 카테고리와 다름 | 별칭과 카테고리 이름을 글자 그대로 맞추세요 |

## 8. FlexDB 와 외부 DB
FlexDB 는 플렉스튜디오가 제공하는 MySQL 기반 DB 입니다.
외부 DB 는 고객사가 가진 DB(MySQL, MSSQL)를 연결해 쓰는 방식입니다.
DB 연결 정보는 앱이 아니라 테넌트의 [시스템 정보]에 있습니다.
같은 앱도 접속한 테넌트가 다르면 다른 DB 를 봅니다.

| 주제 | 규칙 |
|---|---|
| 외부 DB 주소 | 내부 IP 는 쓸 수 없습니다. 공인 IP 여야 합니다 |
| 외부 DB 를 쓰는 앱 | 초대기반앱만 지원합니다 |
| MSSQL 탭 사용 | 시나리오의 FlexSQL 서비스에 외부 DB 연결 설정이 필요합니다 |
| FlexDB 자동 생성 저장 SQL 의 TenantID | 값은 `fBaseCompanyID` 입니다. `sector.TenantID` 로 쓰면 새 행에서 undefined 가 됩니다 |
| FlexDB 컬럼 삭제 | 할 수 있습니다. 다른 테이블이 참조 중이면 막힙니다 |
| FlexDB 테이블 삭제 | 목록에서만 빠지고 실제 테이블은 남습니다 |

외부 DB 접속이 "접속정보가 유효하지 않습니다" 로 실패하면 주소가 공인 IP 인지 먼저 확인하세요.
고객관리의 사용자, 권한 데이터는 플랫폼 서버에 저장되므로 SQL 로 조회할 수 없습니다.
사용자 정보가 필요하면 Flextudio API 의 User 서비스를 쓰세요.
FlexDB 와 FlexSQL 을 쓸 수 있는 요금제는 담당자에게 확인하세요.

## 9. 자동 조회(FlexAutoQuery)
자동 조회는 SQL 없이 FlexDB 테이블 하나를 저장, 조회, 삭제하는 서비스입니다.
메서드 이름은 save, query, delete 입니다.
FlexDB 에서만 동작합니다.
FlexDB 연결이 없으면 `FlexDB 연결이 필요한 화면입니다.` 가 나옵니다.
[보내는 데이터]는 첫 번째 블록만 씁니다.

테이블에 아래 컬럼이 있어야 합니다.

| 컬럼 | 역할 |
|---|---|
| DataSeq | 자동 증가 키. 저장할 때 UPDATE 와 INSERT 를 가르는 기준입니다 |
| TenantID | 테넌트 구분. save 가 자동으로 채웁니다 |
| CreateDate, CreateUserID | 만든 시각과 사람. save 가 자동으로 채웁니다 |
| UpdateDate, UpdateUserID | 고친 시각과 사람. save 가 자동으로 채웁니다 |

save 는 행에 `DataSeq` 키가 있으면 UPDATE, 없으면 INSERT 합니다.
값이 비어 있어도 키가 있으면 UPDATE 로 갑니다.
새 행에는 `DataSeq` 키를 넣지 마세요.
화면에만 있고 테이블에 없는 키는 저장할 때 무시됩니다.
조회 결과의 기본 정렬은 `DataSeq` 내림차순입니다.
테이블 이름은 영문, 숫자, 밑줄로만 짓고 숫자로 시작하지 마세요(어기면 `Bad Request`).

## 10. API 연동(외부 REST API)
API 연동은 자주 쓰는 외부 API 를 모듈로 등록하고 시나리오 서비스로 부르는 기능입니다. 모듈은 워크스페이스 콘솔의 [데이터] 메뉴에서 등록합니다.
호출은 사용자 브라우저가 아니라 플렉스튜디오 서버가 합니다.
그래서 API 키는 화면 스크립트에 두지 말고 Secret Key 에 등록하세요.

모듈 화면에서 정하는 것입니다.

| 항목 | 넣는 것 |
|---|---|
| Method, URL | 호출 방식과 주소. 자동 URL 인코딩을 켰으면 이미 인코딩된 값을 넣지 마세요(이중 인코딩) |
| Params, Header, Body | 요청 값. Header 와 Body 는 JSON 으로 씁니다 |
| Custom Error Msg | 호출이 성공해도 오류로 처리할 조건 값. 예: `{=Result.errMsg}` |
| Response Body | 시나리오로 넘길 결과 모양. 예: `[[{"data":"{=Result.data}"}]]` |

모듈을 만들거나 고친 뒤에는 모듈 화면 아래의 [배포]를 누르세요.

값을 끼워 넣는 치환식입니다.

| 치환식 | 들어가는 값 |
|---|---|
| `{=Event.<키>}` | 시나리오에서 Event Config Key 로 넘긴 값 |
| `{=<비밀 키 이름>}` | Secret Key 에 등록한 값 |
| `{=ParamBlocks}` | [보내는 데이터] 전체(이중 배열) |
| `{=ParamBlocks[0][0].<키>}` | 첫 블록 첫 행의 값. 점과 대괄호 경로를 쓸 수 있습니다 |
| `{=Result.<키>}` | 응답 값. Custom Error Msg 와 Response Body 안에서 씁니다 |

[확인 필요] 테넌트별, 사용자별 설정값을 넣는 `{=Tenant.<키>}`, `{=User.<키>}` 도 있습니다.
값을 등록하는 화면은 담당자에게 확인하세요.

치환 규칙입니다.

1. 문자열로 넣을 때는 `"{=ParamBlocks[0][0].<키>}"` 처럼 큰따옴표로 감싸세요.
2. 큰따옴표로 감싼 값과 객체 값은 JSON 문자열로 들어갑니다.
3. 값이 0, 빈 문자열, false 면 null 로 바뀝니다. 0 이나 false 를 보내야 하면 치환식 대신 전처리 스크립트에서 넣으세요.
4. 치환한 뒤 Header, Body 가 올바른 JSON 이어야 합니다.

결과는 항상 이중 배열(표 모양)로 바뀌어 [받는 데이터] 1번 블록에 들어갑니다.
응답이 객체 하나면 행 하나, 배열이면 그 배열이 행 목록이 됩니다.

전처리, 후처리 스크립트를 쓸 수 있습니다. [확인 필요] 모듈 화면에서 두 스크립트를 넣는 칸의 이름은 아직 확인되지 않았습니다.
두 스크립트는 이벤트에서 서비스를 부를 때만 실행됩니다.

```javascript
function (paramBlocks, Event) {    // 전처리: 보내기 전에 값을 고칩니다
  return paramBlocks;
}
function (resultBlocks, Event) {   // 후처리: 받은 결과를 고칩니다
  return resultBlocks;
}
```

이 코드가 하는 일:
첫 번째 인자를 고쳐 돌려주면 그 값이 쓰입니다.
return 이 없으면 고친 첫 번째 인자를 그대로 씁니다.

| 보이는 것 | 원인 | 조치 |
|---|---|---|
| `ParamBody JSON parse error` | 치환 뒤 Body 가 JSON 이 아님 | 따옴표, 쉼표, 치환식 감싸기를 확인하세요 |
| `Header JSON parse error` | Header 가 JSON 이 아님 | Header 를 JSON 객체로 쓰세요 |
| `Secret Key JSON parse error` | Secret Key 값이 JSON 이 아님 | Secret Key 를 다시 등록하세요 |
| `Module doesn't exist.` | 모듈을 찾지 못함 | 모듈 이름과 [배포] 여부를 확인하세요 |
| Custom Error Msg 의 메시지 팝업 | 정한 오류 조건 값이 왔음 | 외부 API 응답을 확인하세요 |
| 외부 API 의 4xx, 5xx 메시지 | 외부 서버가 거절함 | 상태 코드와 메시지 그대로 외부 API 문서를 보세요 |
| 시간 초과 | 외부 서버 응답이 늦음 | 오래 걸리는 호출은 작업 ID 받기 → 결과 조회 두 번으로 나누세요 |

## 11. 파일 서비스(FlexFile)
올린 파일은 테넌트, 앱, 카테고리, 연월별로 저장됩니다.
업로드 결과로 원래 파일 이름과 고유 키를 돌려줍니다.
고유 키를 카테고리에 저장해 두세요.
스크립트에서 내려받을 때는 `f.File.download(filekey, target, directory)` 를 씁니다.
인자의 의미는 Studio 의 함수 자동 생성으로 확인하세요.

| 규칙 | 설명 |
|---|---|
| 올린 사람만 받기, 지우기 | 올린 사용자와 카테고리가 같을 때만 됩니다. 다른 사용자가 올린 파일은 기본 파일 서비스로 받을 수 없습니다 |
| 실패해도 result 가 success | 권한이 없으면 message 가 `file not accessible`, 파일이 없으면 `file not found` 입니다. 화면에서 message 를 확인하세요 |
| 내려받은 값 모양 | `data:<파일 형식>;base64,…` 문자열입니다 |

예제 코드를 붙였는데 아무 반응이 없으면 카테고리 이름, 빈 배열, 키 이름 셋 중 하나가 예제와 달라 오류 없이 조용히 끝난 경우가 많습니다.
스크립트 앞에서 카테고리가 비었는지 먼저 검사하세요.
ERP(K-System) 첨부파일 연동은 다른 경로이니 담당자에게 확인하세요.

## 12. 구글 시트(GoogleSheet)
구글 연결 정보는 테넌트의 [시스템 정보]에 등록합니다.
메서드는 query, append, update, clear 네 가지입니다(조회, 추가, 수정, 지우기 순서).
[보내는 데이터]는 첫 번째 블록만 씁니다.

| 규칙 | 결과 |
|---|---|
| 시트 1행은 머리글입니다 | 머리글 이름과 카테고리 키를 글자 그대로 맞추세요 |
| PK 컬럼 이름은 머리글 중 하나와 같아야 합니다 | 없으면 `Invalid PK Column` |
| query 는 처음 나오는 완전히 빈 행에서 멈춥니다 | 중간에 빈 행이 있으면 그 아래는 조회되지 않습니다 |
| 조회한 행에는 `_rowIndex`(시트 행 번호)가 붙습니다 | 빈 셀 값은 null 입니다 |
| append 는 PK 값이 빈 행을 건너뜁니다 | PK 가 빈 행은 추가되지 않습니다 |
| append 에서 숫자 0, false 는 빈 셀이 됩니다 | 0 을 쓰려면 문자열 `'0'` 으로 보내세요 |
| append 값은 사람이 입력한 것처럼 들어갑니다 | 시트가 날짜, 수식으로 해석할 수 있습니다 |
| 자격 증명이 틀림 | `checking your Google Credential.` |

## 13. 모든 서비스에 공통인 주의
1. 서비스에 정의한 AfterScript 는 이벤트에서 부를 때만 실행됩니다. 데이터소스(코드도움 등)로 부르면 실행되지 않습니다.
2. 서비스가 실패하면 그 이벤트의 뒤 액션과 스크립트는 실행되지 않습니다.
3. 사진이나 파일을 Base64 로 서비스에 실어 보내지 마세요. 한 번에 오가는 데이터가 합쳐서 약 4MB 를 넘으면 실패할 수 있습니다. 사진은 줄여서 보내거나 파일 서비스를 쓰세요.
4. 제한시간은 서비스 종류마다 다릅니다. 수십 초가 걸리는 처리는 나누세요.
5. 함수 이름과 인자는 Studio 의 함수 자동 생성으로 확인하세요.
