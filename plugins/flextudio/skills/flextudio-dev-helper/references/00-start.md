# 처음 시작하기: 개념 지도와 구축 순서
이 파일이 답하는 질문: 워크스페이스, 앱, 테넌트는 어떻게 다른가 / 시나리오, Step, 그룹, 컨트롤, 컬렉션, 서비스는 어떻게 연결되나 / 앱 하나를 처음부터 배포까지 어떤 순서로 만드나 / 고쳤는데 앱에 안 나온다 / 어떤 질문에 어떤 설명을 보나

## 목차

1. 한눈에 보는 구조
2. 콘솔 구조: 워크스페이스, 앱, 테넌트, 사용자
3. 화면 구조: 시나리오, Step, 그룹, 컨트롤
4. 데이터 구조: 컬렉션, 카테고리, 섹터, 키
5. 이벤트와 서비스
6. 앱 하나를 처음부터 배포까지
7. 고쳤는데 앱에 안 나올 때
8. 처음 쓰는 사람이 자주 막히는 곳
9. 질문별로 볼 설명
10. 공식 문서 읽는 순서

## 1. 한눈에 보는 구조

플렉스튜디오 앱은 두 층으로 나눠 보면 쉽습니다.
바깥 층은 워크스페이스 콘솔에서 다루는 "누가, 어디서 쓰나"입니다.
안쪽 층은 Studio 에서 만드는 "화면과 데이터가 어떻게 움직이나"입니다.

```
[콘솔 층]  워크스페이스 → 앱 → 고객(테넌트) → 사용자
[Studio 층] 시나리오 → Step → 그룹 → 컨트롤
              │         │
              │         └ 이벤트(액션 1, 2, 3 …) → 서비스 → DB·ERP
              └ 컬렉션 → 카테고리 → 섹터 → 컬렉션 키
```

화면 동작은 이벤트가 맡습니다.
바깥 데이터를 주고받는 일은 서비스가 맡습니다.
화면에 보이는 값은 컬렉션에 들어 있습니다.

## 2. 콘솔 구조: 워크스페이스, 앱, 테넌트, 사용자

```
워크스페이스 (개발 조직)
 ├─ [개발]   시나리오, 권한키                ← 앱과 따로 존재
 ├─ [데이터] API 연동 모듈, FlexSQL 서비스
 └─ 앱 (배포 단위, 앱 ID 로 접속)
     ├─ [시나리오 관리] 앱에 넣은 시나리오와 쓸 버전
     ├─ [레이아웃 관리] 시작페이지, 메뉴, 하단탭바
     └─ 고객(테넌트) 1..n
          ├─ 사용자 (앱 사용권한)
          └─ [시스템 정보] ERP·DB 연결
```

| 용어 | 뜻 | 기억할 점 |
|---|---|---|
| 워크스페이스 | 개발 조직 단위 | 처음 만들 때 앱 생성 창이 뜹니다. |
| 앱 | 사용자에게 배포하는 단위 | 앱 ID 가 웹 접속 URL 에 쓰입니다. |
| 고객(테넌트) | 같은 앱을 쓰는 회사 한 곳 | 사용자 명단과 ERP·DB 연결을 따로 갖습니다. |
| 사용자 | 앱에 로그인하는 사람 | 앱 사용권한을 받아야 씁니다. |

ERP·DB 연결 정보는 앱이 아니라 테넌트에 있습니다.
테넌트의 [회사 정보]-[사용할 System] 과 [시스템 정보]에 등록합니다.
그래서 같은 앱이라도 접속한 테넌트에 따라 연결되는 DB 가 달라집니다.
K-System 연동은 테넌트당 시스템 1개입니다.

시나리오와 권한키는 앱과 따로 존재합니다.
[개발]-[시나리오 개발]에서 만든 시나리오는 어떤 앱에도 속하지 않습니다.
[앱]-[시나리오 관리]에서 만든 시나리오는 그 앱에 바로 들어갑니다.

기업 내부 업무앱은 초대기반앱으로 만드세요.

| 기능 | 공개앱 | 초대기반앱 |
|---|---|---|
| 사용자가 직접 가입 | 됨 | 안 됨 |
| 관리자가 사용자 등록(엑셀 일괄) | 안 됨 | 됨 |
| 문자·메일 6자리 인증 로그인 | 안 됨 | 됨 |
| 다른 앱으로 앱 전환 | 안 됨 | 됨 |

메뉴가 없거나 잠겨 있으면 요금제부터 확인하세요.
기능별 요금제 조건은 이 스킬이 단정하지 않습니다.
현재 요금제 안내나 플렉스튜디오 담당자에게 확인하세요.

## 3. 화면 구조: 시나리오, Step, 그룹, 컨트롤

```
시나리오 (업무 프로세스 하나, 예: 거래처 관리)
 ├─ Step (화면 하나, 예: 목록 화면, 상세 화면)
 │   └─ 그룹 (배치 묶음, 데이터 연결을 거는 단위, 안에 그룹을 또 넣을 수 있음)
 │        └─ 컨트롤 (InputText, ComboBox, Button, Sheet 등)
 ├─ 이벤트 (Step 이벤트, 컨트롤 이벤트)
 ├─ 서비스 (바깥 데이터와 주고받기)
 └─ 컬렉션 (화면 값이 들어 있는 곳)
```

| 요소 | 하는 일 | 예 |
|---|---|---|
| 시나리오 | 업무 프로세스 하나 | 로그인, 주문 조회 |
| Step | 시나리오 안의 화면 하나 | 목록, 상세, 팝업 |
| 그룹 | 컨트롤을 배치하고 데이터를 연결 | 검색 영역, 목록 카드 |
| 컨트롤 | 입력, 표시, 클릭 | 입력창, 버튼, 시트 |

반복되는 목록은 카드를 손으로 복제하지 마세요.
그룹의 데이터 연결에 카테고리를 걸면 행 수만큼 그려집니다.
고정 문구는 라벨에 글자로 넣습니다.

Step 이벤트 중 처음 쓰는 두 가지는 [최초 시작 전 (Init)] 과 [로드 시 (Loaded)] 입니다.
Init 은 화면을 그리기 전에 실행됩니다.
Loaded 는 화면을 그린 뒤에 실행됩니다.
처음 조회는 Init 에 두세요.
서비스가 기본값인 동기 호출이면 Init 에서 받은 데이터는 따로 다시 그리지 않아도 화면에 보입니다.
서브 화면에서 돌아왔을 때 다시 조회하려면 [뒤로가기로 돌아올 때] 이벤트를 쓰세요.

다른 시나리오를 화면 흐름 안에서 불러 쓰고 돌아오는 방식을 서브시나리오라고 합니다.
컬렉션은 시나리오마다 따로 있습니다.
그래서 서브시나리오로 넘길 데이터와 돌려받을 데이터를 설정해야 합니다.
자세한 설정은 이벤트와 스크립트 설명의 서브시나리오 왕복 규칙을 보세요.

## 4. 데이터 구조: 컬렉션, 카테고리, 섹터, 키

```
컬렉션 (_c, 시나리오 하나의 데이터 전체)
 └─ 카테고리 (같은 종류 행의 묶음, 예: CustList)
     └─ 섹터 (행 하나, 만들 때 _SUID 가 자동으로 붙음)
         └─ 컬렉션 키 = 값 (예: CustName = "영림상사")
```

비유하면 카테고리는 테이블, 섹터는 행, 컬렉션 키는 컬럼입니다.
다만 실제로는 카테고리에 미리 정하지 않은 키도 섹터에 담길 수 있습니다.

| 하고 싶은 일 | 쓰는 것 |
|---|---|
| 카테고리의 행 전체 읽기 | `_c.<카테고리>` (배열처럼 length, [0] 사용) |
| 지금 선택된 행 읽기 | `_c.activeSector` |
| 행 값 바꾸기 | `<섹터>.set('<키>', <값>)` |

처음부터 지킬 규칙은 네 가지입니다.

1. 값은 `set()` 으로 바꾸세요.
   직접 대입하면 수정 표시가 붙지 않아 저장 서비스가 그 행을 보내지 않습니다.
2. 카테고리는 `(_c.<카테고리> || [])` 로 감싸 읽으세요.
   마지막 행을 지우면 카테고리 자체가 없어집니다.
3. 아무 행도 선택하지 않으면 `_c.activeSector` 는 화면의 첫 행을 돌려줍니다.
   저장이나 삭제 전에 키 값을 확인하세요.
4. `status` 같은 엔진 예약어는 컬렉션 키로 쓰지 마세요.
   상태 컬럼은 `ASStatus` 처럼 접두어를 붙입니다.

예약어 전체 목록과 화면 연결 방법은 화면과 데이터 설명에 있습니다.

## 5. 이벤트와 서비스

이벤트는 액션을 1번부터 순서대로 하나씩 실행합니다.
액션 하나는 세 가지 중 하나를 합니다.

1. 서비스 호출
2. 다른 이벤트 호출
3. 스크립트 실행

서비스는 서버에서 DB·ERP 와 데이터를 주고받습니다.
데이터가 지나가는 길은 이렇습니다.

버튼 클릭 → 이벤트 → 서비스 → SP 또는 쿼리 → [받는 데이터] → 카테고리 → 화면

| 서비스 종류 | 언제 쓰나 | 볼 설명 |
|---|---|---|
| K-System(Flex-K) 연동 | 데이터가 ERP 에 이미 있을 때 | K-System 서비스와 SP 작성 설명 |
| FlexSQL | ERP 밖 DB 에 SQL 을 실행할 때 | FlexSQL과 데이터 서비스 설명 |
| 자동조회(FlexAutoQuery) | FlexDB 테이블을 쿼리 없이 다룰 때 | FlexSQL과 데이터 서비스 설명 |
| API 연동 | 외부 REST API 를 부를 때 | FlexSQL과 데이터 서비스 설명 |

이 데이터가 ERP 에 이미 있으면 K-System(Flex-K) 연동을 쓰세요.
없으면 FlexSQL 이나 FlexDB 를 쓰세요.

서비스 설정에서 자주 보는 화면 글자는 [보내는 데이터], [사용자 데이터], [받는 데이터], [덮어쓰기] 입니다.
조회 서비스의 [받는 데이터]는 [덮어쓰기]로 두세요.
기본값인 추가로 두면 조회할 때마다 목록이 늘어납니다.

## 6. 앱 하나를 처음부터 배포까지

만드는 순서는 데이터 → 서비스 → 화면 배선 → 스크립트 → 확인 → 배포입니다.
이름(컬렉션 키, SP 결과 컬럼)을 먼저 정해 두면 화면에서는 그 이름만 쓰면 됩니다.

### 6-1. 준비 (한 번만)

1. 워크스페이스를 만드세요.
2. 앱을 만드세요.
   업무앱이면 초대기반앱으로 고르세요.
3. 워크스페이스 콘솔의 [고객관리]에서 고객(테넌트)을 만드세요.
4. 고객 설정 페이지의 [회사 정보]-[사용할 System] 에 쓸 시스템을 저장하세요.
   K-System 을 저장하면 [시스템 정보]에 K-System 탭이 보입니다.
5. [시스템 정보]에 연결 값을 넣으세요.

K-System(Flex-K) 연동이라면 [시스템 정보]에 넣는 값은 Oper dsn, Bis dsn, CompanySeq, FlexK API URL 입니다.
Flex-K 설치와 방화벽 허용 값은 설치 안내 문서나 플렉스튜디오 담당자에게 받으세요.
자세한 사전 점검은 구축과 배포 설명의 Flex-K 설치 사전 점검을 보세요.

### 6-2. 만들기

1. 화면 정의 양식을 채우세요.
   화면 목록, 카테고리, 컬렉션 키, 서비스, SP 이름을 먼저 정합니다.
2. 데이터: 테이블을 만드세요.
3. 서비스: SP 나 FlexSQL 쿼리를 쓰고 DB 에서 직접 실행해 결과를 확인하세요.
4. 서비스: Studio 의 Service 탭에서 서비스를 등록하세요.
5. 화면: Step 을 만들고 그룹과 컨트롤을 배치하세요.
6. 화면: 그룹 속성의 데이터 연결에 카테고리를 거세요.
7. 배선: 이벤트 탭에서 이벤트를 만들고 액션에 서비스를 넣은 뒤 [보내는 데이터]와 [받는 데이터]를 고르세요.
8. 스크립트: 필수값 확인, 화면 이동, 값 바꾸기처럼 배선만으로 안 되는 부분만 스크립트로 쓰세요.
9. 확인: Studio 디버거로 실행하고 값과 오류를 보세요.
   디버거의 실행 내역에 이벤트와 서비스가 순서대로 찍히고 오류 문구가 없으면 다음 단계로 갑니다.

SP 가 돌려주는 컬럼 이름과 컬렉션 키는 대소문자까지 같아야 합니다(8절 표 참고).

AI 가 시나리오 JSON 을 만들어 줘도 설계도로만 쓰세요.
실제 입력은 Studio 화면에서 하세요.
JSON 을 직접 반영하는 것은 정식 지원 경로가 아닙니다.
AI 가 만든 JSON 에 서비스 배선이 없다면 Studio 이벤트 탭에서 서비스 액션을 추가하세요.
[Etc] 탭 Collections 가 비어 있다면 SP 가 읽는 키를 Studio 에서 타입과 함께 등록하세요.

### 6-3. 배포와 사용자

1. Studio 에서 저장한 뒤 [배포]를 누르세요.
   시나리오 버전이 발행됩니다.
2. FlexSQL 서비스를 고쳤다면 [새 버전 발행] 또는 [현재버전으로 변경내역 반영]을 하세요.
3. API 연동 모듈을 고쳤다면 모듈 화면에서 [배포]를 누르세요.
4. 앱의 [시나리오 관리]-[시나리오 배포]에서 쓸 시나리오와 버전을 고르세요.
5. [라이브에 적용]을 누르세요.
6. [레이아웃 관리]에서 시작페이지와 메뉴에 시나리오를 넣으세요.
7. 고객 설정의 [사용자관리]에서 사용자에게 앱 사용권한을 주세요.
8. [앱 초대 문자 발송]을 누르세요.
   사용자가 접속하면 상태가 "사용중"이 됩니다.

[라이브에 적용]은 누르는 즉시 실사용자에게 반영됩니다.
적용 전에 디버거로 확인하세요.
앱 삭제는 영구 삭제이고 백업과 복원을 지원하지 않습니다.

배포한 앱 URL 로 테스트 사용자가 로그인했을 때 시작페이지나 메뉴에 시나리오가 보이면 성공입니다.
보이지 않으면 7절 순서로 점검하세요.

## 7. 고쳤는데 앱에 안 나올 때

저장과 "사용자에게 보임" 사이에는 단계가 여럿 있습니다.
아래 순서로 하나씩 확인하세요.

1. Studio 에서 [배포]를 눌러 시나리오 버전을 발행했는지 확인하세요.
2. 앱의 [시나리오 배포]에서 그 버전을 고르고 [라이브에 적용]을 눌렀는지 확인하세요.
3. FlexSQL 서비스를 새 버전으로 발행했는지 확인하세요.
   API 연동 모듈이라면 [배포]했는지 확인하세요.
4. 앱이 앱팩을 쓴다면 [앱팩] 메뉴에서 배포했는지 확인하세요.

시나리오 배포와 앱 배포는 다른 일입니다.
시나리오 배포는 시나리오 버전을 발행하는 일입니다.
앱 배포는 그 버전을 골라 라이브에 반영하는 일입니다.

## 8. 처음 쓰는 사람이 자주 막히는 곳

| 보이는 것 | 원인 | 조치 |
|---|---|---|
| 고쳤는데 앱에 그대로 | 저장만 하고 배포와 라이브 적용을 하지 않았습니다. | 7절 순서로 확인하세요. |
| 메뉴에서 시나리오를 고를 수 없음 | [개발]에서 만든 시나리오를 앱에 넣지 않았습니다. | [앱]-[시나리오 관리]에서 추가하세요. |
| ERP 연결을 어디에 넣는지 모름 | 앱이 아니라 테넌트에서 설정합니다. | 테넌트 [시스템 정보]에 넣으세요. |
| 권한을 줬는데 "사용중"이 아님 | 초대 문자를 보내지 않았습니다. | [앱 초대 문자 발송]을 누르세요. |
| 조회할 때마다 목록이 늘어남 | [받는 데이터]가 기본값인 추가로 되어 있습니다. | [덮어쓰기]로 바꾸세요. |
| 조회는 됐는데 화면에 빈 값 | SP 결과 컬럼 이름과 컬렉션 키가 다릅니다. | SP 에서 `AS <컬렉션 키>` 로 맞추세요. |
| 디버거에서 팝업, 다른 시나리오 호출이 안 됨 | 팝업과 시나리오 호출은 디버거에서 동작하지 않습니다. | 배포한 앱에서 확인하세요. |
| 특정 사용자에게만 오류 | 개발자 계정으로는 재현되지 않습니다. | 그 사용자에게 디버그 권한을 주고 디버거 접속 정보에서 그 사용자로 실행하세요. |

## 10. 공식 문서 읽는 순서

공식 문서 주소는 https://docs.flextudio.com/flextudio 입니다.
페이지 주소 끝에 `.md` 를 붙이면 마크다운으로 받을 수 있어 AI 에 넣기 좋습니다.

공식 문서가 권하는 순서는 이렇습니다.
개발 흐름 파악 0~4단계 → 튜토리얼(메모장, 중고거래) → 심화 실습 → 개념 학습하기 → 로드맵

ERP 데이터로 업무앱을 만드는 분은 이 순서로 보세요.

1. 큰 그림: 처음 시작하기 0~4단계, 워크스페이스 콘솔 가이드
2. 개념: 시나리오 구성요소, 컬렉션과 섹터, 이벤트와 서비스
3. 손에 익히기: 메모장 튜토리얼, 중고거래 튜토리얼
4. 화면 만들기: 컴포넌트(스텝, 그룹, 컨트롤)
5. 데이터 연결과 이벤트: 개발 모드
6. 서비스: 참고의 데이터 연동(K-System), 개발 모드의 서비스
7. 디버깅: 디버거
8. 배포와 운영: 시나리오 배포, 레이아웃, 고객관리, 권한키

공식 문서의 절차는 그림에 많이 들어 있습니다.
AI 에게 물을 때는 메뉴 경로를 글로 적어 달라고 하세요.
