## 1. 화면·시트

### 1-1. 시트 행을 한 번 눌렀는데 activeSector 가 안 바뀝니다
결론: 시트는 행을 한 번 눌러서는 activeSector 가 바뀌지 않습니다. 더블클릭해야 바뀝니다.
할 일:
1. 한 번 클릭으로 처리하려면 그 컬럼에 더블클릭 이벤트를 거세요.
2. 행 안의 버튼으로 처리한다면 버튼 이벤트 첫 줄에서 그 행의 섹터에 `sector.activate()` 를 부르세요.
[확인 필요] 버튼이 눌린 행의 섹터를 꺼내는 방법은 Studio [함수 자동 생성]에서 확인하세요.
확인: 디버거 콘솔 탭에 `_c.<카테고리명>.activeSector` 를 입력해 누른 행으로 바뀌는지 보세요.

### 1-2. 전체선택을 했는데 체크 표시가 안 보입니다
결론: 원인은 두 가지입니다. 전체선택 대상이 체크박스 기능을 켠 그룹이 아니거나, 뒤에서 스텝 전체를 다시 그려 선택 상태가 지워졌습니다.
할 일:
1. 전체선택을 부르는 `f.Content('<그룹fid>')` 의 fid 가 체크박스 기능을 켠 그룹의 fid 인지 확인하세요.
[확인 필요] 전체선택 함수 이름은 공식 명세 목록에 없습니다. Studio [함수 자동 생성]에서 f.Content 항목을 확인하세요.
2. 같은 이벤트 뒤쪽에 `Current.step.reload()` 가 있으면 지우세요. 스텝 reload 는 화면을 새로 그리면서 선택 상태를 초기화합니다.
3. 다시 그려야 한다면 필요한 그룹만 `f.Content('<그룹fid>').reload()` 하세요.
확인: 전체선택 뒤 디버거 콘솔 탭에서 그 카테고리 섹터마다 isSelected 값이 true 인지 보세요.

### 1-3. 저장하고 reload 하면 목록 스크롤이 맨 위로 갑니다
결론: 스텝 reload 는 스텝 스크롤은 유지하지만 그룹 안의 스크롤은 유지하지 않습니다. 자동으로 지켜 주는 설정은 없습니다.
할 일:
1. reload 직전에 `f.Content('<그룹fid>').Scroll.offset` 값을 `_v` 에 저장하세요.
2. 다시 그린 뒤에 저장한 값을 같은 `Scroll.offset` 에 넣어 되돌리세요.
3. 뒤로가기로 돌아온 화면이면 "뒤로가기로 돌아올 때" 이벤트에서 되돌리세요.
[확인 필요] reload 를 부른 줄 바로 뒤에서 되돌리면 다시 그리기 전이라 적용되지 않을 수 있습니다. 되돌리는 코드를 별도 이벤트로 빼서 `f.Event('<복원이벤트>').runNext()` 로 부른 뒤 결과를 비교해 보세요.
확인: 목록 중간까지 내린 상태에서 저장하고, 같은 위치가 보이는지 보세요.

### 1-4. 스텝 reload 를 했더니 무한 로딩이 되거나 화면이 깜빡입니다
결론: 컨트롤 이벤트에서 `Current.step.reload()` 를 걸면 다시 그릴 때 이벤트가 또 돌아 무한 반복이 됩니다. 스텝 reload 는 선택 상태도 지웁니다.
할 일:
1. 스텝 reload 를 필요한 상위 그룹의 `f.Content('<그룹fid>').reload()` 로 바꾸세요.
2. 한 행만 다시 그릴 때는 `f.Content('<그룹fid>', _c.activeSector).reload()` 를 쓰세요.
3. 이미지는 reload 하는 그룹 밖에 두세요. 깜빡임이 줄어듭니다.

### 1-5. 시트에서 조회된 행은 읽기 전용, 새 행만 입력 가능하게 하고 싶습니다
결론: 행 단위 편집 잠금은 공식 기능이 없습니다. 읽기 전용(readOnly)은 컬럼 단위로만 됩니다.
할 일:
1. 조회 행과 입력 행을 서로 다른 시트(카테고리)로 나누는 방법을 먼저 검토하세요.
2. 저장 이벤트에서 조회 행이 바뀌었는지(`sector.isUpdated`) 검사하고, 바뀌었으면 `f.MessageBox` 로 알리고 멈추세요.
3. 색으로만 구분하려면 시트 로드 스크립트의 셀 스타일 설정(customCellStyle)으로 조회 행 색을 바꾸는 우회가 있습니다. 데이터가 많으면 느려지고 공식 기능이 아니므로 그 점을 함께 알리세요.
[확인 필요] customCellStyle 을 넣는 함수는 공식 명세 목록에 없습니다. Studio [함수 자동 생성]에서 시트 로드 스크립트 항목을 확인하세요.
확인: 조회 행을 고친 뒤 저장했을 때 저장이 멈추고 안내가 뜨는지 보세요.

### 1-6. 쿼리는 실행되는데 시트에 값이 안 나오거나 같은 행이 반복됩니다
결론: SQL 컬럼 별칭과 컬렉션 키가 다르거나, 받는 카테고리명과 시트에 설정한 카테고리명이 다릅니다. 같은 카테고리명을 다른 그룹에서도 쓰면 행이 반복돼 보입니다.
할 일:
1. SQL 별칭을 컬렉션 키와 글자까지 똑같이 맞추세요.
2. [받는 데이터]의 카테고리명을 시트의 카테고리명과 맞추세요.
3. 한 카테고리를 여러 그룹에 겹쳐 연결하지 마세요.
4. 엑셀 업로드 뒤에는 시트 그룹을 reload 하세요.
확인: 디버거 콘솔 탭에 `_c.<카테고리명>` 을 입력해 카테고리와 키 이름이 화면 설정과 같은지 보세요.

### 1-7. 값이 들어 있는데 필수값 오류가 납니다
결론: 필수 체크는 그 컨트롤에 연결된 모든 컬렉션 키를 검사합니다. 데이터소스 쪽 키가 비어 있어도 오류가 납니다.
할 일: 필수 체크를 끄고, 저장 이벤트에서 필요한 키만 스크립트로 검사하세요.

### 1-8. 행삭제한 행을 컬렉션에서도 지우고, 삭제에 이벤트를 걸고 싶습니다
결론: 시트의 행삭제는 섹터를 deleted 상태로만 바꿉니다. 기본 행삭제 메뉴에는 이벤트를 걸 수 없습니다.
할 일:
1. 컬렉션에서 지우려면 `f.Collection.removeSector('deleted', '<카테고리명>')` 를 부르세요.
2. 삭제에 처리가 필요하면 별도 삭제 버튼의 click 이벤트에서 `f.SheetControl('<시트fid>').deleteRow(_c.activeSector)` 를 부르세요.

### 1-9. 상태값 X, 탭 안의 탭
- 섹터 상태는 added, updated, deleted 세 가지뿐입니다. 다른 값은 상태용 컬렉션 키를 만들고 `f.Collection.updateSector('all', '<상태키>', 'X', '<카테고리명>')` 처럼 관리하세요.
- 탭 컨트롤을 2단계 이상 겹치면 화면이 반복되거나 깨집니다. 지원하지 않는 구조이므로 안쪽 탭을 라디오, 스텝 이동, 팝업 중 하나로 바꾸세요.

### 1-10. 외부 CSS·JS 파일을 적용하고 싶습니다
결론: 시나리오 설정의 외부파일설정에 파일 링크를 넣습니다. css 와 js 파일만 넣을 수 있습니다.
할 일:
1. 익스플로러에서 시나리오명을 누르고, 외부파일설정에 css 또는 js 파일 주소를 넣으세요.
2. 특정 그룹만 꾸미려면 `section[data-metaid="<그룹fid>"]` 선택자를 쓰세요.
확인: 배포 앱에서 F12 를 누르고 [Network] 탭에서 파일이 200 으로 내려오는지 보세요.

## 2. 이벤트·스텝·서브시나리오

### 2-1. Init 에 넣은 숨기기, 스크롤 이동이 안 먹습니다. 로드 스크립트는 언제 도나요
결론: Init 은 화면이 그려지기 전에 돕니다. 로드 스크립트는 첫 스텝 진입, 다음 스텝 이동, reload 때 돌고, reload 하면 이전에 붙인 addClass 는 남지 않습니다.
할 일:
1. 화면 요소를 다루는 코드는 Loaded 시점 이벤트로 옮기세요.
2. 앱으로 다시 돌아올 때 처리는 "앱에 다시 돌아올 때" 이벤트를 따로 거세요. Init 이 대신 돌지 않습니다.

### 2-2. 시작 스텝으로 돌아왔는데 홈 버튼 대신 뒤로가기 버튼이 보입니다
결론: `Current.step.moveToNext` 로 돌아가면 새로 이동한 스텝으로 인식합니다.
할 일: 처음 스텝으로 돌아갈 때는 `Current.step.moveToPrev` 를 쓰세요. moveToPrev 의 화면 전환 효과는 들어올 때의 반대로 정해지며 따로 지정할 수 없습니다.

### 2-3. 서브시나리오 팝업에 X 버튼이 보이거나 뒤로가기 버튼이 안 보입니다
결론: 서브시나리오 쪽 스텝의 "상단 헤더 사용하기"와 부모 스텝의 "호출한 시나리오로 돌아가기 허용", 두 설정이 버튼을 정합니다.
할 일:
1. X 버튼을 없애려면 서브시나리오 스텝의 "상단 헤더 사용하기"를 끄세요. 켜면 뒤로가기 버튼이 보입니다.
2. 부모 스텝의 "호출한 시나리오로 돌아가기 허용"이 켜져 있는지도 확인하세요.

### 2-4. 팝업 스텝에서 저장에 성공하면 닫고 부모 화면을 다시 조회하고 싶습니다
결론: 저장 성공 뒤 이전 스텝으로 돌아가고, 부모 스텝의 "뒤로가기로 돌아올 때" 이벤트에서 조회를 다시 부릅니다.
할 일:
1. 저장 서비스 뒤 스크립트에서 `_v` 에 플래그를 세우세요.
2. 이어서 `Current.step.moveToPrev(null, true)` 를 부르세요.
3. 부모 스텝의 "뒤로가기로 돌아올 때" 이벤트에서 플래그를 보고 `f.Event('<조회이벤트>').runNext()` 를 부르세요.
확인: 서비스가 실패하면 뒤 스크립트가 실행되지 않아 팝업이 닫히지 않습니다. 이것이 정상 동작입니다.

### 2-5. runNext 를 반복문에서 여러 번 불렀더니 순서가 꼬입니다
결론: 이벤트는 큐로 차례대로 실행됩니다. `runNext()` 는 큐 맨 앞에 넣고 현재 스크립트가 끝난 뒤 실행합니다.
할 일: 반복문 안에서 runNext 를 여러 번 부르지 마세요. 반복할 처리는 한 이벤트 안의 반복문으로 끝내세요.
참고: 버튼을 아주 빠르게(약 20ms 안에) 두 번 누르면 로딩 표시 전에 이벤트가 두 번 들어갈 수 있습니다.

## 3. 링크·알림·팝업

### 3-1. 다른 앱의 시나리오로 이동하고 싶습니다. f.Frame 과 서브시나리오는 뭐가 다른가요
결론: 고르는 기준은 아래와 같습니다.

| 하고 싶은 것 | 쓰는 것 |
|---|---|
| 같은 흐름 안에서 재사용하고 값 주고받고 돌아오기 | 서브시나리오 |
| 다른 앱·워크스페이스 화면을 새로 시작 | `f.Frame.scenario(scenarioID, stepID)` |
| 지금 화면 위에 잠깐 띄우기 | `f.Frame.popUp(scenarioID, stepID)` |
| 하단 탭 메뉴에 반영되게 이동 | `f.Frame.tab.focus()` |

참고: `f.Frame.scenario` 로 연 화면은 이전 흐름과 데이터를 이어받지 않습니다. f.Frame 은 디버거에서 동작하지 않으므로 배포 앱 주소로 시험하세요.

### 3-2. f.Frame.scenario 로 연 화면을 스크립트로 닫고 싶습니다
결론: 지원하지 않습니다. 팝업은 `f.Frame.popUp().remove()` 로 닫을 수 있지만, 팝업이 닫힌 뒤 부모 화면에서 이벤트를 자동으로 실행하는 기능은 없습니다.
할 일:
1. 닫고 돌아와야 하는 화면이면 서브시나리오로 바꾸세요.
2. 같은 시나리오 안이면 팝업 스텝으로 만들고 2-4 방식으로 닫으세요.

### 3-3. 메뉴로 들어왔는지 스크립트로 열었는지 init 에서 구분하고 싶습니다
결론: 여는 쪽이 링크 파라미터에 표시를 싣고, 받는 쪽 init 에서 읽은 뒤 비웁니다. 비우지 않으면 다음에 메뉴로 들어왔을 때 예전 표시가 남습니다(3-4).
할 일:
1. 여는 쪽에서 링크 파라미터에 `{ from: 'script' }` 같은 표시를 넣고 화면을 여세요.
2. 받는 쪽 init 에서 `f.Link.getLinkParam()` 으로 읽으세요.
3. 읽은 직후 `f.Link.init()` 으로 비우세요. 대문자 L 입니다.
[확인 필요] 여는 쪽에서 링크 파라미터를 넣는 함수 이름은 공식 명세 목록에 없습니다. Studio [함수 자동 생성]에서 f.Link 항목을 확인하세요.
참고: `_base.linkParam` 은 지원 종료 예정이라 새 개발에 쓰지 마세요.

### 3-4. 푸시로 들어온 뒤 메뉴로 다시 들어가도 예전 번호 1건만 조회됩니다
결론: 링크 파라미터가 비워지지 않고 남아 있어서입니다.
할 일:
1. 파라미터로 조회한 직후 `f.Link.init()` 을 부르세요.
2. 메인 스텝 init 에서도 `f.Link.init()` 을 한 번 더 부르세요.
3. 파라미터 값을 조회 조건 카테고리에 옮겨 담았다면 그 값도 init 에서 비우세요.
확인: 푸시로 들어간 뒤 메뉴로 다시 들어가 전체 목록이 나오는지 보세요.

### 3-5. 앱 알림을 눌러도 원하는 화면으로 가지 않습니다
결론: 이동 정보에 시나리오가 속한 팩(pack) ID 가 빠졌거나, 상세 스텝으로 바로 보내 값이 없어서인 경우가 많습니다.
할 일:
1. `f.Message().setActionJson(actionJson)` 의 actionJson 에 시나리오가 속한 pack ID 를 넣으세요.
2. 보내는 앱과 받는 사용자가 같은 테넌트인지 확인하세요.
3. 목록의 activeSector 를 읽는 상세 스텝으로 바로 보내지 말고 목록 스텝으로 보내세요.
4. 수신자는 휴대폰 번호가 아니라 사용자 번호로 지정하세요(`addReceiver(fBaseUserNo, isAlarmOff)`).
5. 시작 시나리오에 다른 주소로 넘기는 외부 파일이 있으면 알림으로 들어온 경우를 예외 처리하세요.
[확인 필요] actionJson 안에서 pack ID 를 넣는 키 이름은 공식 명세의 f.Message 절에서 확인하세요.

### 3-6. 팝업 높이를 내용에 맞게 자동으로 하는 설정이 있나요
결론: 공식 기능은 없습니다. 높이를 지정하지 않으면 전체 화면으로 열립니다. 높이를 지정하면 바깥 어두운 영역을 눌렀을 때 닫히는 것이 기본 동작입니다.
할 일:
1. 내용이 가장 길 때를 기준으로 스텝 높이를 지정하세요.
2. 꼭 자동 높이가 필요하면 화면 구조(DOM)에서 팝업 영역 높이를 직접 바꾸는 우회만 있습니다. 비공식이라 업데이트 때 깨질 수 있다고 알리고, 업무 핵심 화면에는 쓰지 마세요.

### 3-7. 하단 탭바가 사라집니다
결론: 하단 탭바는 홈에서 보이고, 탭으로 이동했을 때만 유지됩니다. 사이드 메뉴나 f.Frame 으로 이동하면 사라집니다. 메뉴·탭 클릭에는 이벤트를 걸 수 없습니다.
할 일: 탭 진입 처리는 대상 시나리오 init 에서 `Current.scenario.id` 로 구분해 하세요.

## 4. 바코드·모바일

### 4-1. 모바일과 PDA 에서 바코드를 읽으려면
결론: 모바일 앱 카메라는 `f.Native.getBarcode(isSync, eventName, isMulti)`, PDA 는 `f.Scanner.init(options)` 와 `f.Scanner.startScan()` 을 씁니다.
할 일: 카메라 결과는 eventName 이벤트에서 `f.Barcode.value` 로 읽고, PDA 는 init 의 options 에 기기 모델을 등록하세요.
확인: PC 브라우저는 웹캠으로 대신 읽어 정확도가 낮으니 실제 기기에서 시험하세요.

### 4-2. 아이폰에서 연속으로 스캔하면 가끔 스캔 창이 안 열립니다
결론: 카메라가 아직 해제되기 전에 다음 스캔 요청이 들어가 그 요청이 사라지는 현상입니다.
할 일: 스캔 결과 이벤트에서 다음 `f.Native.getBarcode` 호출을 약 400ms 늦춰 부르세요.

```javascript
setTimeout(function () {
  f.Native.getBarcode(true, '<결과이벤트>', false);
}, 400);
```
[확인 필요] 첫 인자 isSync 와 셋째 인자 isMulti 의 뜻은 공식 명세에서 확인하고, 처음 스캔을 부른 코드와 같은 값으로 맞추세요.
확인: 아이폰에서 10번 이상 연속으로 스캔해 창이 매번 열리는지 보세요.

### 4-3. 큰 사진이나 여러 이미지를 저장하면 413 이나 통신 실패가 납니다
결론: 서비스 한 번에 오가는 데이터가 이미지 합산 약 4MB 를 넘으면 실패할 수 있습니다.
할 일: 사진은 줄이거나 압축해서 보내고, 파일은 Base64 로 싣지 말고 파일 서비스로 처리하세요.

### 4-4. 기타 짧은 답
- 배포 뒤 앱을 다시 실행하지 않아도 됩니다. 메뉴로 다시 들어가거나 홈 버튼을 누르면 배포본이 적용됩니다.
- Android 16 기기에서 뒤로가기를 누르면 앱이 닫히면, 설치형 앱 라이브러리(flex-lib)를 1.0.26 이상으로 올려 다시 빌드하세요.
- 탭 사이 이동은 기기 뒤로가기 버튼의 되돌아갈 대상이 아닙니다.
- 삼성 인터넷에서 숫자 입력 마스크가 이상하면 브라우저 문제입니다. 크롬을 쓰세요.
- fAUID 는 기기 고유 번호가 아닙니다. 앱 데이터를 지우거나 다시 설치하면 바뀝니다.

## 5. 서비스·코드도움

### 5-1. 코드도움을 붙였는데 오류가 납니다
결론: 가장 흔한 원인은 그 서버(DB)에 코드도움 SP 가 없는 경우입니다.
할 일:
1. 연결한 서버의 DB 에 그 SP 가 있는지 먼저 확인하세요. DB 에서 SP 를 직접 실행해 보면 됩니다.
2. 없으면 SP 를 만들거나, 그 SP 가 있는 서버로 연결을 바꾸세요.
3. SP 가 있는데도 오류면 troubleshooting.md 의 서비스 오류 메시지 표를 보세요.

### 5-2. 코드도움이 1000건까지만 나와서 뒤쪽 데이터를 못 찾습니다
결론: 목록은 1000건까지만 보입니다. 검색어로 서버에서 다시 찾게 하면 됩니다.
할 일:
1. 코드도움 데이터 설정에서 "키워드 검색 시 데이터소스 사용"을 켜세요.
2. 데이터소스 파라미터에 대체 텍스트로 검색어를 연결하세요.
3. SP 가 그 검색어로 조건을 걸도록 고치세요. 다른 컨트롤 값을 파라미터로 넘길 때도 대체 텍스트를 씁니다.
확인: 1000번째 뒤에 있는 코드가 검색어로 찾아지는지 보세요.

### 5-3. 서비스 스크립트와 예약 키
| 질문 | 결론 | 할 일 |

## 7. 권한·메뉴·계정

### 7-1. 그룹 권한키와 사용자 권한키가 겹치면 어떻게 되나요. 탭별 권한도 되나요
결론: 그룹과 사용자 권한키는 우선순위 없이 둘 다 적용됩니다. 탭별 권한키는 없습니다.
할 일:
1. 탭 클릭 이벤트에서 `f.Auth.check('<권한키>')` 로 검사하고 권한이 없으면 막으세요.
2. 새 권한키가 권한관리 메뉴에 안 보이면 시나리오에 그 키를 쓰고 라이브에 적용하세요.
참고: 특정 권한자에게만 알림을 보내는 기능은 없습니다. 그룹을 만들고 Flextudio API 로 그룹 사용자를 조회해 수신자로 넣으세요.

### 7-2. K-System 연동 앱에서 메뉴 항목이 공란으로 나옵니다
결론: 로그인 때 ERP 로그인 SP 가 돌려주는 메뉴 권한 목록이 비어 있으면 생깁니다. ERP 쪽 SP·패치 영역이라 플렉스튜디오 화면에서 고칠 수 없습니다.
할 일:
1. 그 사용자의 ERP 화면 권한 설정 캡처와 최근 ERP 패치 여부를 담당 부서에 전달하세요.
2. 담당 부서 확인 뒤 AS(서비스 요청)로 등록하세요.

### 7-3. 휴대폰 인증에서 "존재하지 않는 번호"가 나오거나, 개발자로 등록했는데 앱에 로그인이 안 됩니다
결론: 번호 형식이 틀렸거나 앱 사용자로 등록되지 않았습니다. 개발자 등록은 앱 접근 권한이 아닙니다.
할 일:
1. 전화번호를 하이픈 없이 01000000000 형식으로 넣으세요.
2. 앱 사용자는 그 앱의 고객관리(테넌트 사용자)에 추가하세요.
3. 외부 DB 사용자 동기화를 쓰는 중이면 동기화 체크를 풀어야 수동 등록 버튼이 보입니다. 휴대폰 우선인 인증 기본값은 바꿀 수 없습니다.

### 7-4. 시나리오 ID 변경과 복원
시나리오 ID 와 앱 ID 는 바꿀 수 없습니다. 원하는 ID 로 복제하거나 앱을 복사하세요. 지운 시나리오는 좌측 휴지통에서 우클릭해 복원하세요.

## 8. 파일·메일

### 8-1. 플렉스튜디오로 메일을 보낼 수 있나요. 첨부도 되나요
결론: 공식 명세에 스크립트 함수 `f.Mail()` 이 있어 제목, 본문, 받는 사람을 정해 보낼 수 있습니다. 파일 첨부는 지원하지 않습니다(답변 당시).
[확인 필요] 발송 조건(플랜, 앱 종류, 보내는 주소)과 지원 범위는 확인되지 않았습니다. 공식 명세의 f.Mail 절과 QnA 게시판으로 확인하세요.
할 일:
1. `f.Mail().setTitle(title)`, `setBody(content)`, `addReceiver(mail)` 로 내용을 채우고 `send()` 를 부르세요.
2. 파일을 전달하려면 파일 서비스에 올린 뒤 다운로드 주소를 본문에 넣으세요.
주의: 디버거에서 시험해도 실제로 발송됩니다. 받는 사람을 본인 주소로 두고 시험하세요.
참고: 스크립트가 아닌 별도 메일 발송 API 는 답변 당시 제공하지 않는다고 안내됐습니다. 지금 상태는 [확인 필요]이므로 QnA 게시판에 문의하세요.
