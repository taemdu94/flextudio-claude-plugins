# 플렉스튜디오 용어집 (용어 풀이와 Studio 화면 글자)
이 파일이 답하는 질문: 워크스페이스와 앱과 테넌트는 어떻게 다른가요? 컬렉션, 카테고리, 섹터는 무엇인가요? _SUID 는 무엇인가요? WorkingTag 는 무엇인가요? Q조회와 R조회는 어떻게 다른가요? 보내는 데이터와 받는 데이터는 무엇인가요? ParamBlock 은 Studio 화면에서 뭐라고 부르나요? 답할 때 쓰면 안 되는 말은 무엇인가요?

## 목차

1. 이 파일을 쓰는 법
2. 앱 구조 용어
3. 화면 용어
4. 데이터 용어
5. 이벤트와 스크립트 용어
6. 서비스와 연동 용어
7. K-System(Flex-K) SP 용어
8. 배포와 운영 용어
9. Studio 화면 글자 대응표
10. 쓰지 말아야 할 말
11. 확인 필요 항목

## 1. 이 파일을 쓰는 법

용어를 풀어 줄 때는 아래 표의 풀이 문장을 그대로 씁니다.
처음 나오는 용어만 괄호로 한 번 풀고, 같은 답변에서 다시 풀지 않습니다.
한 답변에서 한 개념은 한 단어로만 부릅니다.
Studio 화면에 보이는 글자는 [대괄호]로 씁니다.
영문 내부 이름(ParamBlock 등)은 학습자가 먼저 꺼냈을 때만 9절 표로 대조해 줍니다.

## 2. 앱 구조 용어

전체 관계는 이 한 줄로 설명합니다.
워크스페이스(개발 조직) → 앱(배포 단위) → 고객(테넌트, 사용자와 ERP 연결) → 사용자

| 용어 | 풀이 |
|---|---|
| 워크스페이스 | 개발 조직 단위입니다. 시나리오, 권한키, 서비스, 앱을 이 안에서 만듭니다. |
| 콘솔 | 워크스페이스를 관리하는 웹 화면입니다. 메뉴는 [대시보드] [앱] [앱팩] [개발] [데이터] [고객관리]입니다. |
| 앱 | 사용자에게 배포하는 단위입니다. 앱 ID 는 앱마다 고유하고 웹 접속 URL 에 쓰입니다. |
| 앱팩 | 여러 시나리오를 묶어 관리하고 배포하는 단위입니다. 앱이 링크앱팩을 쓰면 배포는 [앱팩] 메뉴에서 합니다. |
| 패키지설치 | 플렉스튜디오가 제공하는 시나리오 묶음을 워크스페이스에 내려받는 기능입니다. 이미 설치한 패키지는 다시 설치할 수 없습니다. |
| 테넌트(고객) | 같은 앱을 쓰는 회사 한 곳입니다. 테넌트마다 사용자 명단을 따로 갖습니다. 콘솔에서는 [고객]으로 보입니다. |
| 테넌트 ID | 고객을 만들 때 자동으로 정해지는 값입니다. 고칠 수 없습니다. |
| 고객 설정 페이지 | 테넌트의 사용자, 회사 정보, 시스템 정보를 다루는 화면입니다. 접속키가 필요합니다. |
| 시스템 정보 | 테넌트가 연결할 ERP나 외부 DB 정보를 넣는 곳입니다. 같은 앱도 테넌트가 다르면 다른 DB 를 봅니다. |
| 사용자 | 테넌트에 등록된 사람입니다. 초대기반앱은 이메일과 휴대폰 번호 중 하나가 필수입니다. |
| 초대기반앱 | 관리자가 사용자를 등록하고 초대하는 앱입니다. 기업 업무앱은 이 방식을 씁니다. |
| 공개앱 | 사용자가 직접 가입하는 앱입니다. SNS 가입과 미가입자 접근을 허용할 수 있습니다. |
| 권한키 | 사용자마다 다른 UI 를 보이게 하는 키입니다. 영문, 숫자, 밑줄만 쓸 수 있습니다. |
| 앱 전환 | 한 테넌트의 여러 앱을 다시 로그인하지 않고 오가는 기능입니다. 초대기반앱만 됩니다. |
| 레이아웃 | 앱의 상단헤더, 시작페이지, 알림 페이지, 하단탭바, 우측 메뉴, PC-Web(Beta)을 정하는 설정입니다. |

## 3. 화면 용어

| 용어 | 풀이 |
|---|---|
| 시나리오 | 하나의 업무 프로세스입니다(예: 로그인, 상품, 마이페이지). Step, 이벤트, 서비스로 이루어집니다. |
| Studio | 시나리오를 만드는 개발 화면입니다. 디자인 모드와 개발 모드가 있습니다. |
| Step | 시나리오 안의 화면 하나입니다. Studio 에서 페이지 단위로 만듭니다(예: 목록 화면, 상세 화면). |
| 서브시나리오 | 한 시나리오에서 하위로 불러 쓰는 다른 시나리오입니다. 컬렉션을 따로 쓰므로 데이터는 설정으로 넘깁니다. |
| 그룹 | 컨트롤을 담는 묶음입니다. 컬렉션 데이터는 그룹 단위로 연결합니다. |
| 고정 그룹 | 디자인 모드에서 고정 그룹 설정을 켠 그룹입니다. 이 설정은 Step 바로 아래 그룹만 쓸 수 있습니다. |
| 컨트롤 | 입력, 표시, 선택을 맡는 화면 요소입니다(예: InputText, Combo, Label, ImageBox, 시트). |
| 시트 | 여러 행을 표 모양으로 보여 주고 고치는 컨트롤입니다. 시트 데이터는 연결된 카테고리의 섹터들입니다. |
| 하단 버튼 | Step 아래쪽의 이전, 다음 이동 버튼입니다. |
| 캔버스 버튼 | Step 안에 직접 놓은 버튼 컨트롤입니다. |
| 데이터 연결 | 그룹에 카테고리를 이어 그 데이터로 화면을 그리는 설정입니다. 반복 목록은 데이터 용도를 조회로 둡니다. |
| 대체 텍스트 | 라벨 등에 `{=키}` 로 적어 컬렉션 값을 글자로 보여 주는 표기입니다. `{=$키}` 는 천 단위 콤마를 붙입니다. |
| `{% %}` | 대체 텍스트 안에서 스크립트 결과를 보여 주는 표기입니다. 화면을 그릴 때 한 번만 계산합니다. |
| 데이터소스 | 콤보 같은 선택 컨트롤이 목록을 가져오는 출처입니다. |
| 코드도움 | K-System 코드도움 조건으로 값을 찾아 섹터 키에 채우는 기능입니다. |

## 4. 데이터 용어

데이터 구조는 이 한 줄로 설명합니다.
컬렉션(시나리오 전체 데이터) → 카테고리(이름 붙은 묶음) → 섹터(행 하나) → 키와 값

| 용어 | 풀이 |
|---|---|
| 컬렉션 | 시나리오가 시작해서 끝날 때까지 모든 데이터를 관리하는 곳입니다. 시나리오마다 따로 있고 스크립트에서는 `_c` 입니다. |
| 카테고리 | 컬렉션 안에서 섹터를 이름으로 묶은 것입니다. `_c.<카테고리명>` 은 섹터 배열입니다. |
| 섹터 | 컬렉션을 이루는 단위입니다. 키와 값의 쌍을 담고, DB 조회 결과 한 행이 섹터 하나가 됩니다. |
| 컬렉션 키 | 섹터 안 값의 이름입니다. 컨트롤은 이 키로 값과 연결됩니다. |
| Active 섹터 | 사용자가 마지막으로 선택하거나 입력 중인 섹터 하나입니다. 선택한 섹터가 없으면 화면의 첫 행이 대신 쓰입니다. |
| `_SUID` | 섹터마다 붙는 고유 키입니다. 화면 메모리용 임시 키라 DB 에 저장하지 않습니다. |
| 섹터 상태 | 섹터에 찍히는 표시로 added(추가), updated(수정), deleted(삭제) 세 가지입니다. |
| 상태 필터 값 | 보낼 섹터를 고르는 값입니다. all, active, selected, last, added, updated, deleted 를 소문자로 씁니다. |
| `_v` | 스크립트의 전역 변수 객체입니다. Step 을 옮겨도 값이 남습니다. |
| `_base` | 로그인 사용자, 앱, 고객 정보를 담은 객체입니다. |
| [Etc] 탭 Collections | 컬렉션 키와 타입을 미리 등록하는 곳입니다. 서비스로 보낼 컬럼 타입이 여기서 정해집니다. |

컬렉션 키로 쓸 수 없는 이름이 있습니다.
이 이름을 쓰면 값이 저장되지 않습니다.

| 구분 | 이름 |
|---|---|
| 예약어 | block, collection, innerBlocks, isActive, isAdded, isDeleted, isLast, isSelected, isUpdated, keys, status |
| 섹터 메서드 이름 | activate, delete, remove, select, unSelect, set, setValue, setStatus, release, mergeSector, replaceSector |

상태 컬럼이 필요하면 `ASStatus` 처럼 앞에 다른 글자를 붙이세요.

## 5. 이벤트와 스크립트 용어

이벤트 흐름은 이 한 줄로 설명합니다.
사용자 동작 → 이벤트 → 액션 1, 액션 2, … 차례로 실행 → 컬렉션 변경 또는 화면 이동

| 용어 | 풀이 |
|---|---|
| 이벤트 | 사용자 행위(버튼 누르기, 값 입력)로 생기는 사건입니다. 이벤트 안에 액션을 차례로 넣습니다. |
| 액션 | 이벤트 안에서 실행되는 일 하나입니다. 번호는 화면과 같게 1부터 셉니다. |
| 액션 종류 | 스크립트, 서비스, 연결 이벤트, API, FlipBack 다섯 가지입니다. |
| 연결 이벤트 | 다른 이벤트를 그 자리에서 불러 실행하는 액션입니다. |
| Step 이벤트 | Step 이 열리거나 떠날 때 실행되는 이벤트입니다. 9절 표에 화면 글자가 있습니다. |
| 이벤트 스크립트 | 이벤트의 스크립트 액션에 쓰는 JavaScript 입니다. 오류가 나면 남은 액션이 모두 취소됩니다. |
| 로드 스크립트 | 컨트롤이 그려질 때 실행되는 스크립트입니다. `Load.control`, `Load.sector` 로 그 컨트롤과 행을 읽습니다. |
| `f` | 실행 함수 묶음입니다(예: `f.Collection`, `f.Content`, `f.Event`). |
| `Current` | 스크립트에서 현재 시나리오, Step, 섹터를 가리키는 객체입니다. |
| 동기 호출 | 서비스 응답을 기다린 뒤 다음 액션을 실행하는 기본 방식입니다. |
| 비동기 호출 | 응답을 기다리지 않고 다음 액션으로 넘어가는 방식입니다. 로딩 화면이 없고, 실패해도 오류 창과 디버그 로그 없이 Async Catch Script 만 실행됩니다. |
| 함수 자동 생성 | Studio 이벤트 탭에서 스크립트 액션을 열면 있는 [함수 자동 생성]입니다. 함수 호출 코드를 만들어 줍니다. 함수 이름이 확실하지 않으면 이 기능으로 확인하세요. |
| 디버거 | 앱, 테넌트, 사용자를 골라 시나리오를 실행하고 실행 내역과 컬렉션을 보는 도구입니다. |

## 6. 서비스와 연동 용어

| 용어 | 풀이 |
|---|---|
| 서비스 | DB나 외부 API 와 데이터를 주고받는 설정입니다. 컬렉션 데이터를 보내고 결과를 다시 컬렉션에 반영합니다. |
| FlexSQL | SQL(MySQL, MSSQL)에 EJS 표현식을 섞어 쓰는 서비스입니다. 콘솔 [데이터] 메뉴에서 만듭니다. |
| EJS 표현식 | FlexSQL 안의 `<% %>`(자바스크립트), `<%= %>`(값 출력) 표기입니다. |
| FlexDB | 플렉스튜디오가 제공하는 MySQL DB 입니다. |
| 자동 조회 | FlexDB 테이블을 SQL 없이 저장, 조회, 삭제하는 서비스입니다(save, query, delete). |
| API 연동 모듈 | 외부 REST API 를 서버에서 부르는 모듈입니다. 콘솔 [데이터] 메뉴에서 만듭니다. |
| Secret Key | API 연동 모듈에 비밀값(API 키 등)을 등록하는 자리입니다. 모듈 안에서 `{=키}` 로 꺼내 씁니다. |
| Event Config Key | 시나리오에서 API 연동 모듈로 넘기는 값의 이름입니다. |
| 외부 DB | 테넌트 시스템 정보에 등록해 FlexSQL 로 쓰는 고객사 DB 입니다. |
| K-System | 플렉스튜디오와 연동하는 ERP 입니다. 첫 등장은 "K-System(Flex-K) 연동"으로 씁니다. |
| Flex-K | 고객사 ERP 앱 서버(IIS)에 설치하는 연동 프로그램입니다. K-System 과 연결하려면 먼저 설치돼 있어야 합니다. |
| FlexAPI | K-System 연동 서비스의 모듈 이름입니다. 서비스 종류는 `ksystem` 입니다. |
| 시스템 정보 4개 항목 | K-System 연동에 넣는 Oper dsn, Bis dsn, CompanySeq, FlexK API URL 입니다. |
| dsn | DB 이름이 아니라 ERP 서버 쪽 접속 별칭입니다. 어느 물리 DB 인지는 ERP 담당자에게 확인하세요. |

## 7. K-System(Flex-K) SP 용어

서비스 한 번의 흐름은 이 한 줄로 설명합니다.
이벤트 → 서비스 → 보내는 데이터가 `#BIZ_IN_DataBlock1` 에 들어감 → SP 실행 → SP 가 `#BIZ_OUT_DataBlock1` 에 결과 기록 → 받는 데이터가 카테고리에 반영 → 화면

| 용어 | 풀이 |
|---|---|
| SP | 데이터베이스에 저장해 둔 SQL 명령 묶음입니다. |
| 보내는 데이터 | 서비스가 서버로 보내는 카테고리 데이터입니다. 보내는 데이터 1개가 임시 테이블 한 쌍이 됩니다. |
| 사용자 데이터 | 보내는 데이터에 함께 실리는 값입니다. 주로 로그인 사용자 정보를 넣습니다. K-System SP 서비스에는 CompanySeq, LanguageSeq, UserSeq 를 넣습니다. |
| 받는 데이터 | 서비스 결과를 어느 카테고리에 어떻게 반영할지 정하는 설정입니다. |
| [덮어쓰기] | 기존 행을 모두 지우고 결과로 바꿉니다. 조회에 씁니다. |
| [추가] | 결과 행을 뒤에 붙입니다. 기본값이라 조회에 쓰면 목록이 계속 늘어납니다. |
| [병합] | 기준 키(기본 `_SUID`)로 짝을 맞춰 고치고, 짝이 없으면 붙입니다. |
| DataBlock | 보내는 데이터와 받는 데이터의 블록 하나입니다. 카테고리 1개가 DataBlock 1개입니다. |
| `#BIZ_IN_DataBlock{n}` | n번째 보내는 데이터가 들어가는 임시 테이블입니다. 행 하나가 섹터 하나입니다. |
| `#BIZ_OUT_DataBlock{n}` | SP 가 결과를 쓰는 임시 테이블입니다. 처음에는 입력 행이 복사돼 있습니다. |
| SP 파라미터 4개 | `@WorkingTag`, `@CompanySeq`, `@LanguageSeq`, `@UserSeq` 입니다. 다른 값은 임시 테이블 컬럼으로 옵니다. |
| WorkingTag | 행마다 붙는 상태 글자 A(추가), U(수정과 그 밖), D(삭제)입니다. 섹터 상태에서 자동으로 정해집니다. |
| Q조회 | SP 가 `#BIZ_OUT` 에 결과를 INSERT 만 하고 플랫폼이 그 테이블을 읽어 돌려주는 방식입니다. |
| R조회 | SP 가 마지막에 직접 SELECT 한 결과를 돌려받는 방식입니다. |
| [TempTable to CREATE] | 서비스가 만들 임시 테이블 종류입니다. `#BIZ_IN`/`#BIZ_OUT` 을 쓰는 SP 는 BIZ_IN/OUT_DataBlock 을 고릅니다. 새 서비스 기본값은 FLEX_DataBlock 입니다. |
| [TempTable to SELECT] | Q조회와 R조회를 가르는 설정입니다. BIZ_IN/OUT_DataBlock 이면 Q조회, None 이면 R조회입니다. |
| [공통 트랜잭션 사용] | 켜면 SP 목록 전체가 한 트랜잭션입니다. 하나라도 실패하면 모두 롤백합니다. |
| Status, Result | SP 가 결과 행에 쓰는 오류 표시 컬럼입니다. Status 는 INT(0 또는 NULL 이 정상), Result 는 메시지입니다. |
| Check SP, Save SP | 검사와 저장을 나눈 SP 쌍입니다. Check 가 오류를 남기면 Save 가 실행되지 않습니다. |

WorkingTag 는 직접 넣는 값이 아닙니다.
섹터 상태와 이렇게 이어집니다.

| 섹터 상태 | WorkingTag |
|---|---|
| deleted | D (가장 먼저 봅니다) |
| added | A |
| updated, 또는 상태 없음(조회 결과 행) | U |

SP 에서 추가, 수정, 삭제를 가를 때는 `@WorkingTag` 파라미터가 아니라 `#BIZ_IN_DataBlock1.WorkingTag` 컬럼을 보세요.

## 8. 배포와 운영 용어

반영 흐름은 이 한 줄로 설명합니다.
Studio 저장 → 시나리오 [배포](버전 발행) → 앱에서 버전 선택 후 [라이브에 적용] → 사용자 화면

| 용어 | 풀이 |
|---|---|
| 저장 | Studio 에서 편집 내용을 보관하는 것입니다. 저장만으로는 사용자에게 보이지 않습니다. |
| 시나리오 배포 | 시나리오의 새 버전을 발행하는 것입니다. 앱 배포와 다른 단계입니다. |
| 앱 배포 | 앱의 [시나리오 배포] 메뉴에서 쓸 시나리오와 버전을 골라 라이브에 반영하는 것입니다. |
| 라이브 | 실사용자가 쓰는 앱 상태입니다. [라이브에 적용]을 누르면 바로 반영됩니다. |
| [새 버전 발행] | FlexSQL 서비스를 고친 뒤 시나리오에서 실행되게 하는 버튼입니다. [현재버전으로 변경내역 반영]도 같은 역할입니다. |
| 디버그 권한 | 특정 사용자 정보로 디버깅하게 해 주는 사용자별 권한입니다. |
| 앱 사용권한 | 사용자가 앱을 쓸 수 있게 하는 권한입니다. 초대 문자로 접속해야 "사용중"이 됩니다. |
| [서비스오류로그] | 라이브 앱 사용 중 난 오류 기록을 보는 앱 메뉴입니다. |
| 실행 내역 | 디버거에서 Step 별로 실행된 이벤트와 서비스가 순서대로 보이는 곳입니다. |
| Test-SQL, Test-API | 디버거에서 FlexSQL 과 API 연동 모듈을 따로 시험하는 탭입니다. |
| 실행문 미리보기 | FlexSQL 의 EJS 를 계산한 최종 SQL 을 보는 기능입니다. |

## 9. Studio 화면 글자 대응표

답할 때는 왼쪽 화면 글자를 씁니다.
가운데 영문 이름은 학습자가 메타데이터나 오류 문구에서 영문을 보고 물을 때만 대조해 줍니다.
"(답에 쓰지 않음)"으로 적힌 칸은 영문 이름을 꺼내지 말고 화면 글자로만 안내합니다.

| Studio 화면 글자 | 영문 이름 | 뜻 |
|---|---|---|
| [보내는 데이터] | ParamBlock | 서버로 보내는 카테고리 데이터 |
| [사용자 데이터] | UserData | 함께 보내는 로그인 정보 값 |
| [카테고리명] | (답에 쓰지 않음) | 대상 카테고리 이름 |
| [필터설정] | (답에 쓰지 않음) | 보낼 섹터를 고르는 조건 |
| [받는 데이터] | ResultBlock | 결과를 반영할 카테고리 설정 |
| [화면에 반영하기] | (답에 쓰지 않음) | 결과를 받은 뒤 화면 자동 갱신 |
| [덮어쓰기] / [추가] / [병합] | replace / add / merge | 받는 데이터 반영 방식 |
| [서비스 종류: 기존 서비스 사용] | (없음) | 이미 만든 서비스를 고르는 선택 |
| [비동기 호출 사용하기] | (답에 쓰지 않음) | 응답을 기다리지 않는 호출 |
| Async Then Script, Async Catch Script, Async Finally Script | (화면도 영문) | 비동기 호출의 성공, 실패, 항상 실행 스크립트 |
| [항목 없음 메시지 출력] | (답에 쓰지 않음) | 켜면 결과가 없을 때 "조회결과없음" 표시 |
| [최초 시작 전 (Init)] | Init | Step 을 그리기 전에 실행 |
| [로드 시 (Loaded)] | Loaded | Step 을 그린 뒤 실행 |
| [뒤로가기로 돌아올 때] | OnBackLoaded | 이전 Step 으로 돌아왔을 때 실행 |
| [다음으로 이동 전] | OnLeave | 다음 Step 으로 떠나기 전에 실행 |
| [앱에 다시 돌아올 때] | OnForeground | 앱이 다시 앞으로 왔을 때 실행 |
| [오프라인 모드 이벤트 후] | AfterOfflineEvent | 오프라인 모드 이벤트 뒤 실행 |
| [라이브에 적용] | (없음) | 앱 배포. 문서에 따라 [앱에서 사용하기]로 적혀 있습니다. |

서브시나리오 설정에서 자주 나오는 화면 글자는 [컬렉션 복사], [서브시나리오의 콜렉션으로 대체하기], [콜렉션 이전 상태로 복원하기], [호출한 시나리오로 돌아가기 허용]입니다.
화면 글자에 "콜렉션"으로 적힌 곳은 인용할 때만 그대로 쓰고, 본문은 "컬렉션"으로 씁니다.

## 10. 쓰지 말아야 할 말

| 쓰지 않는 말 | 대신 쓰는 말 | 이유 |
|---|---|---|
| 칸 (컬럼 뜻) | 컬럼 | 기술 용어는 원어 그대로 씁니다. |
| 줄 (행 뜻) | 행 | 학습자가 SQL 과 화면에서 보는 말과 맞춥니다. |
| 표 (DB 테이블 뜻) | 테이블 | 화면의 시트와 헷갈립니다. |
| 출입증 (키, 토큰 뜻) | API 키, 토큰 | 직역어라 검색되지 않습니다. |
| 돌다, 돌린다 (실행 뜻) | 실행되다, 실행하다 | 직역어입니다. |
| 데이터 묶음, 그룹 데이터 (카테고리 뜻) | 카테고리 | 한 개념은 한 단어로 씁니다. |
| 요소, 박스, 위젯 (컨트롤 뜻) | 컨트롤 | 한 개념은 한 단어로 씁니다. |
| 페이지, 스크린 (Step 뜻) | Step | 화면 글자를 인용할 때만 "스텝"을 그대로 둡니다. |
| 프로그램 한 본 | 시나리오 | 제품 용어를 씁니다. |
| 원장 | 사용 내역 | 직역어입니다. |
| 콜렉션 (본문) | 컬렉션 | 화면 글자 인용만 예외입니다. |
| 고객과 테넌트를 번갈아 | 처음 "테넌트(고객)", 이후 "테넌트" | 한 개념은 한 단어로 씁니다. |
| "배포했다"만 쓰기 | 시나리오 배포, 앱 배포 구분 | 둘은 다른 단계입니다. |
| ParamBlock, ResultBlock (먼저 꺼내기) | [보내는 데이터], [받는 데이터] | 학습자는 화면 글자를 봅니다. |
| "사용자 데이터 3종" | CompanySeq, LanguageSeq, UserSeq | 항목은 줄이지 않고 모두 적습니다. |
| 액션 0 | 액션 1 | 번호는 화면과 같게 1부터 셉니다. |

문장 모양의 금지 표현(대시, 번역투, 명사형 끝맺음 등)은 [answer-style.md](answer-style.md)를 따릅니다.

## 11. 확인 필요 항목

아래 이름은 근거끼리 다르거나 아직 확인되지 않았습니다.
답에 쓸 때는 [확인 필요]를 붙이고 확인 방법을 함께 주세요.

| 항목 | 상태 | 학습자가 확인하는 방법 |
|---|---|---|
| f.MessageBox 의 버튼 추가 함수 이름 | 공식 함수 명세 이름은 addBtn 입니다. 예전 문서에 addButton 으로 적힌 곳이 있습니다. | addBtn 을 쓰고, 동작이 다르면 Studio 함수 자동 생성 결과를 따르세요. |
| [데이터베이스 유형]의 업무, 운영이 가리키는 물리 DB | 어느 물리 DB 와 이어지는지 확인되지 않았습니다. | ERP 담당자에게 SP 를 만들 DB 를 물어보세요. |
| 일반 콤보의 저장 키 속성 화면 글자 | 화면 글자가 확인되지 않았습니다. | Studio 속성 패널에서 저장 관련 항목을 캡처해 함께 보세요. |
| ScrollEnd Step 이벤트의 화면 글자 | 화면 글자가 확인되지 않았습니다. | Studio Step 이벤트 목록에서 확인하세요. |
| 요금제별 사용 가능 기능 | 문서마다 다르게 적혀 있습니다. | 메뉴가 없거나 잠겨 있으면 현재 요금제 안내를 확인하세요. |
